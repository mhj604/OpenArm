## V20 보상과 PPO

Stage 보상은 17개 항목으로 구성된다.

```text
approach/lift/transport progress       +5 / +150 / +150
carry height signed progress to .78   +150
grasp/lift/assist/release events       +10 / +15 / +40 / +25
success / failure / timeout            +200 / -100 / -50
elapsed / gripper phase                -0.5 per sec / -4
carry band / clearance                 -10 / -2
actor-only action rate / joint vel     -1e-4 / -1e-4
```

보조 제어 진입 사건은 정책망이 결정한다. 제어기가 만든 바스켓 진입에는 정책망 보상을 주지 않는다.
부호 있는 높이 퍼텐셜은 `0.78m`에 가까워질 때만 양수, 멀어질 때는 음수, 정지할 때는 0이다. PPO는
환경 3072개, 48스텝, 미니배치 24개, 2에포크, 학습률 `5e-6`, 엔트로피 `1e-4`, 감마 `0.995`를
사용한다.

## V21 수직 제어 수정

V20에서 운반 진입 문제는 해결했지만 상승 방지 제한 때문에 Z축 제어가 아래쪽으로만 누적됐다. 물체
높이는 약 `0.645m`에서 `0.632m`로 낮아졌고 이후 파지 유지와 보조 제어 성능도 떨어졌다. 놓기와
성공은 계속 0이었다.

V21은 관측값 69개, 동작 8개, 보상 17개, 목표, 바스켓 변환, 상태 기준을 모두 유지한다. 보조 제어의
Z축 제어만 바꾼다.

```text
dz = 0.10 * (target_z - object_z) - 1.5 * object_vz * step_dt
dz clamp = [-0.0015m, +0.00075m] per control step
target_z = 0.78m before centered; sampled 0.73/0.68m after centered
```

이 방식은 목표보다 아래에 있을 때만 작은 상향 복구를 허용한다. 상승 속도를 제동하면서 하향 제어력은
상향의 두 배로 유지한다.

## V23 실제 물체 피드백 수정

v22의 1304번째 반복에서 파지·들기·보조 제어는 약 `99/97/97%`, 파지 유지는 `91%`에 도달했다.

0이었다. 진입 시 고정한 물체-TCP 간격 때문에 TCP는 명목상 목표에 도달해도 이후 큐브 미끄러짐이

## 현재 V32 정책(V31을 대체함)

v31 실행 `2026-07-13_01-57-04`의 `model_2500.pt`를 행동자 평균으로 GUI에서 확인한 결과,
파지·들기·운반은 좋았다. 그러나 바스켓 위에서 멈춘 뒤 하강하고 정렬하는 데 시간이 너무
오래 걸렸다. 최근 50회 이동 평균은 파지·운반 `94.77/94.33%`, 중심 정렬 `80.62%`, 놓기 허가
`54.78%`, 성공 `52.46%`, 시간 초과 `47.05%`였다. XY·높이·속도 중심 정렬을 일정 시간 확인한
뒤에야 목표를 `.750m carry -> .670m release`로 한 번에 바꾼 것이 직접 원인이었다.

v32는 엄격한 파지·놓기 검사와 모든 동작 상한을 유지한다. 결정론적 보조 제어 목표는 다음과 같다.

```text
XY 120 -> 40mm: Z carry .750m -> min(carry, release + 20mm), cubic smoothstep
XY  40 ->  2mm: Z preplace    -> exact release, cubic smoothstep
descent progress: monotonic latch; XY rebound cannot command an upward bounce
```

하단 목표에서 40mm 전환 구간은 큐브 밑면과 바스켓 가장자리 사이에 `16.46mm`의 여유를 남긴다.
XY 제어를 2.5mm로 제한했을 때 목표 Z의 최대 진행량은 `2.812mm`로, 기존 하강 상한 3mm 안에
들어온다. 직교 좌표계 최대 이동량, 감쇠, 관절 이동량, DLS, 목표 선행량, 놓기 높이 2mm/3mm
제한과 속도 제한 `.06m/s`는 바꾸지 않았다. XY/Z 이득은 작은 오차에서 비례 제어가 길게
이어지는 구간만 줄이려고 `.16/.12 -> .20/.16`으로 높였다. 중심 정렬과 놓기 확인은
`5 -> 3`제어 주기로 줄였다. 중심 정렬은 평면 위치만 확인하고 정확한 높이와 전체 속도는
놓기 준비 단계에서 한 번 검사한다. 새 지표는 `task_descent_progress`와
`task_descent_target_height`다.

종료 실패·시간 초과 비용 `2x`는 검증된 파지 이후부터 `assist_engaged` 이전까지, 즉 학습된
행동자가 운반을 맡는 구간에만 적용한다. 결정론적 보조 제어가 최종 정렬을 맡은 뒤에는 정상
비용 `1x`를 적용한다. 이로써 제어기 단계에서 시간 초과가 난 뒤 파지를 회피하도록 만들던
v31의 유인을 없앴다.

## V34 정책 설계

v34 학습 전 v33의 최근 50회 파지·운반 평균은 이미 `97.30/97.24%`에 도달했다. 이 상태에서

확인된 제어기 결함과 수정 내용은 다음과 같다.

- v33은 현재 선행량과 관절을 제한한 뒤 이전 목표와의 연속성을 마지막에 적용했다. 이 마지막

  현재값 기준 `+/- .12rad`, 이전 목표 기준 `+/- .03rad`의 성분별 교집합에 직접 투영한다.
- 정상 상태 목표는 더 이상 `previous_target + delta`를 누적하지 않는다. 현재값 기준 3제어 주기
  앞을 내다보는 `current + 3 * safe_delta`를 사용하며 출력 연속성은 제어 주기당 `.03rad`로 유지한다.
- 관절 제한 배율은 오래된 목표가 아니라 측정한 현재 관절값을 기준으로 계산한다. 제약 교집합이
  비면 현재 자세를 명시적으로 유지하거나 기준으로 다시 잡고, 다음 제어 전에 직교 좌표계 속도와
  가속도를 지운다.
- 첫 보조 제어에서는 진입 초기값을 최종 목표로 사용한다. 정상 선행 경로는 다음 제어 주기부터
  시작해 한 제어 주기 안에서 `.03 + .03rad`가 뛸 수 있던 기존 문제를 막는다.
- 유효하지 않은 DLS 후보는 그 상태를 유지한다. 0으로 만든 후보를 유효한 무동작 선행량으로
  되살릴 수 없다. 우선 후보, 이전 후보, 점진 후보, 유지 후보는 이제 같은 복구·검증 경로를 쓴다.
- XY와 Z는 각각 `5mm`, `2mm`에서 독립적으로 멈춘다. 놓기 조건 XY `40mm`, 성공 조건 XY
  `50mm`, 높이 `+2/-3mm`, 속도 `.06m/s`는 그대로이며 성공 조건은 하나도 완화하지 않았다.

  요청량의 `25%` 이상 진행해야 하고, 함께 요청된 보조축은 같은 방향으로 `5%` 이상 진행해야
  한다. 역방향 이동과 완전한 축 정지는 허용하지 않되 한 축 때문에 전체 후보가 거부되는 현상을
  줄인다. 증분 후보, 안전 축소, 단일 축 대체, 목표 선행값 검사에 같은 기준을 적용한다.
- 중앙 정렬이 확인되고 XY 오차가 `30mm` 이내가 되면 현재 하강 진행률에서 최종 놓기 높이까지
  `18`개 유효 제어 주기의 5차 보간으로 내려간다. 현재 XY 속도가 `0.05m/s` 이하이고 큐브가
  직전 높이 목표를 `12mm` 이내로 따라온 경우에만 다음 목표로 진행한다. 범위를 벗어나거나 파지가
  불안정하거나 실제 추종이 늦으면 시간을 멈추고, 조건이 회복되면 같은 지점에서 이어 간다. 기존처럼
  XY 오차가 `5mm`가 될 때까지 최종 하강을 미루지 않으면서 목표 선행량도 제한한다. 추종 오차로
  램프가 멈춘 동안에는 Z 우선 제어를 유지해 현재 높이 목표부터 따라잡고, XY 속도가 불안정하거나
  `30mm` 범위를 벗어나면 XY를 다시 우선한다. `30mm` 안에 들어온 순간부터는 중앙 정렬 확인이
  아직 누적 중이어도 기존 XY 연동 높이를 더 내리지 않고 현재 목표에서 기다린다.
- 자동 보조 제어는 진입 순간의 실제 큐브 높이가 운반 하한 `0.730m` 이상일 때만 시작한다. 높이가
  부족하면 행동자가 운반 자세를 회복한 뒤 진입하므로 낮은 상태로 바스켓 가장자리에 접근하는
  경우를 막는다.
- 보상 21개, 놓기 목표 `0.670m`, 놓기·성공 허용 오차, 16초 에피소드, PPO, 파지 게이트,
  관절·속도·가속도·저크 안전 한계는 바꾸지 않았다. 도메인 무작위화도 아직 켜지 않는다.
- 하강 활성 여부·진행률·소요 제어 수와 보조 제어 진입 높이·속도를 TensorBoard에 추가해 원인을
  다음 학습에서 직접 확인할 수 있게 했다. 높이 조건이 진입을 막은 제어 수와 최대 부족 높이,
  하강이 중앙 정렬 확인·안정성·추종 오차·`30mm` 범위 이탈 때문에 멈춘 제어 수, 진입 시 관절
  한계 근접도도 따로 기록한다. 저진행 지표는 복구 전 원시 DLS 후보를 주축 `25%`와 보조축
  `5%` 기준으로 평가하므로 정상 보조축 이동을 실패로 세지 않으면서 실제 후보 거부는 확인할 수 있다.
- 새 목표가 유효하지 않을 때 직전 관절 목표를 유지하는 안정화 경로만 진행률 예외를 허용한다.
  이 경로는 새 목표를 만들지 않으며 기존 직교 좌표계 안전, 관절 한계, 선행량, 연속성 검사를 모두
  통과해야 한다. 코드에서 명시적인 예외 호출 한 곳으로 제한했다.

정적 검증은 `55 passed`이며 Python 컴파일과 `git diff --check`를 통과했다. v39 수정 중에는
Isaac 시뮬레이션이나 학습을 실행하지 않았다. 재개하거나 부트스트랩하지 않고 처음부터 학습한다.


모델 1000에서 최근 50회 파지·들기·운반이 각각 `85%` 이상인지 먼저 확인한다. 이후에는 보조
제어의 전체 정지와 선행값 대체 횟수, `assist_to_center` 및 `center_to_release` 시간 초과가 함께
감소해야 한다. 후기 후보의 1차 기준은 파지·들기·운반 `>=94%`, 성공 `>=62%`, 두 보조 제어
시간 초과 합계 `<=30%`다. 어느 한 체크포인트의 순간값만 보지 말고 최근 100회 추세와 GUI 20회를
함께 확인한다.

## V39 결과와 V40 정책

v39는 3153회에서 100회 평균 성공 `59.08%`를 기록했지만 후반에 접근 정책이 무너졌다. 파지는
100회 평균 최고 `96.91%`에서 마지막 50회 `74.80%`로, 성공은 마지막 50회 `51.02%`로
떨어졌다. 3100회와 4000회를 비교하면 접근 시간이 약 `25.5 -> 238.9 control`로 늘어난 반면
`운반/파지` 비율은 계속 약 `99.8%`였다. 운반을 잊은 것이 아니라 자동 제어 구간의 결과까지
행동자 PPO 경사로 사용하면서 접근 매핑이 뒤늦게 덮인 현상이다. 절대 정렬 품질을 매 주기 지급한
보상도 목표 근처에서 오래 머무는 행동에 계속 양의 값을 줬다.

마지막 하강은 18단계 보간 정지가 원인이 아니었다. 하강을 시작한 에피소드 대부분이 18단계를
완료했고 추종·안정성 정지는 조건부 약 `0.31초`였다. 중앙 정렬 뒤 놓기까지는 약 `100 control`,
즉 `3.33초`였으며, DLS 유효성은 단계별 주축을 사용하면서 후보 순위는 여전히 XY와 Z 중 작은
진행률을 사용한 것이 원인이었다. 예를 들어 Z `80%`·XY `5%`인 유효 후보보다 Z `25%`·XY
`20%` 후보가 선택돼 하강이 약 3.2배 느려질 수 있었다.

v40은 다음 항목만 직접 고친다.

- 중앙 정렬 전에는 XY, 안전 하강 구간에서는 Z를 실제 DLS 주축으로 사용한다. 후보도 같은 주축
  진행률로 비교하고, 안전 검사를 통과한 Z 전용 후보가 결합 후보보다 Z 진행률이 높을 때만 교체한다.
  v33부터 검증한 자세·관절 여유 후보는 주축 진행률 손실이 `5%` 이내일 때 우선하는 기존 절충을
  유지한다. 이는 최고 진행률만 고르는 규칙이 아니라 관절 자세 안정성을 함께 보존하려는 별도 기준이다.
- 중앙 정렬 뒤 5차 보간은 `18 -> 12 control`로 줄이고 Z 무반응 구간은 `2.0 -> 1.5mm`로
  낮춘다. 수직 이동 상한 `3mm/control`, 가속도·저크, 누설·관절·충돌·미끄러짐 검사와 놓기
  높이 허용오차 위 `2mm`·아래 `3mm`, 속도 `0.06m/s`는 유지한다.
- 16초 제한을 실제 실패 horizon으로 처리해 시간 초과에 `gamma * V`가 다시 더해지지 않게 한다.
- 정책·가치망 입력과 분리된 `authority` 관측을 저장한다. 자동 파지·보조 제어가 팔 목표를
  덮어쓴 표본의 행동자 advantage는 0으로 만들고, 가치망은 전체 궤적을 계속 학습한다. 자동
  그리퍼의 8번째 출력은 행동 인터페이스에는 남기되 PPO 로그확률과 엔트로피 합계에서는 제외한다.
  Adam이 단순 경사 배율을 상쇄하지 못하도록 각 미니배치의 실제 행동자 파라미터 이동량을 authority
  비율로 직접 줄이고, 비율이 0이면 누적 momentum이 있어도 행동자를 고정한다. 놓기 예정 상태를
  팔 term에서 먼저 계산해 그리퍼가 열리는 최초 제어 주기부터 팔 목표를 현재 관절 위치로 유지한다.
- 절대 정렬·dwell 보상은 에피소드 최고 정렬 품질을 처음 갱신한 만큼만 지급하고, 행동자가 제어하는
  동안 발생한 후퇴는 전부 차감하는 방식으로 바꾼다. 변화량을 잘라내지 않으므로 빠른 개선을 손해
  보지 않으며, 같은 최고점까지 반복 회복해도 보상을 다시 받지 못한다. 품질 1.0 개선의 총 가중치는
  `25`다. 자동 그리퍼 raw action에 주던 비인과 보상은 제거하고 준비·후보·파지 사건 `8/15/50`과
  접근 지연 `-7.5`는 유지한다.
- PPO 학습률 `2.5e-6`, 2에포크, clip `0.1`, entropy `0`, fixed schedule은 그대로 둔다.
  초기 실패 정책은 행동자 제어 비율이 높아 기존 크기로 학습하고, 성공 정책은 약 `17%`의 인과
  표본과 같은 비율로 실제 행동자 이동량도 줄인다. `actor_authority_fraction`, `actor_step_scale`,
  `actor_parameter_delta_norm`을 기록하며 처음부터 `5%` 미만이면 정책 성능이 아니라 authority 판정
  오류로 본다.

정적·단위 회귀 테스트 `79개`와 Python 컴파일, `git diff --check`를 통과했다. Isaac 시뮬레이션은
새로 실행하지 않았다. v40도 체크포인트를 불러오지 않고 처음부터 학습한다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_authority_primary_descent_v40
```

모델 1000, 2000, 3000에서 최근 100회 파지·들기·운반과 성공을 확인한다. 3000 이후에는
`actor_authority_fraction`, 접근 시간과 접근 시간 초과가 함께 안정적인지 보고 4000·5000까지
비교한다. 후기 1차 기준은 파지·들기·운반 `>=94%`, 성공 `>=62%`, 접근 시간 초과 `<=5%`,
보조 제어 두 구간 시간 초과 합계 `<=25%`다. GUI에서는 마지막 하강이 v39보다 짧아졌는지와
Z 우선 후보 교체가 충돌·슬립을 늘리지 않았는지를 함께 확인한다.

## 다음 실행 자체 충돌 계약

공식 OpenArm 물리 USD는 `physxArticulation:enabledSelfCollisions=0`을 명시하며 이 저장소는 최초
작업부터 v40까지 그 값을 덮어쓰지 않았다. 다음 실행부터는 Reach와 Pick-and-Place 모두 환경
복제 전에 `openarm_bimanual/root_joint`의 루트 레이어에 `true`를 직접 기록한다. 이 경로는 로봇
`prim_path`와 articulation root가 함께 사용하는 단일 상수에서 정해지며 호출자가 다른 경로를 넘길
수 없다. prim, ArticulationRootAPI, 루트 레이어 기록값과 합성값을 모두 확인하고, 시작 이벤트에서
복제된 모든 환경의 값을 다시 읽는다. 로봇 경로·root·`spawn=None` 계약이 달라지거나 환경 하나라도
`true`가 아니면 학습을 시작하지 않는다.

자체 충돌을 켜면 물리 분포와 접촉량이 달라지므로 자체 충돌이 꺼진 v40 또는 이전 체크포인트에서
재개하지 않는다. Reach와 Pick-and-Place의 공용 PhysX 프로필은 contact/patch `2**23`, found-lost
pair `2**22`, found-lost aggregate `2**25`, total aggregate `2**21`, collision stack `2**28`,
heap `2**27`, 임시 버퍼 `2**25`다. `2**23` patch는 7040개 환경의 안전성을 보장하는 실측값이
아니라 사전 측정을 위한 상한 후보다. 검증하지 않은 7040개 초과 실행은 시작 단계에서 거부한다.

다음 fresh 실행 전에는 1~16개 환경의 물리·GUI 검사, 512~1024개 환경의 짧은 접촉 학습,
대규모 환경 100회 처리량 검사를 순서대로 수행한다. PhysX patch/aggregate/found-lost overflow,
`simulation will miss interactions`, CUDA 오류가 한 번이라도 나오면 실행이 계속돼도 그 학습은
무효다. 현재 실행 `2026-07-16_14-02-36_fresh_authority_primary_descent_v40_e7040`은 장면 생성 뒤
코드를 바꿨으므로 자체 충돌이 계속 꺼진 상태이며 중지하거나 변경하지 않았다.

## V40 파지 회귀 원인과 V41 정책

v40은 접근 실패가 아니다. 같은 500회에서 v39는 후보 도달 `93.45%`, 실제 파지 `92.76%`였고
v40은 후보 도달 `95.72%`, 실제 파지 `0%`였다. v40은 접촉 뒤 검증 단계에서 물체와 TCP를
각각 약 `0.04mm`만 움직였다. 파지 확정에 필요한 상승량은 `12mm`와 `10mm`다. 이 상태가
7040개 환경의 서로 다른 실행에서도 반복됐고, v40 행동자 파라미터 변화량도 v39보다 컸다.
자원 부족이나 학습 정지가 아니라 목적함수가 정책을 잘못된 방향으로 바꾼 것이다.

물리 파지 기준, 초기 관절, 큐브와 바스켓 위치는 v35·v39·v40에서 같았다. 회귀를 만든 차이는
v40에서 한꺼번에 바꾼 파지 전 학습 계약이다. 정렬 보상을 `quality/dwell=5/1`에서 에피소드 최고점
기준 변화량으로 바꾸면서 재시도 때 이전 최고점까지 회복하는 동작의 보상이 0이 됐다. 동시에
8차원 표준 PPO를 팔 7차원 로그확률로 바꾸고 자동 닫기·재시도 표본까지 마스킹했으며, Adam
업데이트 뒤 행동자 파라미터 이동량을 권한 비율로 다시 줄였다. v40은 에피소드마다 여러 번
재시도했기 때문에 이 세 변경의 영향을 반복해서 받았다.

웹 ChatGPT Pro와 세 차례 교차 검토한 뒤 v41은 다음처럼 원인을 좁혀 수정했다.

- 파지 전 정렬 보상은 v35·v39에서 검증한 `quality=5`, `dwell=1`로 되돌렸다.
- 자동 그리퍼 단계 보상 `-1`과 표준 8차원 `ActorCritic` 로그확률을 복원했다.
- 권한 마스킹은 파지 뒤 자동 보조 제어, 제어권 반환, 자동 놓기 구간에만 쓴다. 자동 닫기와
  재시도는 과거 성공 버전과 같은 학습 분포를 유지한다.
- 최적화 단계가 끝난 뒤 행동자 파라미터 이동량을 권한 비율로 다시 축소하던 훅은 제거했다.
  권한이 없는 표본의 advantage를 0으로 만드는 마스킹과 행동자 변화량 진단은 유지한다.
- `is_finite_horizon=True`, 12단계 하강, Z `1.5mm` 무반응 구간, 단계별 주축 DLS와 모든 물리
  파지·놓기 조건은 바꾸지 않았다.

## V41 종료 결과와 V42 정책

v41 실행 `2026-07-16_18-40-52_fresh_verified_pregrasp_hybrid_v41`은 1846회까지 기록됐고 마지막
체크포인트는 `model_1825.pt`다. 프로세스는 분석 도중 종료됐지만 `Killed`, OOM, PhysX overflow는

- v41의 행동자 권한 비율은 0회부터 1846회까지 매번 정확히 `1.0`이었다. 권한 마스킹은 파지 뒤

  최고 높이까지 회복할 때는 0을 줬다. `+1cm -> -1cm -> +1cm` 탐색의 순보상이 `-1cm`라서 정책은
  수직 탐색을 줄일수록 유리했다. 실제로 v41의 들기 보상과 물체 높이 변화가 학습 후반에 0으로

- 자체 충돌은 v41에서 처음 켠 물리 변경이다. 공식 충돌 형상을 정적으로 계산하면 좌우

  충돌은 유지하면서 이 두 링크쌍만 필터링한다.

v42는 이 원인만 교정한다.

- 후보 접촉부터 물리 파지 확정까지 쓰던 기존 들기 보상은 그대로 보존하고, `just_grasped` 전이까지
  후보 단계에 포함한다. v35·v39에서 검증한 3단계 파지 진입, 정렬 보상, 재시도와 물리 파지 기준은
  바꾸지 않았다.
- 물리 파지가 확정된 순간 물체와 TCP 높이를 각각 원점으로 저장한다. 목표 높이 `.730m`까지의 두
  진행률 중 작은 값을 사용해 둘이 함께 상승할 때만 최대 `+30`의 보상을 준다. 할인율 `0.995`에
  맞춘 potential 차이를 사용하므로 정지는 매 주기 약한 음수, 하강은 음수, 회복은 양수다. 파지
  시점의 0에서 출발해 다시 0으로 돌아오는 실패 왕복의 할인 누적 보상은 0이다. 놓침·실패·시간

  닫지 않고 마지막 진행량을 한 번 지급해 최대 `+30`의 명시적인 일회성 완료 보너스로 사용한다.
- `current_hold`가 순간적으로 흔들려도 보상 추적을 끊지 않는다. 큐브가 미끄러져 내려가면 진행률
  감소가 그대로 벌점이 되고, 상태를 껐다 켜서 다시 보상을 받는 경로도 없다.
- 미완료 시간 초과의 파지 뒤 배수만 `2.0 -> 1.0`으로 바꿨다. 행동자가 유발할 수 있는 실패는
  `2.0`, 즉 `-110`을 유지한다. 준비·후보·파지 확정 사건의 합계 `+73`보다 실패 비용이 커야 파지

  배수 완화 제안은 이 보상 원장 검산에서 확인된 조기 종료 경로 때문에 일부만 채택했다.

  확인한다.

  켜지 않는다. 보상 discount `0.995`는 PPO gamma `0.995`와 맞췄으므로 이번 실행에서 gamma만
  별도로 덮어쓰면 안 된다.

## V42 실패 원인 확정과 V43 정책

확정된 결함은 v42의 검증 후 들기 보상이다. 파지 시 potential 0에서 시작해 미완료 시간 초과나

보상이 정확히 0으로 상쇄됐다. 첫 들기가 한 번도 없는 상태에서는 이 보상이 상승 탐색을 강화할

v43은 사용자 지시에 따라 중지했다. 실행은 1598회까지 기록됐고 마지막 체크포인트는
`2026-07-17_10-31-29_fresh_meter_coupled_lift_v43/model_1575.pt`다. 마지막 50회 평균은 파지
`96.62%`, 현재 그립 `96.61%`, 물체 높이 `.62805m`, 파지 뒤 수평 이동 `2.37cm`였다. 관측·보상된
결합 상승량은 각각 약 `.000784m`였고 들기·운반·성공은 한 번도 발생하지 않았다. 시간 초과의
`96.61%`가 행동자 운반 단계에서 생겼다.

v43의 미터 단위 watermark 자체는 정상 작동했다. 문제는 보상의 크기와 시간 배치였다. 최근 50회
기준 검증 상승 보상은 에피소드당 약 `+0.118`에 불과했지만 파지 뒤 보조 제어 진입 전 지연 비용은
약 `-194.75`였다. 조금이라도 오르는 탐색이 다음 상승을 배우기 전에 시간 비용에 묻혔고, 더 오래
학습해도 들기 사건은 `0%`였다. v39와 달리 파지 뒤 수평 탐색은 이미 `2~4cm` 나타났으므로 XY
탐색 부족이나 제어기 진입 실패가 최초 병목은 아니다.

v44는 제어기나 상태 기준을 바꾸지 않고 이 보상 불균형만 고친다.

- 파지 확정부터 보조 제어 진입까지 같은 활성 조건을 쓰는 `preassist_delay` 가중치를
  `-15.0 -> -1.5/s`로 낮춘다. 들기 또는 운반 임계점을 넘는 순간 비용이 다시 커지는 단계별
  규칙은 사용하지 않는다. 따라서 정책이 특정 높이나 이동 거리 바로 앞에서 멈출 새 경계가 없다.
- 미완료 시간 초과의 파지 뒤 배수는 `1.0 -> 2.0`으로 높여 일회성 비용을 `-50 -> -100`으로
  되돌린다. 빠른 상승은 학습할 수 있게 하되, 파지만 한 채 16초를 버티는 행동은 계속 손해다.
- 실제 결합 상승량 `r`에 `B(r)=4*.010*(1-exp(-r/.010))`의 포화형 등가 상승량을 더한다.
  보상은 `150 * delta(r+B(r))`다. 시작 기울기는 `750/m`이고 상승할수록 연속적으로 `150/m`에
  수렴한다. 추가분은 최대 `6`, 기존 실제 상승분까지 합친 검증 보상 상한은 약 `19.95`다.
- 원시 상승 watermark는 계속 단조 증가한다. 그립이 유효하지 않을 때 처음 본 상승은 원시분과
  포화형 추가분 모두 소진되며, 그립을 회복하거나 같은 높이를 반복해도 다시 지급하지 않는다.
  실패·놓기·시간 초과는 같은 스텝의 상승보다 먼저 처리한다.
- TensorBoard에는 기존 원시 관측·보상 상승량과 별도로 미터 단위
  `task_verified_lift_bootstrap_credited_rise`를 기록한다. 두 값을 합한 뒤 `150`을 곱하면 검증
  상승 보상의 할인 전 에피소드 누적값이다.

보상 상한도 다시 검산했다. 준비·후보·파지·들기 사건과 검증 상승의 최대 합은
`8+15+50+15+19.95=107.95`로, 행동자 구간에서 큐브를 떨어뜨렸을 때의 `-110`보다 작다. v43의
마지막 정지 궤적을 v44 값으로 환산하면 약 `-70`이므로 파지 후 정지와 시간 초과는 여전히 이득이
아니다. 다만 감마 `0.995` 때문에 아주 늦은 시간 초과 비용이 앞부분에서 작게 보이는 lift-only
국소해는 정적 계산만으로 완전히 배제할 수 없다. 아래 중간 판정 기준으로 실제 학습에서 확인한다.

`is_finite_horizon=True`, PPO와 행동자 권한 마스킹, 3단계 파지 진입, 목표점과 관측값, 전역 자체
충돌과 두 링크 필터, 들기·운반·보조 제어·하강·놓기 기준은 모두 그대로다. 기존 체크포인트를
불러오지 않고 처음부터 실행한다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_smooth_lift_bridge_v44
```

최근 50회 기준으로 300회에는 후보 도달 `>=90%`와 첫 실제 파지가 나타나야 한다. 500회에는 파지
`>=85%`, 현재 그립 `>=80%`, 원시 보상 상승량 `>=.0005m`가 필요하다. 700회에는 시간 초과
`100%`도 허용하지만 원시 상승량 `>=.0015m`, 물체 높이 `>=.624m`이며 둘 다 증가 추세여야 한다.
850회까지 첫 들기가 나타나고 들기 `>=20%`, 1000회에는 들기 `>=80%`와 첫 운반·성공이 나타나는
것을 정상 경로로 본다. 700회에도 상승량이 `.0015m` 미만으로 정체되거나 1000회에도 들기가
`1%` 미만이면 더 돌리지 않는다.

## V44 종료 결과

v44는 3417회에서 중지했다. 최근 50회 성공률 최고값은 2902회에서 약 `58.56%`였고, GUI 확인에는
`model_2900.pt`를 사용했다. 이 모델의 최근 50회 파지·들기·검증 운반은 약
`98.64/98.47/98.45%`였다. 사용자는 파지, 이후 운반, 하강과 놓기는 양호하지만 파지 직후 큐브를
안전 높이까지 먼저 올리지 않고 바스켓 방향으로 비스듬히 이동해 충돌한다고 확인했다.

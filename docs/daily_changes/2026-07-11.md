## v25 결정론적 파지와 실제 운반 검증

v24 `model_1125.pt`는 학습 로그에서 성공률이 약 `73.75%`였지만, GUI에서 20회 연속 큐브를
집지 못했다. 팔은 목표점으로 잘 이동했다.

확인한 원인:

- RSL-RL 학습 전개는 가우시안 표본 동작을 사용하고 GUI 실행은 정책망 평균 동작만 사용한다.
- 모델 1125의 동작 표준편차는 평균 `0.2947`, 그리퍼 표준편차는 `0.2942`였다. 그리퍼 닫힘 임계값은
  `-0.15`인데 마지막 그리퍼 편향값은 `-0.0839`였다. 학습 중에는 잡음이 그리퍼를 닫았지만 GUI에서는
  평균 동작이 데드밴드에 남아 계속 열릴 수 있었다.
- 기존 파지·유지 근접도는 두 손가락 점수의 평균과 `.32/.25` 임계값을 사용했다. 한쪽 손가락만
  가까워도 조건을 통과할 수 있었고, 큐브 높이가 2개 제어 주기 동안 올라가면 파지 상태가 영구 고정됐다.
- 기존 성공 조건은 손 위치가 아니라 실제 큐브의 목표 XY/Z/속도를 검사했다. 다만 약한 파지 상태가
  고정된 뒤 제어기가 큐브를 밀거나 튕겨 넣은 에피소드도 집기·놓기 성공으로 집계될 수 있었다.

v25 수정:

- 그리퍼는 정책망 표본 임계값에 의존하지 않는다. 양쪽이 파지 준비 상태면 자동으로 닫고,
  검증된 들기·운반·배치·놓기 준비 뒤에만 자동으로 연다. 가공하지 않은 그리퍼 동작은 단계 정렬
  보조 신호로만 유지하고 페널티를 `-4 -> -1`로 낮췄다.
- 파지 준비·유지 조건은 두 손가락 근접도의 최솟값을 사용한다. 빈손으로 완전히 닫힌 상태도 파지 후보에서
  제외한다.
- 파지는 큐브와 TCP가 각각 `10/8mm` 이상 함께 상승하고, TCP 지역 좌표의 물체 오프셋 오차
  `<=12mm`, 물체와 TCP 물체 지점의 상대속도 `<=0.15m/s`를 5개 제어 주기 연속 만족해야 한다.
- TCP 속도는 링크 원점의 선속도·각속도와 `omega x r`을 사용하므로 정상적인 손목 회전을
  미끄러짐으로 잘못 판단하지 않는다. 불안정한 후보는 다음 안정 구간에서 기준점을 다시
  잡을 수 있다.
- 파지 유지는 파지 시점의 TCP 지역 좌표 오프셋 오차 `<=25mm`와 상대속도 `<=0.20m/s`를 계속 요구한다.
  들기는 높이 `0.73m`에서 3개 제어 주기, 운반은 검증된 파지 유지 상태에서 실제 큐브의 XY 이동
  `>=5cm`를 3개 제어 주기 확인한다.
- 배치 보조 제어, 바스켓 진입, 놓기, 성공 판정은 운반이 검증되기 전에는 시작할 수 없다. 성공 조건은
  파지·들기·운반·바스켓 진입·중앙 정렬·놓기 이력과 실제 큐브의 안착 자세·속도를 모두 요구한다.
- v24의 팔 동작 배율, 운반·고도 유지 보상, 목표, 전체 6차원 PlaceAssist 이득과 동작 한계는 유지했다.
- Stage PPO는 `noise 0.30 -> 0.15`, `entropy 1e-4 -> 0`, `gamma 0.98 -> 0.995`로 변경했다.
  16초 작업의 최종 보상이 초기 파지 행동까지 전달되고 표본 학습 전개와 정책망 평균 동작의 차이가
  줄어든다. 관측·동작·보상 계약은 `74/8/19`로 유지된다.

검증:

- `py_compile` 및 `git diff --check` 통과.
- 환경 8개, 반복 1회의 실행 확인에서 Stage 관리자, 관측 74개, 동작 8개, 보상 19개,
  자동 그리퍼, TCP 링크 속도 API가 정상 초기화됐다.
- 실행 확인에서 평균 동작의 잡음 표준편차는 `0.15`였고 잘못된 파지·보조 제어·성공 판정은 모두 0이었다.
- 기존 모델 1125를 새 조건으로 960 프레임 재생했을 때도 실제 큐브 운반은 없었다. 이전
  확률적 성공률을 재사용하지 않고 새 정책을 학습해야 한다.

밤샘 신규 학습 명령:


`--resume`, `--load_run`, `--checkpoint`, 부트스트랩은 사용하지 않는다. 환경 5120개의 기존 측정값
`4.27s/iteration` 기준 약 5.9시간이며 체크포인트는 25회 반복마다 저장된다.

## v26 중심 정렬 파지와 재시도

v25 `model_1000.pt`는 TensorBoard에서 파지 약 `97%`, 성공 약 `83%`로 보였지만, 각 환경에서 처음
완료한 에피소드만 세는 정책망 평균 동작 평가에서는 기존 조건의 파지율이 `10.94%`, 성공률이
`5.47%`였다. 학습 전개의 가우시안 표본과 빠른 성공 후 초기화가 지표를 과대표집한 반면, GUI는
잡음 없는 정책망 평균 동작을 사용한 것이 차이의 원인이었다.

실패 궤적에서 확인한 직접 원인:

- 기존 근접도 `.32`는 손가락 본체 원점과 큐브가 약 `116mm` 떨어져도 닫힘을 시작했다.
- 손가락이 닫히는 약 9개 제어 주기 동안 정책망이 TCP를 약 `60mm` 움직여 큐브를 옆으로 밀었다.
- 빗나간 뒤에도 느슨한 파지 유지 상태가 이어져 빈 그리퍼를 다시 열지 않았다.
- 고정 높이 `.640m`는 실제 안착 높이 `.62046m`보다 `19.54mm` 높아 접촉 기준과 맞지 않았다.
- 학습된 동작 표준편차는 약 `.148`로 남아 확률적 학습 전개가 실패를 우연히 보충했다.

v26 수정:

- 측정된 성공 영역인 TCP 지역 좌표 오프셋 목표 `(-8,+3,-28)mm`, X `[-20,+10]mm`,
  Y `[-5,+8]mm`, Z `[-40,-12]mm`, 손가락 거리 비대칭 `<=7mm`, 양쪽 근접도 `.48`을
  모두 만족할 때만 닫는다. 시도 유지 `.38`과 운반 유지 기준 `.25`는 분리했다.
- 팔 동작이 그리퍼보다 먼저 처리되는 같은 제어 주기에 파지 시도를 고정하고 현재 관절 목표를
  유지한다. 닫힘 8개 제어 주기 이후 실제 큐브 접촉 형태를 3개 제어 주기 확인한다.
- 접촉 후 전체 6차원 DLS로 TCP를 최대 `18mm`만 들어 큐브와 TCP가 각각 `12/10mm` 이상 함께
  움직이는지 확인한다. 고정된 월드 Z 조건은 제거했다.
- 접촉이 끊기거나 닫힘이 18개 제어 주기, 검증이 30개 제어 주기를 넘기면 자동으로 다시 열고
  재시도한다. 실패한 시도에는 일회성 페널티 `-10`을 주고 3회 실패한 에피소드만 종료한다.
- 접근 잠재 보상은 손가락 원점 근접도가 아니라 중앙에 맞춘 지역 좌표 정렬과 상대속도를 사용한다.
  3차원 파지 관측은 중복된 닫힘·열림 상태 대신 정규화된 TCP 지역 좌표 XYZ를 제공한다.
- 자동 닫힘·검증 중에는 정책망의 들기 보상과 동작 변화율 보상을 지급하지 않는다. 기존 들기,
  운반, 바스켓 PlaceAssist, 놓기, 성공 조건과 파지 후 유지 기준 `.25`는 그대로 뒀다.
- Stage PPO 초기 잡음은 `.15 -> .05`로 낮춰 새 학습 전개와 GUI 정책망 평균 동작의 차이를 줄였다.

검증:

- 실행 관리자의 관측·동작·보상 계약은 `74/8/20`이다.
- 기존 v25 모델 1000으로 새 상태기를 평가했다. 정책망 평균 동작으로 끝까지 진행한 에피소드
  128개에서 준비/후보/파지/들기/운반은 `80.47/53.91/42.19/39.84/39.06%`, 실패 종료는
  `2.34%`였다. 접촉
  후보 중 실제 파지 전환은 약 `78%`였다. 관측 3개의 의미가 바뀌었으므로 구형 모델의 배치
  성공률은 비교하지 않는다. 이 결과는 상태기 검증용이며 v26은 새로 학습한다.

## v27 실제 접촉 파지와 정책망 들기 복구

v26 `2026-07-11_05-23-39`는 5000회 반복을 마쳤지만 검증 파지는 반복 114의
`2.083%`가 최고였고 이후 0으로 붕괴했다. 들기·운반·보조 제어·성공은 끝까지 0이었다. 마지막
에피소드는 시간 초과 `89.09%`, 실패 `10.91%`였고 TCP 지역 좌표 오프셋은 목표에서 약 20cm 멀어진
`(-.213,+.081,-.137)m`였다.

직접 확인한 원인:

- 파지 재시도 `-10`, 3회 중단 실패, `failed -50 -> -100` 증가가 겹치면서 파지를 시도하기보다
  시간 초과 `-50`을 선택하는 편이 유리했다.
- 접근 잠재 보상은 이전 최고점으로 돌아올 때 보상하지 않으면서 모든 후퇴를 반복 차감해
  에피소드 초기에 실제 기여가 약 `-169`까지 커졌다.
- 한 프레임 정렬만으로 팔을 고정했고, 접촉 뒤 자동 DLS 들기가 정책망의 팔 제어권을 가져갔다.
- 두 손가락 벌림값의 평균을 사용해 한쪽은 열리고 다른 쪽은 닫힌 상태도 접촉으로 통과할 수 있었다.
- 새 PPO 학습의 잡음 `.05`는 v18/v25의 `.15`보다 작아 회피 자세에서 빠져나오기 어려웠다.

v27 수정:

- 정렬 조건을 3개 제어 주기 유지해야 닫힘을 시작한다. 접촉은 양쪽 손가락이 각각 닫힘·열림
  임계값을 만족하고 벌림값 비대칭 `<=.20`, 최대 관절 속도 `<=.03rad/s`를 3개 제어 주기
  만족해야 한다. 빈손 완전 닫힘과 한쪽만 닫힌 상태는 통과하지 않는다.
- 접촉 뒤 자동 들기를 제거했다. 그리퍼만 계속 닫고 팔 목표는 제어 주기당 최대 `.03rad`로 완만하게
  바꿔 정책망이 직접 큐브와 TCP를 들어 올리게 한다. 실제 물체/TCP 동반 상승 `12/10mm`, 결합
  오차 `<=12mm`, 5개 제어 주기 유지의 검증 조건은 그대로 둔다.
- 결합 또는 상대속도가 불안정한 후보는 들기 보상에서 즉시 제외하고 6개 제어 주기 지속되면
  중단한다. 후보가 끊겨도 에피소드의 들기 최고점은 초기화하지 않아 같은 짧은 상승 반복 보상을
  막는다.
- 재시도 페널티와 최대 시도 실패 조건을 제거했다. 실패하면 팔을 고정한 채 그리퍼를 완전히 연
  다음, 정책망에 6개 제어 주기 재배치 시간을 주고 3개 제어 주기 정렬 유지부터 다시 시작한다.
- 접근 보상은 정지 중 누적되지 않고 에피소드의 새 정렬 최고점만 보상한다. 후퇴를 반복 차감하지
  않으며 재시도로 이전 최고점을 다시 통과해도 중복 보상하지 않는다.
- `gamma=.995`, 30Hz에서 취득 전 `-7.5/초 + timeout -50`, 취득 후 보조 제어 진입 전
  `-15/초 + timeout -100`을 적용한다. 제어 주기마다 각각 `-.25/-.5 = terminal * (1-.995)`이므로
  기다린 시간과 무관하게 할인된 미완료 비용이 유지된다.
- 두 단계 비용 차이 `50`은 검증된 파지 `+50`으로 정확히 연결한다. 실제 큐브 낙하 실패는 취득 전
  `-55`, 취득 후 `-110`으로 시간 초과보다 더 낮춰 파지 회피, 파지 후 낙하, 파지만 유지하기,
  조기 큐브 파괴 편법을 모두 막았다.
- 파지 후 유지, 운반·고도 유지 잠재 보상, 바스켓 PlaceAssist, 놓기, 성공, 목표 좌표와 이득은
  v25/v26 그대로 유지했다. 취득 후 유지 벌림값도 확인된 평균 동작 조건을 보존한다.
- 정책에 조건 형상과 현재 시도·후보·허가·검증·재시도·재열기 단계를 추가했다. 관측·동작·보상
  계약은 `83/8/21`이며 구형 체크포인트와 호환되지 않는다.
- Stage PPO는 잡음 `.15`, 엔트로피 `1e-4`로 복원했다.

정적 검증:

- `compileall`, `git diff --check`, 종료 함수·설정 매개변수 계약 검사를 통과했다.
- 양쪽 벌림값 사례에서 정상 대칭 접촉만 통과하고 빈손 닫힘, 한쪽 닫힘, 비대칭 부분 닫힘은 모두
  거부되는 것을 확인했다.
- 사용자가 직접 실행하기로 했으므로 시뮬레이션과 GUI 실행은 하지 않았다.

# 2026-07-11

## v25 결정론적 파지와 실제 운반 검증

v24 `model_1125.pt`는 학습 로그에서 성공률이 약 `73.75%`였지만, GUI에서 20회 연속 큐브를
집지 못했다. 팔은 목표점으로 잘 이동했다.

확인된 원인:

- RSL-RL 학습 rollout은 Gaussian sample action을 사용하고 GUI play는 actor mean만 사용한다.
- model 1125의 action std는 평균 `0.2947`, gripper std는 `0.2942`였다. Gripper close threshold는
  `-0.15`인데 마지막 gripper bias는 `-0.0839`라, 학습 중에는 noise가 gripper를 닫고 GUI에서는
  mean이 dead-band에 남아 계속 열릴 수 있었다.
- 기존 grasp/hold proximity는 두 finger score 평균과 `.32/.25` threshold를 사용했다. 한쪽
  finger만 가까워도 gate를 통과할 수 있고, cube 높이가 2 step 올라가면 grasp가 영구 latch됐다.
- 기존 성공 자체는 손 위치가 아니라 실제 cube의 goal XY/Z/speed를 검사했다. 다만 약한 grasp
  latch 뒤 controller가 cube를 밀거나 튕겨 넣은 episode도 pick-place로 집계될 수 있었다.

v25 수정:

- Gripper는 actor sample 임계값에 의존하지 않는다. Bilateral grasp-ready이면 자동 close하고,
  검증된 lift/transport/place/release-ready 뒤에만 자동 open한다. Raw gripper action은 phase 정렬
  보조 신호만 유지하고 penalty를 `-4 -> -1`로 낮췄다.
- Grasp-ready/hold는 두 finger proximity의 최솟값을 사용한다. 빈손 완전 닫힘도 grasp 후보에서
  제외한다.
- Grasp는 cube와 TCP가 각각 `10/8mm` 이상 함께 상승하고, TCP local object offset 오차
  `<=12mm`, object와 TCP object-point 상대속도 `<=0.15m/s`를 5 step 연속 만족해야 한다.
- TCP 속도는 link-origin linear/angular velocity와 `omega x r`을 사용한다. 따라서 정상적인
  wrist rotation을 slip으로 오판하지 않는다. 불안정한 후보는 다음 안정 구간에서 기준점을 다시
  잡을 수 있다.
- Hold는 grasp 시점 TCP-local offset 오차 `<=25mm`, 상대속도 `<=0.20m/s`를 계속 요구한다.
  Lift는 높이 `0.73m`에서 3 step, transport는 verified hold 상태의 실제 cube XY 이동 `>=5cm`를
  3 step 확인한다.
- Place assist, basket, release, success는 verified transport 전에는 시작할 수 없다. Success는
  grasp/lift/transport/basket/center/release 이력과 실제 cube settle pose/speed를 모두 요구한다.
- v24의 arm scale, transport/carry reward, goal, full-6D PlaceAssist gain과 motion limit는 유지했다.
- Stage PPO는 `noise 0.30 -> 0.15`, `entropy 1e-4 -> 0`, `gamma 0.98 -> 0.995`로 변경했다.
  16초 task의 최종 보상이 초기 파지 행동까지 전달되고 sampled rollout과 mean policy의 차이가
  줄어든다. Observation/action/reward 계약은 `74/8/19`로 유지된다.

검증:

- `py_compile` 및 `git diff --check` 통과.
- 8 env, 1 iteration runtime smoke에서 Stage manager, 74 observations, 8 actions, 19 rewards,
  auto gripper, TCP link velocity API가 정상 초기화됐다.
- Smoke에서 mean action noise std `0.15`, false grasp/assist/success는 모두 0이었다.
- 기존 model 1125를 새 gate로 960 frame 재생했을 때도 실제 cube transport는 없었다. 이전
  stochastic 성공률을 재사용하지 않고 fresh policy로 학습해야 한다.

밤샘 신규 학습 명령:

```bash
python scripts/rsl_rl/train.py --task Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs 5120 --device cuda --max_iterations 5000 --headless --run_name fresh_verified_grasp_mean_v25
```

`--resume`, `--load_run`, `--checkpoint`, bootstrap은 사용하지 않는다. 5120 env의 기존 측정값
`4.27s/iteration` 기준 약 5.9시간이며 checkpoint는 25 iteration마다 저장된다.

## v26 중심 정렬 파지와 재시도

v25 `model_1000.pt`는 TensorBoard에서 파지 약 `97%`, 성공 약 `83%`로 보였지만, 각 환경의 첫
완전한 episode만 세는 actor-mean 평가에서는 기존 gate 파지 `10.94%`, 성공 `5.47%`였다. 학습
rollout의 Gaussian sample과 빠른 성공 reset이 지표를 과대표집했고, GUI는 noise 없는 actor mean을
사용한 것이 차이의 원인이었다.

실패 궤적에서 확인한 직접 원인:

- 기존 proximity `.32`는 finger body origin과 cube가 약 `116mm` 떨어져도 닫힘을 시작했다.
- finger가 닫히는 약 9 control step 동안 actor가 TCP를 약 `60mm` 움직여 cube를 옆으로 밀었다.
- 빗나간 뒤에도 loose hold가 유지되어 빈 그리퍼를 다시 열지 않았다.
- 고정 높이 `.640m`는 실제 settle 높이 `.62046m`보다 `19.54mm` 높아 접촉 기준과 맞지 않았다.
- 학습된 action std는 약 `.148`로 남아 stochastic rollout이 실패를 우연히 보충했다.

v26 수정:

- 측정된 성공 basin인 TCP-local offset target `(-8,+3,-28)mm`, X `[-20,+10]mm`,
  Y `[-5,+8]mm`, Z `[-40,-12]mm`, finger 거리 비대칭 `<=7mm`, bilateral proximity `.48`을
  모두 만족할 때만 닫는다. 시도 유지 `.38`과 운반 hold `.25`는 분리했다.
- arm action이 gripper보다 먼저 처리되는 같은 control step에 파지 시도를 latch하고 현재 관절
  target을 고정한다. 닫힘 8 step 이후 실제 cube 접촉 형태를 3 step 확인한다.
- 접촉 후 full-6D DLS로 TCP를 최대 `18mm`만 들어 cube와 TCP가 각각 `12/10mm` 이상 함께
  움직이는지 확인한다. 고정 world-Z 조건은 제거했다.
- 접촉 손실, 18-step 닫힘 timeout, 30-step 검증 timeout이면 자동으로 다시 열고 재시도한다.
  실패 시도에는 `-10` one-shot penalty를 주고 3회 실패한 episode만 종료한다.
- 접근 potential은 finger-origin 근접도가 아니라 centered local alignment와 상대속도를 사용한다.
  3차원 grasp observation은 중복이던 closed/open 대신 normalized TCP-local XYZ를 제공한다.
- scripted close/verification 중에는 actor lift/action-rate reward를 지급하지 않는다. 기존 lift,
  transport, basket PlaceAssist, release, success 조건과 post-grasp hold `.25`는 유지했다.
- Stage PPO 초기 noise는 `.15 -> .05`로 낮춰 fresh rollout과 GUI actor mean 차이를 줄였다.

검증:

- `py_compile`, `git diff --check`, 8-env/1-iteration runtime smoke를 통과했다.
- runtime manager contract는 observation/action/reward `74/8/20`이다.
- 기존 v25 model1000으로 새 상태기를 평가한 128개 actor-mean 완전 episode에서 ready/candidate/
  grasp/lift/transport는 `80.47/53.91/42.19/39.84/39.06%`, 실패 종료는 `2.34%`였다. 접촉
  candidate 중 실제 파지 전환은 약 `78%`였다. 관측 3개의 의미가 바뀌었으므로 구형 모델의 place
  성공률은 비교하지 않으며, 이 결과는 상태기 검증용이고 v26은 fresh 학습한다.

밤샘 신규 학습 명령:

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_centered_grasp_v26
```

`--resume`, `--load_run`, `--checkpoint`, bootstrap은 추가하지 않는다.

## v27 실제 접촉 파지와 actor lift 복구

v26 `2026-07-11_05-23-39`는 5000 iteration을 끝냈지만 검증 파지는 iteration 114의
`2.083%`가 최고였고 이후 0으로 붕괴했다. lift/transport/assist/success는 끝까지 0이었다. 마지막
episode은 timeout `89.09%`, failure `10.91%`였고 TCP-local offset은 목표에서 약 20cm 멀어진
`(-.213,+.081,-.137)m`였다.

확인된 직접 원인:

- 파지 재시도 `-10`, 3회 abort failure, `failed -50 -> -100` ramp가 합쳐져 파지를 시도하는
  것보다 timeout `-50`을 선택하는 편이 유리했다.
- approach potential은 이전 최고점으로 돌아올 때 보상하지 않으면서 모든 후퇴를 반복 차감해
  episode 초기에 실제 기여가 약 `-169`까지 커졌다.
- 한 frame 정렬만으로 팔을 고정했고, 접촉 뒤 scripted DLS lift가 actor의 팔 제어권을 가져갔다.
- 두 finger aperture의 평균을 사용해 한쪽 open/한쪽 closed도 접촉으로 통과할 수 있었다.
- fresh PPO noise `.05`는 v18/v25의 `.15`보다 작아 회피 자세에서 빠져나오기 어려웠다.

v27 수정:

- 정렬 조건을 3 control step 유지해야 close를 시작한다. 접촉은 양 finger가 각각 closed/open
  threshold를 만족하고 aperture 비대칭 `<=.20`, 최대 joint speed `<=.03rad/s`를 3 step
  만족해야 한다. 빈손 완전 닫힘과 한쪽만 닫힌 상태는 통과하지 않는다.
- 접촉 뒤 scripted lift를 제거했다. 그리퍼만 계속 닫고 arm target은 step당 최대 `.03rad`로
  slew해 actor가 직접 cube/TCP를 들어 올린다. 실제 object/TCP 동반 상승 `12/10mm`, coupling
  error `<=12mm`, 5-step dwell의 검증 조건은 유지한다.
- coupling 또는 relative-speed 불안정 후보는 lift reward에서 즉시 제외하고 6 step 지속 시
  abort한다. 후보가 끊겨도 episode lift 최고점은 초기화하지 않아 같은 짧은 상승 반복 보상을
  막는다.
- retry penalty와 최대 시도 failure를 제거했다. 실패 시 arm을 고정한 채 gripper를 완전히 연
  다음, actor에게 6 step 재배치 시간을 주고 3-step 정렬 dwell부터 다시 시작한다.
- approach reward는 정지 중 누적되지 않고 episode의 새 alignment 최고점만 보상한다. 후퇴를
  반복 차감하지 않으며 retry로 이전 최고점을 다시 통과해도 중복 보상하지 않는다.
- `gamma=.995`, 30Hz에서 취득 전 `-7.5/초 + timeout -50`, 취득 후 assist 진입 전
  `-15/초 + timeout -100`을 적용한다. 스텝당 각각 `-.25/-.5 = terminal * (1-.995)`이므로
  기다린 시간과 무관하게 할인된 미완료 비용이 유지된다.
- 두 단계 비용 차이 `50`은 verified grasp `+50`으로 정확히 연결한다. 실제 cube-drop failure는
  취득 전 `-55`, 취득 후 `-110`으로 timeout보다 더 낮춰 파지 회피, grasp-drop, grasp-hold,
  조기 cube 파괴 편법을 모두 막았다.
- post-grasp hold, transport/carry potential, basket PlaceAssist, release, success, 목표 좌표와
  gain은 v25/v26 그대로 유지했다. 취득 후 hold aperture도 검증된 mean 조건을 보존한다.
- policy에 gate geometry와 현재 attempt/candidate/authorized/verification/retry/reopen phase를
  추가했다. 관측/action/reward 계약은 `83/8/21`이며 구형 checkpoint와 호환되지 않는다.
- Stage PPO는 noise `.15`, entropy `1e-4`로 복원했다.

정적 검증:

- `compileall`, `git diff --check`, termination callable/config parameter 계약 검사를 통과했다.
- bilateral aperture 사례에서 정상 대칭 접촉만 통과하고 empty-close, one-side-close,
  asymmetric partial close는 모두 거부됨을 확인했다.
- 사용자가 직접 실행하기로 했으므로 simulation/GUI runtime은 실행하지 않았다.

신규 학습 명령은 반드시 한 줄로 실행한다:

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_bilateral_grasp_v27
```

판단 지점:

- model 25: alignment/closing/contact 지표가 0이 아니고 abort 원인이 기록되어야 한다.
- model 100: verified grasp가 0이 아니며 candidate object/TCP lift가 함께 양수여야 한다.
- model 250: grasp와 lift가 상승 추세이고 transport가 시작되어야 한다.
- model 500: actor-mean GUI에서 grasp/lift가 반복되고 validated transport가 0이 아니어야 한다.
- model 1000: basket/center/release/success 중 다음 단계 지표가 열려야 한다.

model 100~250에서도 candidate는 많은데 candidate object lift가 계속 0이거나 verification timeout만
증가하면 더 돌리지 말고 해당 checkpoint와 TensorBoard 지표를 분석한다.

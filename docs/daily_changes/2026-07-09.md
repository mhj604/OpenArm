# 2026-07-09 변경 기록

## 1. 들기 조건 때문에 운반 보상이 0으로 막히는 문제 수정

`lifted_transport_v5` 학습 상태를 확인했다.

관찰:

- 학습은 중단되지 않고 약 4000회 반복까지 정상 진행됐다.
- `Loss/value_function`과 `Episode_Reward/action_rate`는 안정화됐다.
- 하지만 GUI에서는 큐브를 집고 들어올리는 동작만 보이고 목표점 방향 운반이 거의 개선되지 않았다.

로그 기준:

- `lifting_object_early`는 약 `15` 수준까지 올라왔다.
- `lifting_object`는 계속 `0.0`이었다.
- `object_goal_tracking`, `object_goal_xy_progress`, `object_goal_y_progress`가 모두 `0.0`이었다.
- `object_released_at_goal`도 계속 `0.0`이었다.

판단:

- 정책이 파지·들기를 전혀 못하는 것이 아니다.
- 현재 정책은 `EARLY_LIFT_HEIGHT_W=0.69` 부근까지는 물체를 들어올린다.
- 하지만 모든 운반 보상이 `MIN_LIFT_HEIGHT_W=0.74`를 넘어야만 켜지도록 되어 있었다.
- 이 때문에 목표점 방향으로 움직이는 보상이 학습 중 거의 전부 0으로 막혔다.
- 정책은 "집고 약간 들기"에서 멈췄고 바스켓 방향 이동을 배울 신호를 받지 못했다.

수정:

- 운반용 들기 조건을 별도 상수로 분리했다.
  - `TRANSPORT_LIFT_HEIGHT_W = EARLY_LIFT_HEIGHT_W`
- 최종 들기 높이 기준은 조금 낮췄다.
  - `MIN_LIFT_HEIGHT_W: 0.74 -> 0.72`
- 목표 이동 관련 보상의 `minimal_height`를 `MIN_LIFT_HEIGHT_W`에서 `TRANSPORT_LIFT_HEIGHT_W`로 변경했다.
  - `object_goal_tracking`
  - `object_goal_xy_tracking`
  - `object_goal_xy_progress`
  - `object_goal_x_tracking`
  - `object_goal_y_tracking`
  - `object_goal_y_tracking_broad`
  - `object_goal_y_progress`
  - `object_goal_z_tracking`
  - `object_goal_height_tracking`
  - `object_goal_tracking_fine_grained`
  - `object_goal_bonus_coarse`
  - `object_goal_bonus_mid`
  - `object_goal_bonus_tight`
  - `object_goal_stable_hold`

의도:

- 큐브를 조금 든 상태부터 바스켓 방향 이동 보상을 켠다.
- 높은 들기를 먼저 완벽하게 만족하지 못해도 운반을 학습할 수 있게 한다.
- 현재 정책이 이미 배우고 있는 파지·들기를 버리지 않고 그 다음 단계인 왼쪽 이동으로 보상 기울기를 연결한다.

주의:

- 이미 떠 있는 GUI의 `model_4000.pt`는 수정 전 `lifted_transport_v5` 정책이다.
- 이번 수정은 다음 학습부터 적용된다.

## 2. 이진 들기 보상을 연속 들기 진행 보상으로 재설계

`transport_gate_v6`를 1200회 반복 부근까지 확인했다.

관찰:

- 수치 안정성은 정상이다.
  - `Loss/value_function`은 약 `4.27`
  - `inf/NaN/outlier` 없음
- 하지만 들기와 운반이 여전히 켜지지 않았다.
  - `lifting_object_early=0.0`
  - `lifting_object=0.0`
  - `object_goal_xy_progress=0.0`
  - `object_goal_y_progress=0.0`
  - `object_goal_tracking=0.0`

판단:

- 운반 조건을 낮췄지만 들기 보상 자체가 여전히 이진 기준값 구조였다.
- 물체가 기준값을 넘기 전까지는 들기 보상이 0이므로, 정책이 "조금 들어올리는 중간 과정"을 학습할 신호가 부족했다.
- 운반 보상도 계속 0으로 막혔다.

수정:

- `object_lift_progress_with_grasp()`를 추가했다.
  - 닫힌 파지 상태에서 물체 높이가 목표 높이로 얼마나 진행됐는지 연속 보상으로 계산한다.
- 높이 기준을 재조정했다.
  - `LIFT_PROGRESS_START_HEIGHT_W = OBJECT_START_POS_W[2] + 0.01`
  - `EARLY_LIFT_HEIGHT_W: 0.69 -> 0.66`
  - `TRANSPORT_LIFT_HEIGHT_W = EARLY_LIFT_HEIGHT_W`
  - `MIN_LIFT_HEIGHT_W: 0.72 -> 0.70`
- `lifting_object_early`를 이진 `object_is_lifted`에서 연속 진행 보상으로 교체했다.
  - `0.635m -> 0.66m` 들기 진행
  - 가중치 `34.0`
- `lifting_object`도 연속 진행 보상으로 교체했다.
  - `0.66m -> 0.70m` 들기 진행
  - 가중치 `24.0`
- `closed_gripper_lift_target` 가중치를 강화했다.
  - `10.0 -> 16.0`

의도:

- 기준값을 넘기 전까지 보상이 0인 희소 보상 문제를 제거한다.
- 파지 이후 물체 높이가 1cm라도 올라가면 들기 방향 보상을 받게 한다.
- 들기 진행이 운반 보상 조건까지 자연스럽게 이어지도록 만든다.
- 다음 학습에서는 `lifting_object_early`가 초반부터 0을 벗어나야 한다.

## 3. 닫힌 파지 뒤 손 상승 보상 추가

`transport_gate_v6`가 1500회 반복을 넘겨도 다음 상태가 유지됐다.

관찰:

- `reaching_object_fine`, `right_fingers_near_object`, `gripper_closed_near_object`는 유지됐다.
- 하지만 `lifting_object_early`, `lifting_object`, `object_goal_*`는 계속 `0.0`이었다.
- 정책은 물체 근처에서 손을 닫는 단계까지는 가지만 닫은 손을 위로 들어 실제 들기로 연결하지 못했다.

판단:

- 물체 높이 기반 보상만으로는 들기 시작 신호가 여전히 늦다.
- 손이 물체 근처에서 닫힌 뒤 위로 움직이는 중간 보상이 필요하다.
- 정적인 파지 근처 보상이 상대적으로 커서, 물체 근처에 머무는 국소 최적점이 생겼다.

수정:

- `body_lift_progress_with_closed_gripper()`를 추가했다.
  - 오른손이 물체 근처에서 닫힌 상태일 때, 오른손 말단 작동부 높이 진행률을 보상한다.
- 새 보상을 추가했다.
  - `right_hand_lift_after_grasp`
  - `LIFT_PROGRESS_START_HEIGHT_W -> HAND_LIFT_TARGET_HEIGHT_W`
  - 가중치 `26.0`
- 들기 유도 보상을 강화했다.
  - `closed_gripper_lift_target: 16.0 -> 20.0`
  - `lifting_object_early: 34.0 -> 42.0`
- 정적인 파지 근처 보상을 낮췄다.
  - `reaching_object_fine: 18.0 -> 14.0`
  - `right_fingers_near_object: 20.0 -> 16.0`
  - `gripper_closed_near_object: 20.0 -> 16.0`

의도:

- 물체 근처에서 닫고 멈추는 정책보다, 닫은 손을 위로 들어올리는 정책이 더 유리하게 만든다.
- 실제 물체 들기 보상이 켜지기 전에도 손 들기 보상으로 들기 동작을 학습시킨다.
- 다음 학습에서는 `right_hand_lift_after_grasp`와 `lifting_object_early`가 먼저 0을 벗어나야 한다.

## 4. 파지 뒤 높은 들기와 바스켓 방향 운반 강화

`hand_lift_v8` 학습 완료 모델을 GUI로 확인했다.

관찰:

- 오른손이 큐브를 집는 동작은 이전보다 안정적이다.
- 하지만 큐브를 집은 뒤 충분히 높게 들지 못하고 바스켓 방향 Y축 이동도 중간에서 멈춘다.
- 현재 병목은 파지가 아니라 `grasp -> higher carry lift -> basket-side transport` 전환이다.

판단:

- 정적인 파지 근처 보상이 아직 커서, 물체 주변에서 잡고 살짝 드는 행동이 국소 최적점으로 남아 있다.
- 목표 명령의 단계별 학습이 너무 짧은 중간 목표에 오래 머물러서, 초반 학습이 바스켓까지 가는 행동보다 짧은 이동을 먼저 고착시킨다.
- 물체 운반 보상은 있지만 손 자체를 바스켓 방향으로 끌어주는 닫힌 파지 운반 유도 보상이 부족하다.

수정:

- 최종 운반 높이 기준을 추가했다.
  - `CARRY_LIFT_HEIGHT_W = 0.75`
  - `HAND_LIFT_TARGET_HEIGHT_W = CARRY_LIFT_HEIGHT_W + 0.04`
- 명령의 단계별 학습을 더 빠르게 최종 바스켓 목표로 보내도록 조정했다.
  - `start_offset_from_object: (0.04, 0.05, 0.14) -> (0.04, 0.12, 0.18)`
  - `curriculum_num_steps: 30000 -> 12000`
  - `curriculum_power: 1.1 -> 0.8`
- 닫힌 파지 상태에서 오른손 말단 작동부가 바스켓 방향 Y축으로 진행하도록 보상을 추가했다.
  - `body_axis_progress_with_closed_gripper()`
  - `right_hand_y_transport_after_grasp`
- 물체가 높은 운반 높이까지 더 올라가도록 보상을 추가했다.
  - `carrying_object_high`
- 바스켓 방향 Y축으로 덜 간 상태를 직접 불리하게 만드는 벌점을 추가했다.
  - `object_goal_axis_shortfall_with_grasp()`
  - `object_goal_y_shortfall`
- 정적인 파지 보상은 낮췄고 운반 관련 보상은 강화했다.
  - `reaching_object_fine: 14 -> 10`
  - `right_fingers_near_object: 16 -> 12`
  - `gripper_closed_near_object: 16 -> 12`
  - `right_hand_lift_after_grasp: 26 -> 34`
  - `object_goal_y_progress: 42 -> 70`

의도:

- 집기 성공 자체보다, 집은 뒤 더 높게 들고 바스켓 방향으로 끝까지 이동하는 행동을 더 유리하게 만든다.
- 중간 목표에 머무는 정책을 줄이고 학습 초반부터 바스켓 쪽 이동을 더 많이 경험하게 한다.
- 다음 학습에서는 `right_hand_y_transport_after_grasp`, `carrying_object_high`, `object_goal_y_progress`가 함께 올라가야 한다.

## 5. 운반 보상이 계속 0이 되는 조건 구조 수정

`carry_transport_v9`를 1000회 반복 이상 확인했다.

관찰:

- 수치 안정성은 좋았다.
  - `Loss/value_function`은 약 `0.23`
  - `object_dropping`은 `0`
- 하지만 핵심 운반 보상이 계속 0이었다.
  - `right_hand_lift_after_grasp = 0`
  - `right_hand_y_transport_after_grasp = 0`
  - `carrying_object_high = 0`
  - `object_goal_y_progress = 0`
- 반대로 파지와 아주 작은 들기 신호는 살아 있었다.
  - `closed_gripper_lift_target > 0`
  - `lifting_object_early > 0`

판단:

- 단순히 보상 가중치가 작은 문제가 아니다.
- `right_hand_lift_after_grasp`의 손 높이 시작 기준이 실제 말단 작동부 높이에 비해 너무 높아서 파지 상태에서도 진행이 0으로 잘렸다.
- 운반 보상은 `TRANSPORT_LIFT_HEIGHT_W`라는 엄격한 조건 뒤에 있어서 물체가 충분히 뜨기 전에는 바스켓 방향 이동 보상이 켜지지 않았다.
- `GRASP_GATE_STD=0.08`도 좁아서 닫힌 파지 근처 상태를 너무 엄격하게 판정했다.

수정:

- 들기 진행 시작 기준을 물체 초기 높이로 낮췄다.
  - `LIFT_PROGRESS_START_HEIGHT_W: OBJECT_START_POS_W[2] + 0.01 -> OBJECT_START_POS_W[2]`
- 초기 들기, 운반 진입, 높은 운반의 높이 조건을 완화했다.
  - `EARLY_LIFT_HEIGHT_W: 0.66 -> 0.645`
  - `TRANSPORT_LIFT_HEIGHT_W: 0.66 -> 0.64`
  - `MIN_LIFT_HEIGHT_W: 0.70 -> 0.68`
  - `CARRY_LIFT_HEIGHT_W: 0.75 -> 0.72`
- 손 들기 진행의 시작점을 말단 작동부에 맞게 별도 분리했다.
  - `HAND_LIFT_START_HEIGHT_W = OBJECT_START_POS_W[2] - 0.12`
  - `HAND_LIFT_TARGET_HEIGHT_W = CARRY_LIFT_HEIGHT_W + 0.02`
- 파지 조건을 완화했다.
  - `GRASP_GATE_STD: 0.08 -> 0.14`
- 바스켓 방향 손 운반 목표를 실제 바스켓 Y 위치까지 확장했다.
  - `RIGHT_HAND_CARRY_TARGET_Y_B: BASKET_GOAL_POS_B[1] - 0.02 -> BASKET_GOAL_POS_B[1]`
- 들기·운반 보상 가중치를 조건 수정에 맞게 재조정했다.
  - `closed_gripper_lift_target: 24 -> 36`
  - `right_hand_lift_after_grasp: 34 -> 42`
  - `right_hand_y_transport_after_grasp: 28 -> 40`
  - `lifting_object_early: 42 -> 60`
  - `lifting_object: 24 -> 40`
  - `carrying_object_high: 30 -> 44`
  - `object_goal_y_progress: 70 -> 80`

의도:

- 물체를 아주 높게 들기 전에도 바스켓 방향 이동 보상이 0으로 막히지 않게 한다.
- 손 높이 보상이 실제 말단 작동부 높이에서 시작하도록 보정한다.
- 다음 학습에서는 500~1000회 반복 안에 `right_hand_lift_after_grasp`, `right_hand_y_transport_after_grasp`, `object_goal_y_progress`가 0을 벗어나야 한다.

## 6. 중간까지만 이동하고 놓지 않는 v10 문제 수정

`relaxed_transport_v10`을 5000회 반복까지 완료했다.

관찰:

- 운반 자체는 v9보다 크게 개선됐다.
  - `right_hand_y_transport_after_grasp > 4`
  - `carrying_object_high > 13`
  - `object_goal_y_progress > 6`
- 하지만 최종 PAP는 실패했다.
  - `position_error`가 최종 약 `0.28`로 다시 커졌다.
  - `object_goal_bonus_mid = 0`
  - `object_goal_bonus_tight = 0`
  - `gripper_open_near_goal = 0`
  - `object_released_at_goal = 0`
  - 모든 에피소드가 `time_out`으로 끝났다.

판단:

- 이제 병목은 파지·들기·운반 시작이 아니다.
- 정책이 목표점까지 끝까지 들어가지 않고 중간 이동 보상만 받고 멈춘다.
- `object_goal_y_progress`와 같은 부분 진행 보상이 너무 커서, 목표점 영역에 들어가지 않아도 충분한 보상을 얻는다.
- 놓기 보상은 3D 목표 거리가 충분히 작아야 켜져서, 실제 학습 중 거의 전부 0으로 죽었다.

수정:

- 부분 이동 보상을 낮췄다.
  - `right_hand_y_transport_after_grasp: 40 -> 26`
  - `object_goal_xy_progress: 52 -> 24`
  - `object_goal_y_progress: 80 -> 32`
- 목표점까지 끝까지 들어가도록 부족분 벌점을 강화했다.
  - `object_goal_y_shortfall: -28 -> -70`
  - `object_goal_xy_shortfall` 추가, 가중치 `-65`
- 목표점 XY 영역 보상을 새로 추가했다.
  - `object_goal_xy_bonus_wide`
  - `object_goal_xy_bonus_mid`
  - `object_goal_xy_bonus_tight`
- 목표점 근처 보상 기준값을 완화하고 강화했다.
  - `GOAL_BONUS_COARSE_THRESHOLD: 0.30 -> 0.36`
  - `GOAL_BONUS_MID_THRESHOLD: 0.20 -> 0.28`
  - `GOAL_BONUS_TIGHT_THRESHOLD: 0.12 -> 0.20`
  - `object_goal_bonus_mid: 16 -> 44`
  - `object_goal_bonus_tight: 28 -> 70`
- 놓기 보상이 너무 늦게 켜지는 문제를 줄이기 위해 XY 기준 놓기 보상을 추가했다.
  - `gripper_open_near_goal_xy`
  - `gripper_closed_near_goal_xy`
  - `GOAL_RELEASE_XY_THRESHOLD = 0.22`
- 놓기·안착·성공 기준값을 완화했다.
  - `GOAL_RELEASE_THRESHOLD: 0.12 -> 0.22`
  - `GOAL_SETTLE_XY_THRESHOLD: 0.16 -> 0.20`
  - `GOAL_SUCCESS_XY_THRESHOLD: 0.11 -> 0.16`
  - `GOAL_SUCCESS_Z_THRESHOLD: 0.10 -> 0.14`

의도:

- 중간 이동만으로 높은 보상을 받는 구조를 줄인다.
- 목표점 XY 영역 안으로 들어가는 행동을 직접 보상한다.
- 목표점 근처에서 그리퍼를 열어 물체를 놓는 행동이 실제로 학습될 수 있도록 놓기 보상을 0에서 벗어나게 한다.
- 다음 학습에서는 1000~1500회 반복 안에 `object_goal_xy_bonus_mid`, `gripper_open_near_goal_xy`, `object_released_at_goal`을 확인해야 한다.

## 7. 이동 중 조기 놓기와 부족한 운반 수정

`release_basin_v11`의 `model_575.pt`를 GUI로 확인했다.

관찰:

- 큐브를 집기는 하지만 이동이 끝나기 전에 큐브를 떨어뜨린다.
- 팔이 여전히 바스켓 방향으로 충분히 많이 이동하지 못한다.
- 수치상 놓기 보상이 켜졌지만 실제 동작은 목표점 도착 전 조기 놓기에 가깝다.

판단:

- `GOAL_RELEASE_XY_THRESHOLD=0.22`가 너무 넓어서 목표점에 충분히 도달하지 않아도 놓기 보상이 켜졌다.
- `gripper_open_before_final_goal`은 단계별 학습 진행률만 보고 있어서 단계별 학습이 최종 목표에 도달한 뒤에는 목표점 밖에서 열어도 직접 막지 못했다.
- v11에서 부분 이동 보상을 줄인 영향으로 운반 자체도 약해졌다.

수정:

- 놓기 허용 범위를 좁혔다.
  - `GOAL_RELEASE_THRESHOLD: 0.22 -> 0.16`
  - `GOAL_RELEASE_XY_THRESHOLD: 0.22 -> 0.14`
- 목표점 밖에서 열면 직접 벌점이 생기도록 추가했다.
  - `gripper_open_far_from_goal_xy`
  - 가중치 `-120`
- 목표점 밖에서는 그리퍼를 닫고 운반하도록 보상했다.
  - `gripper_closed_far_from_goal_xy`
  - 가중치 `38`
- 운반 보상을 다시 강화했다.
  - `right_hand_y_transport_after_grasp: 26 -> 42`
  - `carrying_object_high: 36 -> 48`
  - `object_goal_xy_progress: 24 -> 34`
  - `object_goal_y_tracking_broad: 28 -> 38`
  - `object_goal_y_progress: 32 -> 58`
- 과도한 부족분 벌점은 조금 낮춰 회피 행동을 줄였다.
  - `object_goal_xy_shortfall: -65 -> -42`
  - `object_goal_y_shortfall: -70 -> -46`

의도:

- 바스켓 XY 범위에 충분히 들어가기 전까지는 그리퍼를 열지 않게 한다.
- 목표점 밖에서는 큐브를 잡고 버티는 행동이 더 유리하게 만든다.
- 동시에 바스켓 방향 운반을 다시 강화해 “조금만 이동하고 멈추는” 문제를 줄인다.

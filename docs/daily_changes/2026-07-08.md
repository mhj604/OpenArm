## 22. PAP 성공 종료와 놓기 정책 수정

GUI 검증용 목표 표시 문제를 해결한 뒤, 기존 학습을 그대로 이어갈 수 없는 이유를 다시 확인했다.

문제:

- 학습용 작업에는 성공 종료 조건이 없었다.
  - `object_reached_goal = None`
- 그래서 정책이 큐브를 목표 근처까지 가져가도 에피소드가 끝나지 않고 계속 행동했다.
- 이 때문에 목표 근처에 도달한 뒤 팔이 풀리거나, 오른쪽으로 처지거나, 큐브를 다시 떨어뜨리는 행동이 학습에 섞였다.
- 놓기 보상도 단계별 학습 중간 목표에서 켜질 수 있어, 최종 바스켓이 아니라 이동 경로 중간에서 그리퍼를 여는 지름길을 만들 수 있었다.
- `object_goal_xy_stable_after_release`는 XY 안정만 봤기 때문에 바스켓 안착의 3D 위치를 충분히 강제하지 못했다.
- 기존 단계별 학습은 최종 바스켓 목표에 너무 늦게 도달해, 5000회 반복 중 최종 목표에서 안정적으로 연습할 시간이 부족했다.

수정:

- 단계별 학습을 더 빨리 최종 목표에 도달하도록 조정했다.
  - `curriculum_num_steps: 120000 -> 45000`
  - `curriculum_power: 1.5 -> 1.2`
- 놓기 보상은 거의 최종 목표 단계에서만 켜지도록 조건을 추가했다.
  - `GOAL_RELEASE_MIN_PROGRESS=0.95`
  - `gripper_open_near_goal`
  - `gripper_closed_near_goal`
- 최종 목표 전에 물체를 든 상태에서 그리퍼를 여는 행동을 벌점으로 추가했다.
  - `gripper_open_before_final_goal`
  - 가중치: `-12.0`
- 놓기 후 안착 보상을 XY 기준에서 3D 기준으로 바꿨다.
  - `object_goal_settled_after_release`
  - `xy_threshold=0.16`
  - `z_threshold=0.10`
  - `velocity_std=0.05`
  - 가중치: `44.0`
- 성공 종료 조건을 추가했다.
  - `object_released_at_goal`
  - `xy_threshold=0.11`
  - `z_threshold=0.10`
  - `max_speed=0.12`
  - `min_progress=0.98`
  - 그리퍼가 열린 상태에서만 성공 처리

의도:

- 중간 목표에서 그리퍼를 열고 떨어뜨리는 지름길을 막는다.
- 최종 바스켓 목표에서 충분히 오래 학습하게 한다.
- 목표 근처에 도달한 뒤 계속 행동하다가 망가지는 문제를 성공 종료로 끊는다.
- PAP의 완료 기준을 “근처까지 운반”이 아니라 “바스켓 목표에 놓은 뒤 안정적으로 안착”으로 바꾼다.

## 25. `lifted_transport_v4` 중단 원인과 PPO 안정화

`lifted_transport_v4` 학습이 약 400회 반복 구간에서 다음 오류로 중단됐다.

- `RuntimeError: normal expects all elements of std >= 0.0`

로그 확인:

- `Episode_Reward/action_rate`가 383번째 스텝에서 `-7.6e12`로 비정상적으로 튀었다.
- `Train/mean_reward`도 같은 구간에서 `-2.9e13`으로 튀었다.
- 이후 `Loss/value_function`이 `1e21 -> inf`로 폭발했다.
- `Policy/mean_noise_std` 자체는 직전까지 약 `0.244`로 정상 범위였다.

판단:

- 직접 원인은 정책 표준편차가 처음부터 음수였던 것이 아니라, 가치망·가치 함수 폭발 이후 정책 매개변수가 NaN 또는 비정상 상태로 무너진 것이다.
- 기존 RSL-RL 실행기에 `clip_actions`가 없어 원시 동작 이상치가 동작 관리자로 들어갈 수 있었다.
- `action_rate_l2`는 원시 동작 차이를 제곱하므로 이상치 하나가 수조 단위 벌점을 만들 수 있었다.
- 적응형 학습률도 `8e-6`에서 순간적으로 `0.004` 수준까지 증가했다. 접촉이 많은 PAP 작업에서는 이 설정이 너무 공격적이었다.

수정:

- RSL-RL 실행기에 동작 제한을 추가했다.
  - `clip_actions = 1.0`
- 동작 변화율 보상을 이상치에 안전한 함수로 교체했다.
  - `action_rate_l2 -> action_rate_l2_clamped`
  - `max_rate=2.0`
- PPO 갱신을 더 보수적으로 조정했다.
  - `value_loss_coef: 0.5 -> 0.25`
  - `learning_rate: 8.0e-6 -> 5.0e-6`
  - `schedule: adaptive -> fixed`
  - `max_grad_norm: 0.5 -> 0.25`

의도:

- 원시 동작 이상치 하나가 가치 함수를 폭발시키는 경로를 차단한다.
- 적응형 LR이 접촉 과정의 이상치 구간에서 학습률을 과하게 키우는 문제를 막는다.
- 목표 높이 수정 자체는 유지하면서 학습이 5000회 반복까지 끊기지 않도록 안정화한다.

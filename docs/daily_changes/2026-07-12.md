# 2026-07-12 OpenArm 변경 기록

## v28 정책망 평균 동작의 파지 격차 수정

v27은 5000회 반복을 마쳤고 확률적 TensorBoard 지표에서는 파지 약 `97%`, 성공 최고
약 `83%`가 나왔다. 그러나 `model_3650.pt`를 같은 Stage-Play 조건에서 128개 환경의 정책망
평균 동작으로 평가해 환경마다 첫 완전 에피소드만 세면 다음과 같았다.

```text
grasp ready       109/128 = 85.16%
candidate         105/128 = 82.03%
verified grasp    104/128 = 81.25%
lift/transport    100/128 = 78.13%
success latch       91/128 = 71.09%
failed latch         7/128 =  5.47%
timeout latch       31/128 = 24.22%
```

위 항목은 단계별·종료 사건의 고정 상태이므로 상호 배타적인 결과표가 아니다. 같은 마지막 제어
주기에 실패와 시간 초과 조건이 함께 참일 수 있어 합계가 128을 넘기도 한다.

TensorBoard 파지는 거짓 물체 이동이 아니었다. 엄격 추적기가 큐브·TCP 동반 상승과 결합, 실제
운반을 검증했으므로 표본 학습 전개에서는 실제로 성공했다. 문제는 학습 정책망이 평균 `.1429`의
Gaussian 표준편차를 유지해 관절 목표에 축마다 약 `.065-.074rad`의 무작위 보정을 받았지만,
GUI는 잡음 없는 정책망 평균 동작을 사용했다는 데 있다. TensorBoard 에피소드 값은 서로 다른
시점에 끝난 초기화 묶음을 평균하므로 빠른 에피소드와 느린 시간 초과를 같은 배포 성공률로
해석할 수 없다.

단계별 손실은 준비 이전 `19/128`, 준비 이후 검증된 파지까지 `5/128`이었다. 양쪽 접촉, 결합,
유지 조건을 느슨하게 만들지 않고 정책망 평균 동작이 정렬 중심에 안정적으로 들어가도록 수정한다.

### 장면과 초기 자세

- 로봇 기준 오른쪽은 `-Y`다. 큐브 기준 Y를 `-.10 -> -.15m`로 이동했다.
- 기존 무작위 배치의 최악 조건에서 큐브 면과 바스켓 외벽 사이 여유는 약 `9.6mm`였다. 변경 후 약
  `59.6mm`가 되어 손가락 접근 공간을 확보한다.
- 큐브만 옮기면 기존 TCP 로컬 정렬 조건을 벗어나므로 준비 관절 7개를 함께 보정했다.
  새 FK/IK 해는 TCP 위치만 세계 좌표 `-Y 50mm` 이동하고 기존 TCP 자세와 큐브 로컬 파지
  오프셋을 보존한다. 모든 관절은 제한 안에 있다.
- 물체 초기화 무작위화 `x/y +/-15mm`, 요각 `+/-0.35rad`는 그대로 유지한다.

### 보상, 관측, PPO

- 에피소드의 새 정렬 최고점에만 총 `+30`을 지급하던 `approach_progress`를 제거했다.
- 정책망이 팔을 소유하고 파지를 시도하기 전까지 현재 `grasp_alignment_quality * 5`와 정규화한
  연속 정렬 체류 `* 1`을 매초 보상한다. 최대 `+6/s`는 기존 파지 전 지연 `-7.5/s`와 경과 시간
  `-0.5/s`보다 작아 중심에서 정지해도 계속 손해다. 3단계 닫기를 빨리 끝내야 유리하다.
- 표본 원시 행동이 들어가고 닫기·재시도·보조 제어 때 실제 적용 목표와도 달랐던 `last_action`
  8차원을 제거했다. 이에 따라 부분 관측 항목이 된 작은 행동 변화율 벌점도 Stage 보상에서
  제거했다. 관절 속도 벌점과 보조 제어·인계의 관절 이동량 제한은 유지한다.
  관측·행동·보상 계약은 `75/8/20`이다.
- Stage PPO의 학습 가능한 `init_noise_std .15 -> .05`, `entropy_coef 1e-4 -> 0`으로 변경했다.
  `.05`는 고정값이 아니므로 학습 중 학습된 표준편차와 표본·평균 차이를 계속 기록한다. v26의
  `.05` 붕괴 원인이었던 재시도 벌점, 최대 시도 실패, 음수 접근 누적 제한은 v27에서 이미
  제거했으며 v28은 절대 중심 정렬 보상으로 탐색 신호를 보완한다.
- 3단계 정렬 체류, 멈춘 양쪽 손가락 접촉, 실제 물체·TCP `12/10mm` 동반 상승, `12mm` 결합
  오차, 정책망이 맡는 들어 올리기, 유지·운반·PlaceAssist·놓기·성공 조건은 유지한다.

### 검증

- `compileall`, AST 구문 분석, `git diff --check`를 통과했다.
- 8개 환경, 1회 반복의 헤드리스 실행 간단 검증에서 관측 `75`, 행동 `8`, 보상 `20`, 초기
  Gaussian 행동 표준편차 `.05`를 확인했고 관리자·물리 과정도 정상 종료됐다. 간단 검증 로그는 제거했다.
- 체크포인트 채택에는 TensorBoard 표본 비율을 사용하지 않는다. 128개 환경의 정책망 평균 동작에서
  환경마다 첫 완전 에피소드만 세고 `lift_completed`, `validated_transport`, 성공, 최악의 초기화
  자세를 평가한 뒤 1개 환경의 GUI를 확인한다. v28의 개선 여부는 아직 학습 전이라 미확정이다.

최종 체크포인트 채택 조건:

```text
actor-mean, observation corruption off, first complete episode only
seeds 42/43/44/45 x 128 env = 512 episodes
overall lift_completed and validated_transport >= 90%, success >= 80%, timeout <= 15%
each seed lift/transport >= 85%
fixed reset-Y bins [-.165,-.1575), [-.1575,-.150), [-.150,-.1425), [-.1425,-.135]m
각 fixed Y bin n >= 100, lift/transport >= 85%
Stage-Play `--seed=42` 연속 10 episode에서 실제 cube lift/transport >= 9/10, empty transport = 0
learned action std와 동일 조건 sampled/mean 격차도 함께 보고; TensorBoard 값으로 대체 금지
```

신규 학습은 반드시 처음부터 한 줄로 실행한다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_clearance_mean_grasp_v28
```

`--resume`, `--load_run`, `--checkpoint`, 부트스트랩은 추가하지 않는다.

## v29 파지 정렬과 운반 전환 최적화

v28 `2026-07-12_03-16-50/model_4999.pt`는 128개 환경의 정책망 평균 동작으로 첫 에피소드를
평가했을 때 실제 들어 올리기·운반이 `85/128 = 66.41%`, 성공이 `77/128 = 60.16%`였고 GUI에서도
실제 집기·놓기에 성공했다. 집은 뒤 성공은 `77/85 = 90.59%`였으므로 운반과 놓기 구조를 바꾸지 않고 파지
확률과 동작 품질만 최적화한다.

### 확인된 원인

- 마지막 25회 반복에서 시도 중단은 에피소드당 약 `.951`이었으며 `.928`이 빈손 닫기
  시간 초과였다. 정렬·결합·검증 중단은 각각 약 `.0047/.0177/.0002`여서 물리
  검증 문턱이 주된 병목은 아니었다.
- v28의 절대 중심 정렬 보상은 XYZ `40/25/40mm`, 손가락 대칭 `12mm` Gaussian과 근접도 하한
  `0.5`를 사용해 실제 닫기 조건보다 넓었다. 상대 속도도 품질 전체에 곱해져 빠른 중심 교정보다
  조건 경계에서 느리게 미세 조정하는 동작이 더 높은 즉시 보상을 받기 쉬웠다.
- 파지 검증 종료 뒤 `.03rad/control` 목표 제한은 12단계, 즉 30Hz에서 `.4s` 뒤 끝났다. 이후
  원시 절대 정책망 목표가 고강성 PD 팔에 직접 적용돼 운반 중간의 급가속을 만들 수 있었다.
- 보조 제어 진입도 원시 정책망 목표를 최대 `.12rad` 선행량으로 즉시 인계했다. v28의 보조 제어
  목표 선행량은 약 `.040rad`, 최대 힘 비율은 약 `1.12`였다. 전환 충격은 없애되 부하 지지에
  필요한 정상 상태 `.12rad` 제어 권한은 유지한다.

### 수정

- 파지 전 보상의 XYZ를 실제 비대칭 강제 조건 폭, 대칭을 실제 `7mm` 문턱으로 정규화했다.
  근접도 하한과 상대 속도 곱을 제거했다. 속도와 열림 조건은 기존 3단계 강제 조건이 계속
  검사하며, 재시도 대기 중에는 시작할 수 없는 중심 정렬 보상도 지급하지 않는다.
- 파지 뒤 정책망이 팔을 소유하는 전체 운반 구간에 기존 `.03rad/control` 목표 선행량 제한을
  계속 적용한다. 유한한 인계가 끝난 뒤 원시 목표로 뛰는 경로만 제거하며 정책망 보상의 귀속은
  바꾸지 않는다.
- 새 보조 제어 목표는 현재 측정한 관절 자세에서 시작한다. DLS가 기존 `.03rad/control`로 선행량을
  누적해 정상 상태 한도 `.12rad`까지 올라가므로 전환은 연속적이고 기존 구동력은 보존된다.
- 놓기 고정 상태에서는 보조 제어 활성 여부와 관계없이 현재 관절 자세로 12단계 인계 유지를
  시작한다. 그리퍼가 먼저 열려 유지가 끊기는 정상 경로에서도 원시 정책망 목표가 다시 적용되지
  않아 큐브 안착 중 재접촉을 막는다.
- 최종 목표·놓기 높이를 세계 좌표 `.680 -> .675m`로 5mm 낮췄다. 상단 놓기 교육 과정 `.73m`,
  운반 `.75m`, 안착 `.65m`는 유지한다. `.675m`에서 큐브 밑면은 바스켓 가장자리 위 약
  `1.46mm`이고, 1cm 낮춘 `.670m`는 가장자리 아래 약 `3.54mm`라 적용하지 않았다.
- 관측·행동·보상과 엄격한 파지 계약은 `75/8/20` 그대로다. 양쪽 접촉, 물체·TCP `12/10mm`
  동반 상승과 결합·유지·운반 판정은 바꾸지 않았다. 놓기 조건의 논리와 허용 오차, 성공 안착
  판정도 유지하고 놓기 중심만 5mm 내렸다.

신규 학습은 이전 지시대로 체크포인트를 이식하지 않고 처음부터 실행한다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_precise_smooth_place_v29
```

판단은 TensorBoard 표본 성공률이 아니라 정책망 평균 동작으로 한다. `model_250`에서 준비·후보와
닫기 시간 초과 추이를 보고, `model_500`에서 128개 환경의 실제 들어 올리기·운반과 GUI 운반
가속을 비교한다. 최종 기준은 v28과 같으며 4개 시드와 시드당 128개 환경에서 들어 올리기·운반
`>=90%`, 성공 `>=80%`, 시간 초과 `<=15%`, GUI 에피소드 10회에서 실제 들어 올리기·운반
`>=9/10`이다.

정적 검사와 8개 환경·1회 반복의 헤드리스 간단 검증을 통과했다. 수정된 Stage-Play에서 v28
`model_4999.pt`를 정책망 평균 동작으로 한 에피소드 호환 평가한 결과 파지·들기·운반·보조 제어·
놓기·성공을 모두 완료했다. 보조 제어 전 목표 선행량의 최댓값은 정확히 `.030rad`, 첫 보조 제어
선행량은 `.0146rad`, 놓기 직후 인계 계수기는 `11`이었다. 설정 프레임을 포함한 12제어 주기
유지가 10단계 안착을 덮으며 실제 놓기 목표도 `.675m`로 확인됐다.

## v30 안정 파지 체류와 최종 높이 미세 조정

v29 신규 실행 `2026-07-12_15-37-08`은 2110번째 반복에서 최근 50회 표본 평균이 파지
`91.78%`, 놓기 `78.97%`, 성공 `77.23%`로 가장 높았다. `model_2100.pt`의 정책망 평균 동작을
GUI로 확인한 결과 파지 이후 운반, 감속, 하강, 놓기가 정상적으로 동작했지만 파지 확률과 최종 높이에
추가 최적화가 필요했다.

### 확인된 병목

- 모델 2100 주변의 표본 학습 전개는 준비 `94.97%`, 후보 `93.94%`, 검증된 파지 `92.03%`였다.
  에피소드당 중단 `.391` 중 `.367`이 빈손 닫기 시간 초과였고 정렬·결합·검증 중단은 각각
  `.0045/.0202/~0`이었다. 엄격한 물리 검증을 완화할 근거는 없다.
- 3제어 주기 정렬은 조건 가장자리를 순간적으로 통과한 자세에서도 닫기를 시작할 수 있었다.
  반면 준비와 실제 양쪽 접촉의 일회성 보상은 각각 `5/10`이라 안정적인 닫기 진입을 직접 강화하는
  신호가 상대적으로 작았다.
- 바스켓 가장자리 상단은 세계 좌표 `.649539394m`, 0.8배 큐브의 반높이는 `.024m`다. v29 목표
  `.675m`에서 큐브 밑면 여유는 `1.460606mm`였다.

### 수정

- 닫기 전 정렬 체류를 `3 -> 4 control`로 늘렸다. 30Hz에서 총 `133ms`이며 가장자리 통과 중
  닫히는 현상을 줄이지만 정렬 목표·경계와 근접도 문턱은 바꾸지 않는다.
- 연속 체류 보상을 `1 -> 1.5`, 일회성 파지 준비를 `5 -> 8`, 실제 접촉 후보를 `10 -> 15`로
  높였다. 최대 지속 보상은 `6.5/s`로 파지 전 지연과 경과 시간의 합계 `-8/s`보다 작아 중심에서
  정지해도 여전히 `-1.5/s` 손해다. 준비·후보는 에피소드 고정 상태라 재시도로 반복
  획득할 수 없다.
- 검증된 파지 `+50`은 취득 전후 시간 초과 비용 차이와 맞으므로 유지한다. 멈춘 양쪽 손가락
  접촉, 물체·TCP `12/10mm` 동반 상승, `12mm` 결합, 유지·운반 판정도 그대로다.
- 최종 명령·놓기를 세계 좌표 `.675 -> .674m`, 로봇 루트 `.325 -> .324m`로 1mm 낮췄다.
  큐브 밑면은 가장자리 위 `0.460606mm`를 유지한다. `.673m`부터는 기준 밑면이 가장자리 아래로
  들어가므로 손가락-벽 충돌 검증 없이 더 낮추지 않는다.
- v29의 전체 파지 후 변화율 제한, 측정 자세 기반 보조 제어 인계, 놓기 유지, DLS 이득과 속도
  제한, 놓기·성공 허용 오차는 그대로다. 상단 놓기 `.73m`, 운반 `.75m`, 안착 `.65m`, PPO와
  관측·행동·보상 계약 `75/8/20`도 바꾸지 않는다.

신규 학습은 v29 체크포인트를 이식하지 않고 처음부터 실행한다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_stable_grasp_lower_place_v30
```

`model_250`에서 준비·후보·획득과 닫기 시간 초과 추이를 확인한다. 실제 운반이 형성된
`model_1500~2100`에서는 v29 `model_2100.pt`와 같은 방식으로 정책망 평균 동작의 첫 에피소드와
GUI 10회를 비교한다. 최종 채택에는 표본 성공률을 사용하지 않고 정책망 평균 동작의 들어 올리기·
운반 `>=90%`, 성공 `>=80%`, 시간 초과 `<=15%`, GUI 실제 들어 올리기·운반 `>=9/10` 기준을
그대로 적용한다.

`compileall`, AST 보상·설정 계약 검사, `git diff --check`를 통과했다. 사용자가 실행하기 전에는
SimulationApp이 필요한 실행 간단 검증이나 새 학습을 대신 수행하지 않았다.

### v30 학습 결과와 최고점 보존

신규 실행 `2026-07-12_22-06-37`은 1781번째 반복 종료 시점의 최근 50단계 표본 평균에서 파지
`74.13%`, 놓기 `51.25%`, 성공 `49.51%`, 시간 초과 `49.81%`로 가장 높았다. 이후 파지가 빠르게

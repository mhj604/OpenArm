# 2026-07-13 OpenArm 변경 기록

## v31 파지 회귀 복구와 정밀 배치 안정화

### 이전 성공 정책과 v30 비교

- v18 `model_825.pt`는 표본 50회 구간에서 파지율 `97.92%`, 들기율 `97.33%`였지만 부트스트랩
  정책이며 후보·접촉·결합 검증이 현재보다 약하다. 강한 파지 동작의 참고값으로만 사용하고 현재의
  엄격한 물리 계약을 v18 수준으로 되돌리지는 않는다.
- v28 `model_4999.pt`와 v29 `model_2100.pt`는 모두 엄격한 양쪽 접촉, 물체/TCP `12/10mm`
  동반 상승, `12mm` 결합, 3개 제어 주기 정렬을 사용한 사용자 승인 기준이다.
- v29의 최근 50회 최고점은 반복 2110에서 파지율 `91.78%`, 성공률 `77.23%`, 시간 초과율
  `21.43%`였다. 사용자 GUI에서도 운반·감속·하강·놓기를 확인했다.
- v30은 PPO가 v29와 같았지만 정렬을 `3 -> 4 control`, 연속 유지 계수를 `1 -> 1.5`로 바꿨다.
  최고점인 반복 1781의 파지율과 성공률은 `74.13/49.51%`였고, 반복 1950부터 모든 작업 단계가
  `0%`, 시간 초과율이 `100%`가 됐다. 최고점 이후 정책망 변화가 `1.83%`에 불과했으므로 작은
  정책 이동에도 취약해진 4개 제어 주기 조건과 강화된 유지 계수의 조합이 가장 큰 회귀 원인이다.

### 파지와 학습 안정성

- `alignment_confirm_steps: 4 -> 3`, `dwell_scale: 1.5 -> 1.0`으로 v28/v29의 검증값을
  복원했다.
- 에피소드에서 한 번만 지급하는 준비 보상 `+8`과 실제 양쪽 접촉 후보 보상 `+15`는 유지한다.
  지속적인 중앙 정렬 보상의 최댓값 `6/s`는 파지 전 지연과 경과 시간 비용의 합계 `-8/s`보다 작아,
  정지한 채 보상만 받는 정책은 계속 손해다.
- 오프셋·근접도·대칭·정지한 손가락 조건, 닫힘 10개 제어 주기, 접촉 3개 제어 주기, 물체/TCP
  동반 상승, 결합, 검증된 파지 5개 제어 주기, 재시도와 유지 조건은 바꾸지 않았다.
- Stage PPO의 고정 학습률만 `5e-6 -> 2.5e-6`로 낮췄다. v29 `model_2100 -> 3625`의 정책망
  변화량이 `9.62%`였고 성공률도 최고 `77.23% -> 약 66%`로 떨어졌기 때문이다. 에포크,
  미니배치, 클리핑, 최대 기울기, 엔트로피와 25회 반복 저장 간격은 유지한다.
- 설치된 rsl_rl의 적응형 스케줄은 최소 학습률이 `1e-5`여서 현재보다 오히려 높아진다. 이 때문에
  적응형으로 바꾸지 않는다. 고정 스케줄에서는 `desired_kl`이 동작하지 않는다.

### 운반과 최종 배치

- 마지막 XY 약 2cm에서 PlaceAssist 명령이 너무 일찍 줄어든 원인은
  `step=0.12*distance-damping`을 사용하는 비례 제어였다. `horizontal_position_gain: .12 -> .16`으로
  올리고 XY/Z 공통 데드밴드를 `3 -> 2mm`로 줄였다. 제어 주기당 최대 이동 `.0025m/control`, 감쇠
  `.25`, 목표 선행값 `.012m`, 관절 이동 `.03rad`는 유지해 먼 구간의 최고 속도와 v29의 가속 제한은
  바뀌지 않는다.
- 낮은 목표를 월드 좌표 `.674 -> .670m`, 로봇 루트 좌표 `.324 -> .320m`로 낮췄다. 바스켓 테두리
  상단 `.649539394m`와 큐브 반높이 `.024m`를 기준으로 큐브 바닥이 테두리 안쪽 `3.539mm`에 있다.
- 기존 `release_height_tolerance=.040m`는 목표보다 최대 40mm 위에서도 자동 열림을 허용했다. 이를
  목표 위 `2mm`, 아래 `3mm`의 비대칭 조건으로 교체하고 놓기 속도를 `.12 -> .06m/s`, XY/Z 공통
  제어 데드밴드를 `3 -> 2mm`로 낮췄다. 5개 제어 주기 확인은 유지한다. 가장 높은 `.672m` 허가
  상태에서도 큐브 바닥이 테두리 안쪽 `1.539mm`에 있으므로 목표 위 공중 열림 요청을 구조적으로
  차단한다. 실제 70% 손가락 열림 높이는 새 고정 지표로 따로 확인한다.
- v29에서 검증한 Z 이득·감쇠 `.12/.30`, 제어 주기당 최대 하강 `3mm/control`, 보조 제어 진입·인계,
  놓기 후 12개 제어 주기 유지, 높은 목표 `.730m`, 안착 높이 `.650m`는 그대로 뒀다.
- 놓기 명령을 요청한 순간과 실제 손가락이 열린 순간의 높이·오차·속도를 각각 고정하는 TensorBoard
  지표 6개를 추가했다. 놓기가 발생하지 않은 에피소드는 0이므로 조건부 평균은 명령값의 경우
  `task_release_commanded`, 실제 열림값의 경우 `task_released` 비율로 나눠 읽는다.

### 실행과 판단

이전 체크포인트를 이식하지 않고 처음부터 실행한다. CUDA와 5000회 반복은 Stage 설정의 기본값이다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --headless
```

학습률이 절반이므로 v29와 같은 진행은 더 뒤에서 나타날 수 있다. 모델 500에서 준비/후보/파지,
모델 1000에서 파지 유지, 모델 2500에서 들기/운반, 모델 3500~4500에서 놓기/성공을
확인한다. 25회 반복마다 저장하므로 후반에 표본 수치가 하락해도 앞선 최고 체크포인트는 지워지지
않는다. 최종 선택은 표본 최고값이 아니라 시드 4개, 환경 128개의 정책망 평균 동작에서 검증된 파지
`>=95%`, 들기/운반 `>=90%`, 성공 `>=80%`, 시간 초과 `<=15%`를 만족하고 GUI 10회에서 실제
파지·운반이 `>=9/10`인지 확인해 판단한다.

새 학습을 대신 실행하지 않고 `compileall`, AST·설정 계약, 형상과 제어식, `git diff --check`를
검증한다. 실제 손가락과 테두리의 접촉, 정책망 평균 동작은 새 체크포인트를 만든 뒤 GUI에서 최종
확인한다.

### 단조 결합 궤적

- XY `12cm -> 4cm`에서 Z 목표를 `.750m -> release+20mm`, `4cm -> 2mm`에서
  `release+20mm -> release`로 각각 세제곱 smoothstep 보간한다. 두 경계에서 위치와 기울기가
  연속이므로 목표점 위에서 별도 수직 동작으로 바뀌지 않는다.
- 진행률은 보조 제어 진입 뒤 증가만 허용한다. XY가 순간적으로 흔들려도 Z 목표가 다시 높아져 팔이
  위로 튀지 않는다. 동작과 중앙 정렬 판정은 같은 고정 목표를 사용한다.
- 낮은 목표 기준 Z 목표는 XY `12/10/8/6/4/2/0.2cm`에서 각각
  `.750/.741/.720/.699/.690/.679/.670m`다. 4cm 지점에서 큐브 바닥은 테두리보다 `16.46mm`
  높고, 정확한 놓기 높이는 XY 2mm 안에서만 요구한다.
- XY의 제어 주기당 최대 이동이 `.0025m`일 때 궤적 Z 목표의 최대 변화는 `2.812mm`로 기존 하강
  상한 `3mm/control` 이내다. XY/Z 최대 이동, 감쇠, 관절 이동 `.03rad`, DLS, 목표 선행값은
  유지한다. 작은 오차에서 길게 이어지는 비례 제어의 꼬리 구간만 줄이도록 XY/Z 이득을
  `.16/.12 -> .20/.16`으로 올렸다. 최대 이동 상한은 그대로이므로 먼 구간 최고 속도나 급가속
  한계는 커지지 않는다.
- `place_centered`는 XY `4cm`와 XY 속도만 확인한다. 궤적 추적 높이를 중복 조건으로 쓰지 않고,
  정확한 놓기 높이와 전체 속도는 최종 놓기 준비 상태에서 한 번만 검사한다. 중앙 정렬과 놓기
  확인은 각각 `5 -> 3 control`로 줄이되 놓기 높이 위 `2mm`/아래 `3mm`, 속도 `.06m/s`
  조건은 그대로다.
- `task_descent_progress`, `task_descent_target_height` 지표를 추가해 실제 학습에서 결합 궤적
  진입과 마지막 수렴을 나눠 확인할 수 있다. 관측 `75`, 동작 `8`, 보상 `20` 계약은 같다.

## v33 파지 회복과 연속 보조 제어 최적화

### v32에서 확인된 병목

- v32 `2026-07-13_12-22-03/model_2875.pt`는 파지·들기·운반·배치를 수행했지만 보조 제어가
  에피소드당 평균 약 `248 control`, 즉 `8.27s`를 사용했다. 파지보다 목표 근처 제어가 시간 초과의
  주원인이었다.
- 보조 제어에 진입할 때 누적된 정책망 목표를 버리는 것은 안전하지만, 관절 목표까지 현재 자세로
  0으로 초기화해 진입 속도가 끊겼다. 이후 증분식 직교 좌표 이동과 누적 목표 선행값에서 XY/Z 중 작은
  비율을 전체 관절 변화량에 적용했고, 한 축이 멈추면 전체 목표를 현재 자세로 재설정했다.
- 모델 2875의 파지 중단은 대부분 정렬·결합 실패가 아니라 빈손 닫힘이 30개 제어 주기까지 기다린
  경우였다. 엄격한 파지 조건을 완화할 근거는 없다.

### 파지와 보상

- 정렬 3개 제어 주기, 양쪽 정지 접촉 3개 제어 주기, 물체/TCP `12/10mm` 동반 상승, 결합 `12mm`,
  검증된 파지 5개 제어 주기와 유지·미끄러짐 조건은 그대로다.
- 닫힘 10개 제어 주기 이후 양쪽 중 한 손가락이라도 유효 벌림값 `.08` 아래에서 멈춘 상태가 3개
  제어 주기 지속되면 회복할 수 없는 빈손 닫힘으로 판정해 즉시 다시 열고 재시도한다.
- 기존 30개 제어 주기 제한 시점에 이미 유효 접촉 형상에 들어온 경우에만 최대 12개 제어 주기의
  접촉 유예를 허용한다. 그 외에는 기존 제한 시점에서 바로 재시도한다.
- 자동 닫힘·재열기 자세 유지 중에만 파지 전 시간 페널티와 중앙 정렬 형성 보상을 제외한다. 검증과
  범위가 제한된 인계는 정책망 제어 구간이므로 시간 비용과 형성 보상을 유지한다. 실패한 시도에는
  기존 파지 전 보상 항목 안에서 실제 `-1.5`의 작은 일회성 비용만 부과한다.

### 연속 보조 제어와 축별 안전 제한

- 가공하지 않은 정책망 목표는 보조 제어에 넘기지 않는다. 진입 순간 측정한 물체 속도에서 목표 방향
  성분만 기존 최대 이동과 저크를 고려한 정지 한계 안에서 받아, 12개 제어 주기 C2 다섯째 차수
  혼합으로 폐루프 명령에 인계한다. 투영은 목표 오차 전체가 아니라 `오차-deadband`까지만 허용해
  마지막 급정지를 막는다.
- XY/Z 명령은 각각 목표 방향으로 투영한다. 기존의 전체 목표 제동, 증분식 `min(XY,Z)` 배율,
  목표 선행값의 `min(XY,Z,angular)` 배율은 제거했다. 요청된 활성 XY/Z를 1순위 DLS로 풀고 비활성
  병진과 방향은 활성 작업의 영공간에서 2순위로 보정한다. 관절 한계를 적용한 뒤 완전히 안전한 후보
  중 실제 진행률이 가장 높은 것을 고르며, 자세 유지 후보는 그 진행률의 95% 이상일 때만 쓴다.
- XY/Z 최대 이동 `.0025/.0030m`, 관절 이동 `.03rad`, 목표 선행값, 완화된 관절 한계, 방향,
  영공간, 미끄러짐 임계값 `15mm x 3 control`은 유지한다. 최대 속도를 올리는 대신 XY/Z 가속도
  `.60/.45m/s^2`와 저크 `6.0/4.5m/s^3`를 추가했다.
- 누적 목표 선행값은 제어 주기마다 새 후보를 먼저 검사한다. 실패하면 이전 누적 선행값, 검증된
  1개 제어 주기 선행값, 현재 자세 유지 순서로 내려간다. 진입 초깃값을 포함한 움직이는 후보는
  선행값과 완화된 한계를 먼저 적용하고, 이전 목표 대비 `.03rad/control` 제한을 마지막에 적용한다.
  그런 다음 다시 비례 조정하지 않고 병진, 각도 `.03`, 유한값 여부까지 검증한다. 물리적으로 활성 진행과
  비활성 축 누출 1mm를 동시에 만족할 수 없는 자세만 안전 정지하며, 대체 제어 종류와 진행률이 낮은
  제어 주기를 별도로 기록한다.
- 미끄러짐 감시기가 동작하면 즉시 전체 목표와 속도·가속도를 0으로 만들고 3개 제어 주기 정지한 뒤
  12개 제어 주기 혼합으로 다시 출발한다. 하강 진행률이 줄어들지 않는 특성도 유지한다.
- 정확한 놓기 높이가 제어기 데드밴드와 같은 XY `2mm`에서만 열리던 경계를 `5mm`로 분리했다.
  놓기 XY `4cm`, 성공 XY `5cm`, 높이 위 `2mm`/아래 `3mm`, 속도 `.06m/s`, 안착 조건은 바꾸지 않았다.

### 목표 정합과 진단

- Stage 학습의 `.730/.670m = 40/60%` 혼합을 제거하고 학습·실행 모두 실제 목표 `.670m`로
  통일했다. 정규화 범위는 유지해 관측 75, 동작 8과 체크포인트 입력 계약은 같다.
- 첫 시도/재시도 파지, 빈손 닫힘, 접촉 유예와 접근/닫기/재시도/정책망 운반/
  보조 제어에서 중앙 정렬/중앙 정렬에서 놓기/열기/안착의 제어 주기 수를 TensorBoard에 기록한다. 시간
  초과가 발생한 정확한 단계도 원-핫으로 고정한다. 종료 제어 주기에서 파지 횟수와 단계 고정값을
  명령 초기화 전에 직접 복사해 마지막 사건이 로그에서 사라지지 않게 했다.
- 에피소드는 `16s`, PPO, 사건 보너스, 성공·실패 조건과 체크포인트를 25회 반복마다 저장하는 간격을
  유지한다.
  에피소드 연장이나 성공 범위 완화로 시간 초과를 숨기지 않는다.

처음부터 학습하는 명령은 다음 한 줄이다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_continuous_assist_v33
```

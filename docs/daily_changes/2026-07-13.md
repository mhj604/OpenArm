# 2026-07-13 OpenArm 변경 기록

## v31 파지 회귀 복구와 정밀 배치 안정화

### 이전 성공 정책과 v30 비교

- v18 `model_825.pt`는 sampled 50-window 파지 `97.92%`, lift `97.33%`였지만 bootstrap 정책이며
  candidate/contact/coupling 검증이 현재보다 약하다. 강한 파지 동작의 참고값으로만 사용하고 현재
  strict 물리 계약을 v18 수준으로 되돌리지는 않는다.
- v28 `model_4999.pt`와 v29 `model_2100.pt`는 모두 strict bilateral contact, object/TCP
  `12/10mm` 동반 상승, `12mm` coupling 및 3-control alignment를 사용한 사용자 승인 기준이다.
- v29의 rolling-50 최고점은 iteration 2110에서 grasp `91.78%`, success `77.23%`, timeout
  `21.43%`였다. 사용자 GUI에서도 운반, 감속, 하강과 release가 확인됐다.
- v30은 PPO가 v29와 동일했지만 alignment를 `3 -> 4 control`, 지속 dwell을 `1 -> 1.5`로
  바꿨다. 최고점 iteration 1781의 grasp/success가 `74.13/49.51%`였고 iteration 1950부터 모든
  task milestone `0%`, timeout `100%`가 됐다. 최고점 이후 actor 변화가 `1.83%`뿐이었으므로
  작은 정책 이동에도 취약해진 4-control gate와 강화된 dwell 조합이 가장 강한 회귀 원인이다.

### 파지와 학습 안정성

- `alignment_confirm_steps: 4 -> 3`, `dwell_scale: 1.5 -> 1.0`으로 v28/v29의 검증값을
  복원했다.
- episode에서 한 번만 지급되는 ready `+8`, 실제 bilateral contact candidate `+15`는 유지한다.
  persistent centering 최대 `6/s`는 pregrasp delay와 elapsed 합계 `-8/s`보다 작아 정지해서
  보상을 받는 정책은 계속 손해다.
- offset/proximity/symmetry/stopped-finger gate, closing 10 step, contact 3 step, object/TCP
  동반 상승, coupling, verified grasp 5 step, retry와 hold 조건은 변경하지 않았다.
- Stage PPO의 fixed learning rate만 `5e-6 -> 2.5e-6`로 낮췄다. v29 `model_2100 -> 3625`
  actor drift가 `9.62%`였고 성공률도 최고 `77.23% -> 약 66%`로 하락했기 때문이다. epochs,
  minibatches, clip, max-grad, entropy와 25-iteration 저장 간격은 유지한다.
- 설치된 rsl_rl의 adaptive schedule은 최소 learning rate가 `1e-5`여서 현재보다 오히려 높아진다.
  따라서 adaptive로 바꾸지 않는다. fixed schedule에서 `desired_kl`은 동작하지 않는다.

### 운반과 최종 배치

- 마지막 XY 약 2cm에서 PlaceAssist 명령이 너무 일찍 줄던 원인은
  `step=0.12*distance-damping`인 비례 제어였다. `horizontal_position_gain: .12 -> .16`으로
  올리고 XY/Z 공통 deadband를 `3 -> 2mm`로 줄였다. 최대 step `.0025m/control`, damping `.25`,
  target lead `.012m`, 관절 step `.03rad`는 유지해 먼 구간 최고 속도와 v29의 가속 제한은
  변하지 않는다.
- low target을 world `.674 -> .670m`, robot-root `.324 -> .320m`로 낮췄다. basket rim top
  `.649539394m`와 cube half-height `.024m`를 기준으로 cube bottom이 rim 안쪽 `3.539mm`에 있다.
- 기존 `release_height_tolerance=.040m`는 목표보다 최대 40mm 위에서도 자동 open을 허용했다.
  이를 목표 위 `2mm`, 아래 `3mm`의 비대칭 gate로 교체하고 release speed를 `.12 -> .06m/s`,
  XY/Z 공통 제어 deadband를 `3 -> 2mm`로 낮췄다. 5-control 확인은 유지한다. 가장 높은
  `.672m` authorization에서도 cube bottom이 rim 안쪽 `1.539mm`라 목표 위 공중 open 요청을
  구조적으로 차단한다. 실제 70% finger-open 높이는 신규 latch metric으로 별도 확인한다.
- v29에서 검증된 Z gain/damping `.12/.30`, 최대 하강 `3mm/control`, assist entry/handoff,
  release 12-control hold, high target `.730m`와 settle `.650m`는 유지했다.
- release command 요청 순간과 실제 finger-open 순간의 height/error/speed를 각각 latch하는
  TensorBoard metric 6개를 추가했다. 미release episode는 0이므로 조건부 평균은 command 값은
  `task_release_commanded`, 실제 open 값은 `task_released` 비율로 나눠 읽는다.

### 실행과 판단

이전 checkpoint를 이식하지 않고 fresh로 실행한다. CUDA와 5000 iteration은 Stage 설정 기본값이다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --headless
```

학습률이 절반이므로 v29와 같은 진행은 뒤쪽으로 이동할 수 있다. model 500에서 ready/candidate/grasp,
model 1000에서 grasp 유지, model 2500에서 lift/transport, model 3500~4500에서 release/success를 본다.
25 iteration마다 저장되므로 뒤에서 sampled 수치가 하락해도 앞선 최고 checkpoint는 지워지지 않는다.
최종 선택은 sampled 최고값이 아니라 actor-mean 4 seeds x 128 env에서 verified grasp `>=95%`,
lift/transport `>=90%`, success `>=80%`, timeout `<=15%`와 GUI 10회 실제 파지·운반 `>=9/10`으로
판단한다.

새 학습을 대신 실행하지 않고 `compileall`, AST/config 계약, 기하와 제어식, `git diff --check`를
검증한다. 실제 finger-rim 접촉과 actor-mean 동작은 새 checkpoint 생성 후 GUI로 최종 확인한다.

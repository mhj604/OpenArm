# 2026-07-13 OpenArm 변경 기록

## v31 파지 회귀 복구와 정밀 배치 안정화

### 이전 성공 정책과 v30 비교

- v18 `model_825.pt`는 sampled 50-window 파지 `97.92%`, lift `97.33%`였지만 bootstrap 정책이며
  candidate/contact/coupling 검증이 현재보다 약하다. 강한 파지 동작의 참고값으로만 사용하고 현재
  strict 물리 계약을 v18 수준으로 되돌리지는 않는다.
- v28 `model_4999.pt`와 v29 `model_2100.pt`는 모두 strict bilateral contact, object/TCP
  `12/10mm` 동반 상승, `12mm` coupling 및 3-control alignment를 사용한 사용자 승인 기준이다.
- v29의 rolling-50 최고점은 iteration 2110에서 grasp `91.78%`, success `77.23%`, timeout
  `21.43%`였다. 사용자 GUI에서도 운반, 감속, 하강과 release가 확인됐다.
- v30은 PPO가 v29와 동일했지만 alignment를 `3 -> 4 control`, 지속 dwell을 `1 -> 1.5`로
  바꿨다. 최고점 iteration 1781의 grasp/success가 `74.13/49.51%`였고 iteration 1950부터 모든
  task milestone `0%`, timeout `100%`가 됐다. 최고점 이후 actor 변화가 `1.83%`뿐이었으므로
  작은 정책 이동에도 취약해진 4-control gate와 강화된 dwell 조합이 가장 강한 회귀 원인이다.

### 파지와 학습 안정성

- `alignment_confirm_steps: 4 -> 3`, `dwell_scale: 1.5 -> 1.0`으로 v28/v29의 검증값을
  복원했다.
- episode에서 한 번만 지급되는 ready `+8`, 실제 bilateral contact candidate `+15`는 유지한다.
  persistent centering 최대 `6/s`는 pregrasp delay와 elapsed 합계 `-8/s`보다 작아 정지해서
  보상을 받는 정책은 계속 손해다.
- offset/proximity/symmetry/stopped-finger gate, closing 10 step, contact 3 step, object/TCP
  동반 상승, coupling, verified grasp 5 step, retry와 hold 조건은 변경하지 않았다.
- Stage PPO의 fixed learning rate만 `5e-6 -> 2.5e-6`로 낮췄다. v29 `model_2100 -> 3625`
  actor drift가 `9.62%`였고 성공률도 최고 `77.23% -> 약 66%`로 하락했기 때문이다. epochs,
  minibatches, clip, max-grad, entropy와 25-iteration 저장 간격은 유지한다.
- 설치된 rsl_rl의 adaptive schedule은 최소 learning rate가 `1e-5`여서 현재보다 오히려 높아진다.
  따라서 adaptive로 바꾸지 않는다. fixed schedule에서 `desired_kl`은 동작하지 않는다.

### 운반과 최종 배치

- 마지막 XY 약 2cm에서 PlaceAssist 명령이 너무 일찍 줄던 원인은
  `step=0.12*distance-damping`인 비례 제어였다. `horizontal_position_gain: .12 -> .16`으로
  올리고 XY/Z 공통 deadband를 `3 -> 2mm`로 줄였다. 최대 step `.0025m/control`, damping `.25`,
  target lead `.012m`, 관절 step `.03rad`는 유지해 먼 구간 최고 속도와 v29의 가속 제한은
  변하지 않는다.
- low target을 world `.674 -> .670m`, robot-root `.324 -> .320m`로 낮췄다. basket rim top
  `.649539394m`와 cube half-height `.024m`를 기준으로 cube bottom이 rim 안쪽 `3.539mm`에 있다.
- 기존 `release_height_tolerance=.040m`는 목표보다 최대 40mm 위에서도 자동 open을 허용했다.
  이를 목표 위 `2mm`, 아래 `3mm`의 비대칭 gate로 교체하고 release speed를 `.12 -> .06m/s`,
  XY/Z 공통 제어 deadband를 `3 -> 2mm`로 낮췄다. 5-control 확인은 유지한다. 가장 높은
  `.672m` authorization에서도 cube bottom이 rim 안쪽 `1.539mm`라 목표 위 공중 open 요청을
  구조적으로 차단한다. 실제 70% finger-open 높이는 신규 latch metric으로 별도 확인한다.
- v29에서 검증된 Z gain/damping `.12/.30`, 최대 하강 `3mm/control`, assist entry/handoff,
  release 12-control hold, high target `.730m`와 settle `.650m`는 유지했다.
- release command 요청 순간과 실제 finger-open 순간의 height/error/speed를 각각 latch하는
  TensorBoard metric 6개를 추가했다. 미release episode는 0이므로 조건부 평균은 command 값은
  `task_release_commanded`, 실제 open 값은 `task_released` 비율로 나눠 읽는다.

### 실행과 판단

이전 checkpoint를 이식하지 않고 fresh로 실행한다. CUDA와 5000 iteration은 Stage 설정 기본값이다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --headless
```

학습률이 절반이므로 v29와 같은 진행은 뒤쪽으로 이동할 수 있다. model 500에서 ready/candidate/grasp,
model 1000에서 grasp 유지, model 2500에서 lift/transport, model 3500~4500에서 release/success를 본다.
25 iteration마다 저장되므로 뒤에서 sampled 수치가 하락해도 앞선 최고 checkpoint는 지워지지 않는다.
최종 선택은 sampled 최고값이 아니라 actor-mean 4 seeds x 128 env에서 verified grasp `>=95%`,
lift/transport `>=90%`, success `>=80%`, timeout `<=15%`와 GUI 10회 실제 파지·운반 `>=9/10`으로
판단한다.

새 학습을 대신 실행하지 않고 `compileall`, AST/config 계약, 기하와 제어식, `git diff --check`를
검증한다. 실제 finger-rim 접촉과 actor-mean 동작은 새 checkpoint 생성 후 GUI로 최종 확인한다.

## v32 연속 하강과 timeout 보상 책임 교정

### v31 GUI 결과와 직접 원인

- v31 run `2026-07-13_01-57-04`의 `model_2500.pt`를 actor-mean GUI로 확인했다. 파지, 들기와
  목표 위까지의 XY 운반은 좋았지만, 목표 위에서 방향을 맞춘 뒤 수직으로 내려오는 구간이 길었다.
- model 2500 rolling-50은 grasp/lift/transport `94.77/94.36/94.33%`였지만 center
  `80.62%`, release authorization `54.78%`, success `52.46%`, timeout `47.05%`였다.
  즉 파지나 팔 길이가 아니라 center에서 정확한 release 상태로 들어가는 구간이 병목이다.
- 기존 제어기는 XY `4cm`, carry 높이 오차 `25mm`, XY 속도 `.05m/s`를 5 control 확인할
  때까지 높이 `.750m`를 유지한 뒤 Z 목표를 `.670m`로 한 번에 바꿨다. 이 이산 목표가
  `빠른 XY -> 정렬 대기 -> 긴 수직 하강`을 만들었다. v18에서 자연스럽게 보였던 핵심은
  assist 진입 후 XY와 Z를 동시에 보정한 점이므로, 오래된 약한 파지 판정은 복원하지 않는다.

### 단조 결합 궤적

- XY `12cm -> 4cm`에서 Z 목표를 `.750m -> release+20mm`, `4cm -> 2mm`에서
  `release+20mm -> release`로 각각 cubic smoothstep 보간한다. 두 경계에서 위치와 기울기가
  연속이므로 목표점 위에서 별도 수직 동작으로 바뀌지 않는다.
- 진행률은 assist 진입 뒤 증가만 허용한다. XY가 순간적으로 흔들려도 Z 목표가 다시 높아져 팔이
  위로 튀지 않는다. action과 center 판정은 같은 latched target을 사용한다.
- low target 기준 Z 목표는 XY `12/10/8/6/4/2/0.2cm`에서 각각
  `.750/.741/.720/.699/.690/.679/.670m`다. 4cm 지점 큐브 바닥은 rim보다 `16.46mm`
  높고, exact release 높이는 XY 2mm 안에서만 요구한다.
- XY 한 control 최대 이동 `.0025m`일 때 궤적 Z 목표 최대 변화는 `2.812mm`로 기존 하강
  상한 `3mm/control` 이내다. 최대 XY/Z step, damping, 관절 step `.03rad`, DLS와 target lead는
  유지한다. 작은 오차의 긴 비례제어 tail만 줄이도록 XY/Z gain을 `.16/.12 -> .20/.16`으로
  올렸다. 최대 이동 상한은 그대로이므로 먼 구간 최고 속도나 급가속 한계는 커지지 않는다.
- `place_centered`는 XY `4cm`와 XY 속도만 확인한다. 궤적 추적 높이를 중복 gate로 쓰지 않고,
  exact release 높이와 전체 속도는 최종 release-ready에서 한 번만 검사한다. center와 release
  확인은 각각 `5 -> 3 control`로 줄이되 release 높이 위 `2mm`/아래 `3mm`, 속도 `.06m/s`
  조건은 그대로다.
- `task_descent_progress`, `task_descent_target_height` metric을 추가해 실제 학습에서 결합 궤적
  진입과 마지막 수렴을 분리해 확인할 수 있다. 관측 `75`, action `8`, reward `20` 계약은 같다.

### 보상 책임과 실행

- v31은 assist 진입 뒤 deterministic controller가 최종 정렬을 담당하는데도, 이후 timeout이나
  failure를 파지 이후라는 이유로 `2x` 부과했다. strict release에 늦게 진입한 episode의 비용이
  무파지 timeout보다 커져 학습 후반에 파지 회피로 무너질 수 있었다.
- `2x` terminal cost는 `grasp_acquired && !assist_engaged`, 즉 actor가 파지 후 운반을 아직
  책임지는 구간에만 적용한다. assist 이후 실패·timeout은 기본 `1x`이며 성공, release, assist
  event와 모든 dense reward는 유지한다.
- fresh 학습 명령은 반드시 아래 한 줄 그대로 실행한다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --headless --run_name=fresh_coupled_descent_v32
```

model 500에서 verified grasp, model 1000에서 lift/transport를 먼저 확인한다. model 1500부터
500 간격으로 center, release authorization, success와 timeout을 비교하고, sampled 성공률만으로
5000까지 기다리지 않는다. 후보는 actor-mean과 GUI에서 한 번의 결합된 XY-Z 동작, 정확한 낮은
release, timeout 감소를 확인한 뒤 승인한다.

## v33 파지 회복과 연속 assist 최적화

### v32에서 확인된 병목

- v32 `2026-07-13_12-22-03/model_2875.pt`는 파지·들기·운반·배치를 수행했지만 assist가
  episode당 평균 약 `248 control`, 즉 `8.27s`를 사용했다. 파지보다 목표 근처 제어가 timeout의
  주원인이었다.
- assist 진입 시 누적 actor target을 버리는 것은 안전하지만, 관절 목표까지 현재 자세로 0-reset해
  진입 속도가 끊겼다. 이후 incremental Cartesian step과 누적 target lead에서 XY/Z 중 작은 비율을
  전체 관절 delta에 적용했고, 한 축이 멈추면 전체 target을 현재 자세로 재설정했다.
- model 2875의 파지 abort 중 대부분은 정렬·coupling 실패가 아니라 빈손 close가 30 control까지
  기다린 경우였다. 따라서 strict 파지 gate를 완화할 근거는 없다.

### 파지와 보상

- alignment 3 control, bilateral stopped contact 3 control, object/TCP `12/10mm` 동반 상승,
  coupling `12mm`, verified grasp 5 control과 hold/slip 조건은 그대로다.
- closing 10 control 이후 양쪽 중 한 finger라도 유효 aperture `.08` 아래에서 정지한 상태가
  3 control 지속되면 회복 불가능한 빈손 close로 판정해 즉시 reopen/retry한다.
- 기존 30-control deadline에서 유효 접촉 geometry에 이미 들어온 경우에만 최대 12 control의
  contact grace를 허용한다. 그 외에는 기존 deadline에서 바로 retry한다.
- 자동 closing/reopen pose hold 동안에만 pregrasp 시간 페널티와 centering shaping을 제외한다.
  verification과 bounded handoff는 actor 제어이므로 시간 비용과 shaping을 유지한다. 실패 시도에는
  기존 pregrasp reward term 안에서 실제 `-1.5`의 작은 one-shot 비용만 부과한다.

### 연속 assist와 축별 안전 제한

- raw actor target은 assist에 넘기지 않는다. 진입 순간 측정된 물체 속도 중 목표 방향 성분만 기존
  최대 step과 jerk-aware stopping envelope 안에서 받아 12 control C2 quintic blend로 closed-loop
  명령에 인계한다. 투영은 목표 오차 전체가 아니라 `오차-deadband`까지만 허용해 마지막 급정지를 막는다.
- XY/Z 명령은 독립적으로 목표 방향 projection을 거친다. 기존 whole-target braking,
  incremental `min(XY,Z)` scale, target-lead `min(XY,Z,angular)` scale을 제거했다. 요청된 활성 XY/Z를
  1순위 DLS로 풀고 비활성 translation과 orientation은 활성 task의 nullspace에서 2순위로 보정한다.
  joint limit 적용 뒤 hard-safe 후보 중 실제 진행률이 가장 높은 것을 고르며, 자세 유지 후보는 그
  진행률의 95% 이상일 때만 쓴다.
- XY/Z 최고 step `.0025/.0030m`, 관절 step `.03rad`, target lead, soft joint limit, orientation,
  nullspace와 slip threshold `15mm x 3 control`은 유지한다. 최대 속도를 올리는 대신 XY/Z 가속도
  `.60/.45m/s^2`, jerk `6.0/4.5m/s^3`를 추가했다.
- 누적 target lead는 매 control 새 후보를 먼저 검사한다. 실패하면 이전 누적 lead, 검증된 1-step
  lead, current-pose hold 순서로 내려간다. 진입 seed를 포함한 움직이는 후보는 lead/soft limit를 먼저
  적용하고 이전 target 대비 `.03rad/control` 제한을 마지막에 적용한 뒤 재스케일 없이 translation,
  angular `.03`, finite 값까지 검증한다. 물리적으로 활성 진행과 비활성축 누설 1mm를 동시에 만족할
  수 없는 자세만 안전 정지하며 fallback 종류와 low-progress control을 별도 기록한다.
- slip watchdog이 동작하면 즉시 전체 target과 속도/가속도를 0으로 만들고 3 control 정지한 뒤
  12-control blend로 재출발한다. 하강 진행률의 단조성도 유지한다.
- exact release 높이가 controller deadband와 같은 XY `2mm`에서만 열리던 경계를 `5mm`로
  분리했다. release XY `4cm`, success XY `5cm`, 높이 위 `2mm`/아래 `3mm`, 속도 `.06m/s`와
  settle 조건은 변경하지 않았다.

### 목표 정합과 진단

- Stage train의 `.730/.670m = 40/60%` 혼합을 제거하고 train/play 모두 실제 목표 `.670m`로
  통일했다. normalization bounds는 유지해 관측 75, action 8과 checkpoint 입력 계약은 같다.
- first-attempt/retry grasp, empty close, contact grace와 approach/close/retry/actor transport/
  assist-to-center/center-to-release/opening/settle의 control 수를 TensorBoard에 기록한다. timeout이
  발생한 정확한 phase도 one-hot으로 latch한다. terminal control에서 grasp counter와 phase latch를
  command reset 전에 직접 복사해 마지막 event가 로그에서 사라지지 않게 했다.
- episode는 `16s`, PPO, event bonus, success/failure 조건과 25-iteration checkpoint 간격을
  유지한다. episode 연장이나 성공 범위 완화로 timeout을 숨기지 않는다.

fresh 학습 명령은 다음 한 줄이다.

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_continuous_assist_v33
```

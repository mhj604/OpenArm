# 2026-07-14 OpenArm 변경 내역

## V33 진단

완료된 v33 실행은 파지와 운반 성능을 유지했지만 에피소드의 절반가량을 최종 보조 제어에 사용했다.
마지막 50회 이동 평균은 파지 `97.30%`, 운반 `97.24%`, 중앙 정렬 `82.91%`, 놓기 허가 `69.22%`,
성공 `68.98%`, 시간 초과 `31.04%`였다. 남은 시간 초과는 대부분 보조 제어에서 중앙 정렬로 넘어가는
구간이나 중앙 정렬에서 놓기로 넘어가는 구간에서 발생했다.

## V34 제어기 수정

- 순서에 따라 달라지던 목표 제한을 관절·선행값·연속성 조건의 정확한 교집합으로 투영하는 방식으로
  바꿨다.
- 누적식 목표 적분을 현재값 기준 세 제어 주기 선행 예측으로 바꿨다.
- 진입 시 초깃값은 한 번만 적용하고, 유효하지 않은 DLS 상태를 최종 검증까지 보존했다.
- 놓기·성공 게이트는 바꾸지 않고 제어기 데드밴드를 XY `5mm`와 Z `2mm`로 나눴다.
- 요청값과 실현값의 XY/Z 진행률, 축별 진행률, 선행값 재설정·누적량, 관절 한계 근접도를 짝지어
  진단하는 지표를 추가했다. 제한 적용 전 액추에이터 지표의 이름은 `effort_demand_ratio`로 바꿨다.
- v33의 보상, 정책, 목표, PPO, 에피소드, 엄격한 파지 조건, 엄격한 물리적 성공 조건은 유지했다.
- 환경 5120개의 기준 학습 작업에는 ContactSensor와 광범위한 도메인 무작위화를 넣지 않았다.

정적 검증 결과 `28 passed`, Python 컴파일, `git diff --check`를 모두 통과했다. 수정 중에는 Isaac
시뮬레이션이나 GUI를 실행하지 않았다.

처음부터 학습하는 명령:

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_current_relative_assist_v34
```

## V35 최종 보조 제어 수정

- 남은 실패의 원인은 DLS 후보를 전부 허용하거나 전부 거부하던 방식이었다. 보조 제어 증분의
  `79.25%`가 멈추고 선행값 갱신의 `56.44%`가 유지됐다. 반면 허용된 증분은 진행률이 좋았고,
  최종 단계에서 위험한 명령이나 선행값 재설정은 기록되지 않았다.
- 방향을 유지하는 균일 안전 축소를 추가했다. 활성 축은 정확한 상한과 오차 비증가 조건을 적용하고,
  비활성 축의 누출은 `1mm` 이내로 제한한 뒤 기존의 전체 안전 검증을 다시 수행한다.
- 계속 유효하지 않은 후보에만 단계별 XY/Z 축소 DLS 대체 제어를 추가했다. 모든 대체 제어는 관절
  한계와 동일한 직교 좌표계 안전 게이트를 유지한다.
- v34의 XY `5mm` 데드밴드를 유지하고 놓기 목표와 엄격한 파지·놓기·성공 조건을 모두 보존했다.
  변경 범위는 유효하지 않은 후보의 복구로 한정했다.
- 비례 축소 복구, XY/Z 대체 제어, XY/Z 거부, 전체 유지 상태를 각각 확인하는 진단 지표를 추가했다.

검증 결과 `35 passed`, Python 컴파일, `git diff --check`, 100,000행 무작위 안전 검사를 모두
통과했으며 위반은 한 건도 없었다.

처음부터 학습하는 명령:

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=5120 --device=cuda --max_iterations=5000 --headless --run_name=fresh_safe_axis_fallback_v35
```

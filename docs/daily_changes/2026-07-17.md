## V42 실패 원인 확인

- v42는 1105회 기준 파지율이 약 `95.9%`였지만 들기·운반·성공은 모두 0이었고 시간 초과는
  100%였다. 파지 뒤 평균 높이와 수평 이동을 함께 확인해 파지 전 회귀가 아니라 파지 후 상승
  탐색이 사라진 상태로 판정했다.
- v34 체크포인트를 현재 장면에서 물리 A/B로 실행했다. CPU 자체 충돌 켬과 끔 모두 파지·들기·운반
  `5/5`, GPU 자체 충돌 켬도 `1/1`로 성공했다. GPU 실행의 최고 물체 높이는 `.732167m`였다.
  장면, GPU, 자체 충돌과 두 필터는 v42의 0% 들기 원인에서 제외했다.
- v42의 검증 후 보상은 파지 시 0에서 시작한 potential을 미완료 종료 때 다시 0으로 닫아 모든
  부분 상승의 할인 누적 보상을 정확히 상쇄했다. 첫 들기 이전에는 상승 탐색 신호가 없는 구조였다.
- v41의 최초 계기는 유한 horizon 전환과 기존 들기 보상의 취약성이 함께 드러난 결과일 가능성이
  높지만 단독 A/B가 없어 가설로 남겼다. 의미상 올바른 `is_finite_horizon=True`는 유지했다.

## V43 정책 수정

- 웹 ChatGPT Pro에서 원안, 반론, 최종안으로 세 차례 검토했다.
- 물체와 TCP가 함께 오른 실제 거리의 에피소드 최고 증가분만 보상하도록 바꿨다. 환경별 상한은
  `min(max(.730 - 파지 시 물체 높이, 0), .093)`, 가중치는 `150/m`, 최대 보상은 `13.95`다.
- 그립이 유효하지 않을 때 처음 관측된 상승은 최고값에만 반영하고 보상하지 않는다. 그립을 다시
  얻은 뒤 같은 높이에 도달해도 보상을 재획득할 수 없다.
- terminal은 `just_lifted`보다 우선하고 종료 시 음수 clawback은 주지 않는다. 관측 최고 상승과
  보상 누적 상승은 환경 reset 때만 0으로 만든다.
- TensorBoard에 `task_verified_lift_observed_watermark`와
  `task_verified_lift_credited_rise`를 추가했다.
- 파지 후보 경로, 목표점, 물리 조건, PPO, 자체 충돌, 운반·놓기 보조 제어는 변경하지 않았다.
- 현재 실행 중인 v42 학습은 종료하거나 다시 시작하지 않았다.
- 회귀 테스트 `113개`, Python 컴파일과 `git diff --check`를 통과했다.

## V44 정책 수정

- 웹 ChatGPT Pro에서 임계점 불연속과 보상 악용 가능성을 세 차례 검토했다.
- 파지 뒤 보조 제어 전 지연 비용을 모든 구간에서 `-15 -> -1.5/s`로 낮추고, 미완료 시간 초과의
  파지 뒤 배수를 `1 -> 2`로 높였다. 들기나 운반 임계점에서 비용이 바뀌는 규칙은 넣지 않았다.
- 결합 상승량 `r`에 `4*.010*(1-exp(-r/.010))`를 더하는 연속 포화형 초기 상승 보상을 추가했다.
  초기 기울기는 `750/m`, 장거리 기울기는 `150/m`, 추가 보상 상한은 `6`, 전체 검증 상승 보상
  상한은 약 `19.95`다.
- 원시 상승과 포화형 추가 상승은 같은 watermark를 사용한다. 유효하지 않은 그립에서 먼저 오른
  구간은 둘 다 소진되며 회복·반복·종료 스텝에서 재지급되지 않는다.
- `task_verified_lift_bootstrap_credited_rise` 지표를 추가했다. 목표점, 제어기, PPO, 파지 조건,
  자체 충돌, 도메인 무작위화 설정은 바꾸지 않았다.

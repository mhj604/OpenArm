# 2026-07-10 변경 기록

## 1. 이동 중 조기 release 방지 강화

`hold_until_basket_v12`의 `model_625.pt`를 GUI로 확인했다.

관찰:

- 큐브를 집고 들어올린다.
- 이전보다 더 많이 basket 방향으로 이동한다.
- 하지만 basket에 도착하기 전에 그리퍼를 열어 큐브를 떨어뜨린다.
- 실제 동작은 안정적인 place가 아니라, 이동 중 release/drop에 가깝다.

판단:

- `GOAL_RELEASE_XY_THRESHOLD=0.14`도 실제 동작에서는 여전히 넓다.
- `gripper_open_far_from_goal_xy` 벌점이 `MIN_LIFT_HEIGHT_W` 이상에서만 켜져, 낮게 든 상태에서 이동 중 열기를 충분히 막지 못했다.
- release 보상은 너무 일찍 켜지고, 목표점 밖에서 닫고 유지하는 보상은 늦게 켜졌다.

수정:

- release 허용 범위를 더 좁혔다.
  - `GOAL_RELEASE_THRESHOLD: 0.16 -> 0.11`
  - `GOAL_RELEASE_XY_THRESHOLD: 0.14 -> 0.09`
  - `GOAL_XY_BONUS_TIGHT_THRESHOLD: 0.12 -> 0.10`
- 목표점 밖에서 열기 벌점은 더 일찍 켜지도록 했다.
  - `gripper_open_far_from_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> LIFT_PROGRESS_START_HEIGHT_W`
  - weight `-120 -> -220`
- 목표점 밖에서 닫고 운반하는 보상도 더 일찍 켜지도록 했다.
  - `gripper_closed_far_from_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> LIFT_PROGRESS_START_HEIGHT_W`
  - weight `38 -> 72`
- 목표점 안에서 열기 보상은 더 늦게 켜지도록 했다.
  - `gripper_open_near_goal.minimal_height: MIN_LIFT_HEIGHT_W -> CARRY_LIFT_HEIGHT_W`
  - `gripper_open_near_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> CARRY_LIFT_HEIGHT_W`
- basket 방향 이동 보상을 다시 강화했다.
  - `right_hand_y_transport_after_grasp: 42 -> 56`
  - `object_goal_xy_progress: 34 -> 42`
  - `object_goal_y_tracking_broad: 38 -> 46`
  - `object_goal_y_progress: 58 -> 72`
  - `object_goal_y_shortfall: -46 -> -58`

의도:

- basket에 도착하기 전까지는 그리퍼를 열지 않게 한다.
- 물체를 낮게 들고 이동하는 중에도 조기 release 벌점이 작동하게 한다.
- 충분히 높게 들고 basket XY 안에 들어간 뒤에만 release가 유리하도록 만든다.

## 2. 최종 place 목표 높이 낮춤

GUI에서 최종 목표 화살표가 basket보다 지나치게 높게 보이는 문제가 확인됐다.

관찰:

- 기존 목표 높이는 `BASKET_GOAL_POS_B[2] = 0.42`였다.
- 로봇 root 높이 `0.35`를 더하면 월드 기준 목표 높이는 `0.77m`다.
- basket settle 높이 `BASKET_SETTLE_POS_B[2] = 0.30`, 월드 기준 `0.65m`보다 약 `12cm` 높다.
- 이 때문에 정책이 basket에 놓기보다 공중 목표점까지 이동한 뒤 열어 떨어뜨리는 동작을 학습하기 쉽다.

수정:

- 최종 command/화살표 높이를 낮췄다.
  - `BASKET_GOAL_POS_B[2]: 0.42 -> 0.33`
- 월드 기준 최종 목표 높이는 `0.68m`가 된다.
- 이동 중 carry 높이 보상은 유지했다.
  - `CARRY_LIFT_HEIGHT_W = 0.72`

의도:

- 최종 목표는 basket 안/위쪽의 place 지점에 가깝게 둔다.
- 이동 중에는 여전히 높게 들게 하되, 최종 release는 낮은 place 목표에서 일어나도록 분리한다.

## 3. Release 목적함수와 최종 단계 gate 정렬

`lower_goal_v14`를 iteration 2100대까지 확인했다.

관찰:

- grasp 이후 lift와 basket 방향 transport는 계속 개선됐다.
- `object_goal_xy_bonus_tight`, `gripper_open_near_goal_xy`는 계속 0이었다.
- 성공 종료는 약 0.3% 수준이고 episode의 99% 이상이 timeout이었다.
- 목표 밖 open 벌점은 커졌지만 목표 안에서 release하는 양의 신호는 거의 발생하지 않았다.

원인:

- 성공 termination에 별도 보상이 없어, 성공하면 남은 episode의 dense grasp/carry 보상을 잃었다.
- 목표 높이는 world `0.68m`인데 release 보상은 object가 `0.72m`보다 높을 때만 켜져 height tracking과 충돌했다.
- 성공 XY 반경은 `0.16m`, open 허용 반경은 `0.09m`라 성공 가능한 상태 일부를 open 벌점이 막았다.
- `carrying_object_high`와 closed-grasp stable hold가 목표 안에서도 계속 적용돼 내려놓기보다 계속 쥐는 정책을 강화했다.
- 정책 관측에 object velocity가 없어 정지 후 release 조건을 직접 판단할 수 없었다.

확인:

- USD container 내부 반폭은 약 `0.228m x 0.210m`다.
- command randomization `+-0.03m`를 포함해도 `0.16m` release 반경은 cube 중심을 basket 내부에 유지한다.

수정:

- release/settle/success XY 반경을 `0.16m`로 통일했다.
- release readiness에 goal height 오차와 object speed를 함께 사용한다.
- release 최소 높이를 basket rim과 일치하는 world `0.65m`로 낮췄다.
- high-carry reward는 release basin 밖에서만 적용한다.
- closed-grasp stable hold를 gripper 상태와 무관한 `object_goal_release_readiness`로 교체했다.
- 안정된 release basin에서 open 보상을 강화하고 closed penalty를 강화했다.
- 목표 밖 open penalty와 closed hold reward는 낮춰 transport 보상과의 불균형을 줄였다.
- 성공 termination에 `successful_release` terminal reward를 추가했다.
- policy observation에 robot-root frame object linear velocity를 추가했다.
- 장기 pick-and-place credit assignment를 위해 PPO `gamma`를 `0.98 -> 0.995`로 높였다.

주의:

- policy observation이 42차원에서 45차원으로 바뀌므로 이전 checkpoint를 resume할 수 없다.
- 새 run은 checkpoint 없이 처음부터 학습해야 한다.

## 4. 누적 개선 정책 기반 transport fine-tuning

`release_aligned_v15`를 5000 iteration까지 학습하고 `model_900.pt`, `model_2075.pt`를 GUI로 확인했다.

관찰:

- 두 checkpoint 모두 cube를 집는 도중 gripper를 열어 놓쳤다.
- v15 TensorBoard의 release 성공률은 드문 stochastic episode였고 deterministic GUI 정책은 동일하게 실패했다.
- 과거 run을 같은 지표로 비교하면 `relaxed_transport_v10`에서 grasp/lift는 이미 안정적이었다.
  - `gripper_closed_near_object ~= 2.39`
  - `right_hand_lift_after_grasp ~= 13.72`
  - `lifting_object_early ~= 19.58`
  - `carrying_object_high ~= 14.25`
  - `object_goal_y_progress ~= 7.03`
  - 최종 `position_error ~= 0.283m`
- v10의 실패는 grasp/drop이 아니라 basket 방향으로 이동하다 중간에서 멈추는 것이었다.
- v11~v14는 이 기준선 위에 release basin, 조기 open 억제, transport 강화, 낮춘 final goal을 순차적으로 추가했다.
- 따라서 v10은 원인 분석 자료로만 사용하고 초기 정책으로 직접 되돌아가면 안 된다.

판단:

- v15는 object velocity 관측 추가로 policy 입력을 42차원에서 45차원으로 바꿔 누적 개선된 v14 정책을 재사용하지 못했다.
- `gamma=0.995`와 새 release 목적함수로 처음부터 학습하면서 이미 해결했던 grasp를 다시 잃었다.
- 누적 transport progress reward는 중간 지점에 정지해도 계속 양의 보상을 주므로 정지 local optimum을 제거하지 못한다.
- fine-tuning 환경에서 command curriculum을 다시 시작하면 이미 학습된 transport 정책이 가까운 중간 목표로 되돌아간다.
- 기존 open penalty는 object height gate에 의존해, lift가 완성되기 전에 열면 벌점을 회피할 수 있었다.

수정:

- v14 checkpoint 호환성을 복원했다.
  - object velocity observation 제거: 45차원 -> 42차원
  - PPO `gamma: 0.995 -> 0.98`
- `Isaac-PickPlace-OpenArm-TestUSD-Bi-FineTune-v0` task를 추가했다.
  - train randomization은 유지한다.
  - command는 첫 step부터 최종 basket goal을 사용한다.
- `object_goal_xy_potential_progress`를 추가했다.
  - lifted closed grasp가 유지되는 동안 이전 step보다 goal XY 거리가 줄어든 양만 보상한다.
  - 정지하면 0, goal에서 멀어지면 음수다.
  - reset/재grasp 직후의 거리 jump는 보상하지 않는다.
- `gripper_open_after_grasp_outside_goal_xy`를 추가했다.
  - finger 근처에서 closed grasp가 3 control step 유지되면 grasp acquired로 latch한다.
  - 이후 basket XY 밖에서 open하면 object height와 무관하게 벌점 처리한다.
- v14까지 유지됐던 `carrying_object_high`를 goal 거리로 감쇠하지 않도록 원래 lift-progress 형태로 복원했다.
- grasp/lift 관련 기존 reward weight와 action space는 변경하지 않았다.

학습 방식:

- 새 정책을 처음부터 학습하지 않는다.
- v10은 수치와 실패 원인을 참고하지만 checkpoint는 사용하지 않는다.
- v11~v14 개선이 누적되고 grasp 유지가 확인된 `lower_goal_v14/model_2175.pt`에서 resume한다.
- checkpoint iteration이 2175이므로 추가 250/500/1000 iteration은 각각 model 2425/2675/3175 부근에서 판단한다.

검증:

- `lower_goal_v14/model_2175.pt` actor/critic 입력이 42차원임을 확인했다.
- 64 env, 2 iteration resume smoke training을 통과했다.
- 새 FineTune task actor/critic 입력은 42차원이고 v14 optimizer state까지 정상 로드됐다.
- `object_goal_xy_potential_progress`가 실제 rollout에서 양수로 발생했다.
- `gripper_open_after_grasp_outside_goal_xy`도 실제 rollout에서 조기 open 벌점으로 발생했다.
- final-goal curriculum progress는 reset 이후 `1.0`으로 유지됐다.

실행:

```bash

```

판단:

- `model_2275` 부근: grasp/lift가 v14 수준으로 유지되는지 먼저 GUI 확인한다.
- `model_2425` 부근: potential progress와 XY/Y transport가 상승하는지 확인한다.
- `model_2675` 부근: position error가 v14의 약 `0.23m` 아래로 내려가는지 확인한다.
- grasp가 다시 무너지거나 조기 open이 보이면 1000 iteration을 기다리지 않고 중단한다.

## 5. 단계 상태 기반 objective 재설계

v16을 `lower_goal_v14/model_2175.pt`에서 재개해 `model_2900.pt`까지 학습했다. 그러나 `model_2675.pt` 기준 실제 물체 오차인 `object_position_error`가 약 `0.278m`로 v14의 약 `0.247m`보다 나빠졌고, 성공률은 0, timeout은 약 99.86%였다. 기존 방식의 보상 계수 조정만으로는 개선되지 않는 것이 확인돼 v16 학습을 중단했다.

확정한 구조적 원인:

- 과거 v10~v15 run은 모두 새 run으로 시작했다. 코드 변경은 누적됐지만 학습된 정책 자체가 run 사이에서 누적된 것은 아니었다.
- 기존 50개 dense reward에는 grasp/carry 상태를 매 step 유지하면 받는 양의 보상이 많았다. 따라서 basket에 완전히 놓기보다 중간에 멈춰 timeout되는 행동이 안정적인 local optimum이었다.
- reward와 termination이 서로 다른 grasp/release 조건을 사용했고, 성공에는 release dwell과 실제 정착 상태가 필요하지 않았다.
- 기존 drop 높이 `0.45m`는 물체가 시작 탁자 높이 약 `0.625m`로 떨어지는 실패를 검출하지 못했다.
- policy는 보상 계산에 쓰인 grasp latch, release-ready, 물체 속도, episode 진행률을 보지 못해 동일 관측에서 서로 다른 행동을 요구받았다.
- `position_error`는 command body인 손의 오차이며 물체의 실제 목표 오차가 아니다. 비교에 사용해야 할 값은 `object_position_error`다.
- v16의 gated potential은 gate가 켜지고 꺼질 때 telescoping 조건이 깨져 장기 task objective를 안정적으로 표현하지 못했다.

v17 수정:

- `Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0`와 전용 play task를 추가했다.
- grasp 확인, lift 완료, basket XY 진입, release 준비, release, 성공/실패를 한 개의 `TaskStateTracker`가 계산하도록 통합했다.
- 성공은 실제 release 이후 basket 내부에서 높이, 속도, open 상태가 10 control step 연속 안정될 때만 발생한다.
- basket 밖 release, grasp 후 hold 상실, basket 밖으로 벗어난 release, 시작 높이보다 `3cm` 이상 낙하를 즉시 또는 짧은 dwell 후 실패로 종료한다.
- policy observation에 물체 선속도 3개, 단계 상태 6개, episode 진행률 1개를 추가해 총 52차원으로 만들었다.
- gripper action에 `+-0.15` hysteresis를 넣어 exploration noise가 0 근처에서 open/close를 반복하지 않게 했다.
- reward를 50개에서 18개로 줄였다. 정지하면 0인 signed approach/lift/transport/place progress, 한 번만 지급되는 milestone, 성공/실패 outcome과 최소한의 regularization만 남겼다.
- stage event reward는 `dt`를 상쇄해 설정한 `10/15/40/20/5/200/-100`이 실제 episode bonus가 되도록 했다.
- PPO rollout을 48 step, `gamma=0.995`, exploration std를 `0.15`로 설정했다.

정책 이식:

- 과거 checkpoint를 동일 지표로 비교해 grasp/lift/carry가 가장 강했던 `hold_until_basket_v12/model_4999.pt`의 actor를 사용했다.
- 기존 42개 observation의 순서를 보존하고 새 10개 입력 weight만 0으로 확장했다. 나머지 actor layer는 bit 단위로 그대로 복사했다.
- 52차원 critic은 새로 초기화했고 optimizer state도 비웠다. 따라서 이미 학습된 grasp actor는 보존하면서 새 상태와 outcome value만 다시 학습한다.
- 생성 checkpoint: `2026-07-10_14-45-00_v12_actor_stage_v17_bootstrap/model_0.pt`

검증:

- fresh task smoke와 actor-transfer resume smoke를 모두 통과했다.
- observation 52, action 8, termination 4, reward 18개가 실제 manager에서 확인됐다.
- 강제 물리 상태 테스트에서 basket 밖 open은 failure, basket 내부 release 후 10-step 정착은 success로 판정됐다.
- 이식 actor의 초기 rollout은 grasp/lift를 유지하면서 basket XY까지 도달했다.
- 초기 병목은 transport가 아니라 basket 위 약 `0.92m`에서 멈추는 것이었다. release 목표 높이 오차는 약 `0.25m`, XY 오차는 약 `0.11m`였다. 따라서 place potential은 속도를 섞지 않고 목표 높이 `0.68m`까지 내려가는 signed 높이 변화만 보상하도록 정리했다.

실행:

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=1024 --device=cuda --max_iterations=1000 --headless --resume --load_run=2026-07-10_14-45-00_v12_actor_stage_v17_bootstrap --checkpoint=model_0.pt --run_name=stage_aligned_v17
```

판단 시점:

- `model_100`: grasp/lift가 유지되는지와 `task_release_height_error`가 초기 약 `0.25m`에서 분명히 감소하는지 확인한다.
- `model_250`: `task_release_ready`가 0보다 커지고 basket 내부 물체 속도가 감소하는지 확인한다.
- `model_500`: `task_released`, `task_succeeded`가 발생하고 timeout이 감소하는지 확인한다.
- `model_500`에서도 release-ready와 success가 계속 0이면 `model_1000`까지 무작정 기다리지 않고 중단해 rollout을 다시 분석한다.

## 6. v18 hybrid place 정책과 보상/실패 조건 정렬

v17 `model_650.pt`까지 확인한 결과 grasp/lift와 XY transport는 유지됐지만 하강·release는 전혀
발생하지 않았다. 64-env deterministic 측정에서는 초기 goal XY 거리 평균 `0.3136m`에서 최소
`0.0900m`까지 감소했고, `93.75%`가 `0.12m` 안에 진입했다. 따라서 병목은 XY 이동이 아니라
basket 진입 후 약 `0.99m` 높이에서 멈추는 high-carry local optimum이었다.

구조 수정:

- learned actor는 grasp, lift, basket XY 도달, release 요청을 계속 담당한다.
- `basket_reached`는 lift 완료 후 XY `0.12m` 안에 들어왔을 때만 latch한다.
- basket 진입 뒤에는 Cartesian assist target과 policy target을 `0.12~0.20m`에서 연속적으로
  혼합한다. assist는 object XY를 goal 중심으로 보정하면서 episode별 release 높이로 내린다.
- Cartesian step은 XY `0.0010m`, Z `0.0015m`, joint target step은 `0.03rad`로 제한했다.
- train release 높이는 `0.95/0.86/0.77/0.68m`, 확률은 `0.20/0.20/0.20/0.40`이다. 고정
  `(0.68, 0.95)` bounds로 정규화해 Play의 단일 `0.68m` 목표도 Train과 동일하게 관측된다.

release 상태기계:

- authorization은 현재 XY, 높이 오차, 속도 조건이 5 step 연속 맞을 때 latch한다.
- 실제 release는 actor action이 `+0.15` 이상일 때만 `release_commanded`로 latch한다. 기존
  `-0.75` threshold처럼 authorization 직후 사실상 자동으로 열리는 경로는 제거했다.
- opening transition은 10 step까지 hold-loss를 유예하며, 추가 3 step 안에도 물리 open이
  완료되지 않으면 실패한다.
- basket 진입 후 `0.20m` 밖 이탈 6 step, release 후 `0.16m` 밖 이탈 6 step, 일반 hold-loss
  3 step을 각각 독립적으로 실패 처리한다.
- 성공은 actor-requested release 뒤 XY `0.16m`, settle 높이 `0.65+-0.045m`, 속도 `0.08m/s`
  이하가 10 step 유지될 때만 확정한다.

최종 Stage reward 15개:

- signed potential: approach `5`, lift `150`, transport `150`. 정지 시 0이고 후퇴 시 음수다.
- one-shot event: grasp `10`, lift `15`, basket `40`, physical release `25`, success `200`,
  failure `-100`, incomplete timeout `-50`.
- penalty: elapsed `-0.5/s`, direct gripper action phase `-4`, actor-control 비율로 제한한
  action-rate `-1e-4`, table clearance `-2`, joint velocity `-1e-4`.
- assist가 만든 하강을 actor에 귀속하던 place progress, release-ready bonus, height/speed
  penalty와 actor가 제어하지 않는 left-arm penalty는 제거했다.
- event/potential 함수는 `step_dt`를 상쇄하므로 event weight는 실제 episode bonus이고,
  potential 누적은 `weight x physical delta`다. 16초 timeout의 elapsed penalty는 총 `-8`이다.
- Stage curriculum의 reward-weight 변경도 꺼서 위 계수가 학습 중 바뀌지 않게 했다.

  확장했다. optimizer state는 비우고 iteration은 0으로 설정했다.
- bootstrap:
  `2026-07-10_16-26-00_model650_hybrid_v18_bootstrap/model_0.pt`

- Object velocity는 `+/-0.25m/s`로 제한한 뒤 EMA `0.80`을 적용한다.
- XY는 `kp=.12`, `kd=.25`, norm cap `2.5mm`; Z는 `kp=.12`, `kd=.30`, 상승 `2.5mm`,
  하강 `3mm`; deadband는 noisy contact를 고려해 `3mm`다.
- Predicted TCP step은 target 방향뿐 아니라 적용 후 XY/Z 잔여 오차가 실제로 감소해야 한다.
  Persistent Cartesian lead도 XY/상승 `5mm`, 하강 `6mm`로 제한한다.
- Entry offset은 제어에 사용하지 않고 slip 진단에만 보존한다. Slip `50mm`가 6 step 지속되면
  persistent target을 current joint로 reset하고 1 step 정지한 뒤 기준 offset을 다시 잡는다.
- Assist control step 수, requested/incremental/applied Z, 최대 slip, watchdog 횟수, posture error,
  target lead를 episode 누적으로 기록해 controller가 실제로 작동하는지 직접 확인할 수 있다.
- 운반 경로는 이전 요청에 맞춰 lift gate `0.73m`, target `0.75m`, band `0.73~0.79m`, center
  `0.75 +/- 0.025m`로 3cm 낮췄다. Release `0.73/0.68m`, settle `0.65m`는 유지한다.
- 실제 효과가 확인된 fresh grasp shaping, 19 rewards, 74 observations, failure ramp, PPO 설정은
  변경하지 않았다.

다음 학습은 actor/critic/optimizer 모두 신규이며, 확인된 자원 여유에 따라 4096 env를 사용한다.

```bash
python scripts/rsl_rl/train.py --task Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --headless --num_envs 4096 --device cuda --max_iterations 2000 --run_name fresh_object_feedback_place_v23
```

판단은 model 250 lift/assist, model 500 object Z `>0.70m`와 center nonzero, model 750
ready/auth/released 중 하나, model 1000 success nonzero를 기준으로 한다. model 750에도 center가
0이거나 Z가 `0.68m` 아래면 1300까지 기다리지 않고 controller를 다시 점검한다.

## 12. v24 실제 구동력 및 hold 복구 수정

v23 model 500 부근에서 fresh policy의 grasp/lift/assist는 약 `95/92/92%`까지 정상적으로
증가했지만, terminal object Z는 약 `0.632m`, center/release/success는 계속 0이었다. Assist는
episode당 약 209 step 동안 상승 명령을 냈지만 이것은 실제 이동이 아니라 Jacobian이 예측한
동일한 target lead를 반복 합산한 값이었다.

정확한 원인:

- persistent joint target을 매 step current joint 기준으로 다시 제한했고 Cartesian upward lead도
  `5mm`로 제한했다. 실제 최대 joint lead는 약 `0.0208rad`여서 stiffness `400` 기준 정지 토크가
  약 `8.3Nm`에 불과했다.
- `OPENARM_BI_HIGH_PD_CFG`는 robot link gravity를 끄도록 되어 있지만, 원본 scene USD를 참조한 뒤
  robot `spawn=None`을 쓰므로 spawn rigid property인 `disable_gravity=True`가 적용되지 않았다.
- `current_hold`가 접촉 상태 외에 object Z `> start + 5mm`, 즉 `>0.630m`까지 요구했다. Cube가
  이 높이에 닿으면 assist가 바로 꺼지고 3 step 뒤 실패해 회복할 수 없었다.

v24 수정:

- 원본 USD 참조 직후 `openarm_bimanual` 아래 모든 rigid body에
  `physxRigidBody:disableGravity=True`를 명시적으로 author한다. Cube gravity는 계속 켜 둔다.
- assist 진입 시 actor의 기존 absolute joint target을 bounded하게 인계한다.
- 한 control step의 XY/Z 속도 cap은 `2.5/2.5~3mm`로 유지하되 persistent lead만 joint
  `0.05 -> 0.12rad`, XY `5 -> 12mm`, upward `5 -> 25mm`, downward `6 -> 12mm`로 늘린다.
  관측된 Jacobian 비율에서 upward `25mm`는 shoulder가 설정 effort limit까지 사용할 수 있는
  약 `0.10rad` joint error를 제공한다. 실제 actuator effort limit가 최종 안전 제한이다.
- v18에서 hold 보존이 확인된 full 6D spatial DLS를 복원한다. Translation 명령 3축과 angular
  velocity 0을 함께 풀고 persistent target의 angular lead도 `0.03rad`로 제한해, torque lead를
  키웠을 때 position-only 3D nullspace로 손목 자세가 무너지는 것을 막는다.
- `current_hold`는 높이가 아니라 기존에 학습이 검증된 finger proximity와 gripper closure만
  나타낸다. Hold가 끊긴 12-step 유예 동안 object servo는 중지하고 `q_target=current_q`로
  고정한다. 다시 hold가 잡히면 fresh assist로 복귀한다.
- Slip watchdog은 `50mm/6step -> 15mm/3step`으로 강화한다. Handoff/freeze 동안에도 assist가
  실제 arm target owner임을 별도 상태로 기록해 actor-only reward와 penalty가 잘못 적용되지 않는다.
- episode metric에 actual object/TCP Z delta, 직전 Z 명령 방향으로의 실제 object/TCP progress,
  estimated effort-limit ratio, TCP orientation error를 추가해 명령 예측과 실제 동작을 분리한다.
- 5120 env reset용 PhysX aggregate pair capacity를 `32768 -> 65536`으로 늘렸다.
- v23에서 학습이 정상 확인된 74 observations, 19 rewards, PPO와 모든 place 높이/거리 조건은
  변경하지 않았다.

완전한 신규 학습 명령:

```bash
python scripts/rsl_rl/train.py --task Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --headless --num_envs 5120 --device cuda --max_iterations 2000 --run_name fresh_gravity_compensated_place_v24
```

model 250부터 command-aligned object/TCP Z progress가 양수인지 확인하고, model 500에서 object Z
`>0.70m`와 center nonzero를 요구한다. model 500에도 center/release가 0인 상태에서 command-aligned
Z progress가 0 이하이거나 object Z가 `0.68m` 아래면 추가 학습 없이 controller를 다시 점검한다.

## 13. v24 5120-env PhysX patch buffer

첫 v24 실행에서 PhysX가 rigid contact patch buffer 최소 `199728`을 요구했다. 기본값
`5 * 2**15 = 163840`은 5120개 환경에 부족하므로 IsaacLab의 대규모 환경 설정에서 사용하는
`10 * 2**15 = 327680`으로 늘렸다. 이 변경은 물리 접촉 누락만 방지하며 policy, reward,
observation, PPO에는 영향을 주지 않는다. 오류가 발생한 실행은 접촉 결과를 신뢰할 수 없으므로
이어 학습하지 않고 같은 v24 명령으로 처음부터 다시 실행한다.

# 2026-07-10 변경 기록

## 1. 이동 중 조기 release 방지 강화

`hold_until_basket_v12`의 `model_625.pt`를 GUI로 확인했다.

관찰:

- 큐브를 집고 들어올린다.
- 이전보다 더 많이 basket 방향으로 이동한다.
- 하지만 basket에 도착하기 전에 그리퍼를 열어 큐브를 떨어뜨린다.
- 실제 동작은 안정적인 place가 아니라, 이동 중 release/drop에 가깝다.

판단:

- `GOAL_RELEASE_XY_THRESHOLD=0.14`도 실제 동작에서는 여전히 넓다.
- `gripper_open_far_from_goal_xy` 벌점이 `MIN_LIFT_HEIGHT_W` 이상에서만 켜져, 낮게 든 상태에서 이동 중 열기를 충분히 막지 못했다.
- release 보상은 너무 일찍 켜지고, 목표점 밖에서 닫고 유지하는 보상은 늦게 켜졌다.

수정:

- release 허용 범위를 더 좁혔다.
  - `GOAL_RELEASE_THRESHOLD: 0.16 -> 0.11`
  - `GOAL_RELEASE_XY_THRESHOLD: 0.14 -> 0.09`
  - `GOAL_XY_BONUS_TIGHT_THRESHOLD: 0.12 -> 0.10`
- 목표점 밖에서 열기 벌점은 더 일찍 켜지도록 했다.
  - `gripper_open_far_from_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> LIFT_PROGRESS_START_HEIGHT_W`
  - weight `-120 -> -220`
- 목표점 밖에서 닫고 운반하는 보상도 더 일찍 켜지도록 했다.
  - `gripper_closed_far_from_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> LIFT_PROGRESS_START_HEIGHT_W`
  - weight `38 -> 72`
- 목표점 안에서 열기 보상은 더 늦게 켜지도록 했다.
  - `gripper_open_near_goal.minimal_height: MIN_LIFT_HEIGHT_W -> CARRY_LIFT_HEIGHT_W`
  - `gripper_open_near_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> CARRY_LIFT_HEIGHT_W`
- basket 방향 이동 보상을 다시 강화했다.
  - `right_hand_y_transport_after_grasp: 42 -> 56`
  - `object_goal_xy_progress: 34 -> 42`
  - `object_goal_y_tracking_broad: 38 -> 46`
  - `object_goal_y_progress: 58 -> 72`
  - `object_goal_y_shortfall: -46 -> -58`

의도:

- basket에 도착하기 전까지는 그리퍼를 열지 않게 한다.
- 물체를 낮게 들고 이동하는 중에도 조기 release 벌점이 작동하게 한다.
- 충분히 높게 들고 basket XY 안에 들어간 뒤에만 release가 유리하도록 만든다.

## 2. 최종 place 목표 높이 낮춤

GUI에서 최종 목표 화살표가 basket보다 지나치게 높게 보이는 문제가 확인됐다.

관찰:

- 기존 목표 높이는 `BASKET_GOAL_POS_B[2] = 0.42`였다.
- 로봇 root 높이 `0.35`를 더하면 월드 기준 목표 높이는 `0.77m`다.
- basket settle 높이 `BASKET_SETTLE_POS_B[2] = 0.30`, 월드 기준 `0.65m`보다 약 `12cm` 높다.
- 이 때문에 정책이 basket에 놓기보다 공중 목표점까지 이동한 뒤 열어 떨어뜨리는 동작을 학습하기 쉽다.

수정:

- 최종 command/화살표 높이를 낮췄다.
  - `BASKET_GOAL_POS_B[2]: 0.42 -> 0.33`
- 월드 기준 최종 목표 높이는 `0.68m`가 된다.
- 이동 중 carry 높이 보상은 유지했다.
  - `CARRY_LIFT_HEIGHT_W = 0.72`

의도:

- 최종 목표는 basket 안/위쪽의 place 지점에 가깝게 둔다.
- 이동 중에는 여전히 높게 들게 하되, 최종 release는 낮은 place 목표에서 일어나도록 분리한다.

## 3. Release 목적함수와 최종 단계 gate 정렬

`lower_goal_v14`를 iteration 2100대까지 확인했다.

관찰:

- grasp 이후 lift와 basket 방향 transport는 계속 개선됐다.
- `object_goal_xy_bonus_tight`, `gripper_open_near_goal_xy`는 계속 0이었다.
- 성공 종료는 약 0.3% 수준이고 episode의 99% 이상이 timeout이었다.
- 목표 밖 open 벌점은 커졌지만 목표 안에서 release하는 양의 신호는 거의 발생하지 않았다.

원인:

- 성공 termination에 별도 보상이 없어, 성공하면 남은 episode의 dense grasp/carry 보상을 잃었다.
- 목표 높이는 world `0.68m`인데 release 보상은 object가 `0.72m`보다 높을 때만 켜져 height tracking과 충돌했다.
- 성공 XY 반경은 `0.16m`, open 허용 반경은 `0.09m`라 성공 가능한 상태 일부를 open 벌점이 막았다.
- `carrying_object_high`와 closed-grasp stable hold가 목표 안에서도 계속 적용돼 내려놓기보다 계속 쥐는 정책을 강화했다.
- 정책 관측에 object velocity가 없어 정지 후 release 조건을 직접 판단할 수 없었다.

확인:

- USD container 내부 반폭은 약 `0.228m x 0.210m`다.
- command randomization `+-0.03m`를 포함해도 `0.16m` release 반경은 cube 중심을 basket 내부에 유지한다.

수정:

- release/settle/success XY 반경을 `0.16m`로 통일했다.
- release readiness에 goal height 오차와 object speed를 함께 사용한다.
- release 최소 높이를 basket rim과 일치하는 world `0.65m`로 낮췄다.
- high-carry reward는 release basin 밖에서만 적용한다.
- closed-grasp stable hold를 gripper 상태와 무관한 `object_goal_release_readiness`로 교체했다.
- 안정된 release basin에서 open 보상을 강화하고 closed penalty를 강화했다.
- 목표 밖 open penalty와 closed hold reward는 낮춰 transport 보상과의 불균형을 줄였다.
- 성공 termination에 `successful_release` terminal reward를 추가했다.
- policy observation에 robot-root frame object linear velocity를 추가했다.
- 장기 pick-and-place credit assignment를 위해 PPO `gamma`를 `0.98 -> 0.995`로 높였다.

주의:

- policy observation이 42차원에서 45차원으로 바뀌므로 이전 checkpoint를 resume할 수 없다.
- 새 run은 checkpoint 없이 처음부터 학습해야 한다.

# 2026-07-10 변경 기록

## 1. 이동 중 조기 놓기 방지 강화

`hold_until_basket_v12`의 `model_625.pt`를 GUI로 확인했다.

관찰:

- 큐브를 집고 들어올린다.
- 이전보다 바스켓 방향으로 더 많이 이동한다.
- 하지만 바스켓에 도착하기 전에 그리퍼를 열어 큐브를 떨어뜨린다.
- 실제 동작은 안정적인 배치가 아니라 이동 중 놓기·낙하에 가깝다.

판단:

- `GOAL_RELEASE_XY_THRESHOLD=0.14`도 실제 동작에서는 여전히 넓다.
- `gripper_open_far_from_goal_xy` 벌점이 `MIN_LIFT_HEIGHT_W` 이상에서만 켜져, 낮게 든 상태에서 이동 중 열기를 충분히 막지 못했다.
- 놓기 보상은 너무 일찍 켜지고, 목표점 밖에서 닫고 유지하는 보상은 늦게 켜졌다.

수정:

- 놓기 허용 범위를 더 좁혔다.
  - `GOAL_RELEASE_THRESHOLD: 0.16 -> 0.11`
  - `GOAL_RELEASE_XY_THRESHOLD: 0.14 -> 0.09`
  - `GOAL_XY_BONUS_TIGHT_THRESHOLD: 0.12 -> 0.10`
- 목표점 밖에서 열기 벌점은 더 일찍 켜지도록 했다.
  - `gripper_open_far_from_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> LIFT_PROGRESS_START_HEIGHT_W`
  - 가중치 `-120 -> -220`
- 목표점 밖에서 닫고 운반하는 보상도 더 일찍 켜지도록 했다.
  - `gripper_closed_far_from_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> LIFT_PROGRESS_START_HEIGHT_W`
  - 가중치 `38 -> 72`
- 목표점 안에서 열기 보상은 더 늦게 켜지도록 했다.
  - `gripper_open_near_goal.minimal_height: MIN_LIFT_HEIGHT_W -> CARRY_LIFT_HEIGHT_W`
  - `gripper_open_near_goal_xy.minimal_height: MIN_LIFT_HEIGHT_W -> CARRY_LIFT_HEIGHT_W`
- 바스켓 방향 이동 보상을 다시 강화했다.
  - `right_hand_y_transport_after_grasp: 42 -> 56`
  - `object_goal_xy_progress: 34 -> 42`
  - `object_goal_y_tracking_broad: 38 -> 46`
  - `object_goal_y_progress: 58 -> 72`
  - `object_goal_y_shortfall: -46 -> -58`

의도:

- 바스켓에 도착하기 전까지는 그리퍼를 열지 않게 한다.
- 물체를 낮게 들고 이동하는 중에도 조기 놓기 벌점이 작동하게 한다.
- 충분히 높게 들고 바스켓 XY 안에 들어간 뒤에만 놓기가 유리하도록 만든다.

## 2. 최종 배치 목표 높이 낮춤

GUI에서 최종 목표 화살표가 바스켓보다 지나치게 높게 보이는 문제가 확인됐다.

관찰:

- 기존 목표 높이는 `BASKET_GOAL_POS_B[2] = 0.42`였다.
- 로봇 루트 높이 `0.35`를 더하면 세계 좌표 기준 목표 높이는 `0.77m`다.
- 바스켓 안착 높이 `BASKET_SETTLE_POS_B[2] = 0.30`, 세계 좌표 기준 `0.65m`보다 약 `12cm` 높다.
- 이 때문에 정책이 바스켓에 놓기보다 공중 목표점까지 이동한 뒤 열어 떨어뜨리는 동작을 학습하기 쉽다.

수정:

- 최종 명령·화살표 높이를 낮췄다.
  - `BASKET_GOAL_POS_B[2]: 0.42 -> 0.33`
- 세계 좌표 기준 최종 목표 높이는 `0.68m`가 된다.
- 이동 중 운반 높이 보상은 유지했다.
  - `CARRY_LIFT_HEIGHT_W = 0.72`

의도:

- 최종 목표는 바스켓 안쪽·위쪽의 배치 지점에 가깝게 둔다.
- 이동 중에는 여전히 높게 들게 하되, 최종 놓기는 낮은 배치 목표에서 일어나도록 분리한다.

## 3. 놓기 목적함수와 최종 단계 조건 정렬

`lower_goal_v14`를 2100회 반복대까지 확인했다.

관찰:

- 파지 이후 들어 올리기와 바스켓 방향 운반은 계속 개선됐다.
- `object_goal_xy_bonus_tight`, `gripper_open_near_goal_xy`는 계속 0이었다.
- 성공 종료는 약 0.3% 수준이고 에피소드의 99% 이상이 시간 초과였다.
- 목표 밖 열림 벌점은 커졌지만 목표 안에서 놓는 양의 신호는 거의 발생하지 않았다.

원인:

- 성공 종료에 별도 보상이 없어 성공하면 남은 에피소드의 밀집 파지·운반 보상을 잃었다.
- 목표 높이는 세계 좌표 `0.68m`인데 놓기 보상은 물체가 `0.72m`보다 높을 때만 켜져 높이 추종과 충돌했다.
- 성공 XY 반경은 `0.16m`, 열림 허용 반경은 `0.09m`라 성공 가능한 상태 일부를 열림 벌점이 막았다.
- `carrying_object_high`와 닫힌 파지의 안정 유지가 목표 안에서도 계속 적용돼 내려놓기보다 계속 쥐는 정책을 강화했다.
- 정책 관측에 물체 속도가 없어 정지 후 놓기 조건을 직접 판단할 수 없었다.

확인:

- USD 컨테이너 내부 반폭은 약 `0.228m x 0.210m`다.
- 명령 무작위화 `+-0.03m`를 포함해도 `0.16m` 놓기 반경은 큐브 중심을 바스켓 내부에 유지한다.

수정:

- 놓기·안착·성공의 XY 반경을 `0.16m`로 통일했다.
- 놓기 준비 상태에 목표 높이 오차와 물체 속도를 함께 사용한다.
- 놓기 최소 높이를 바스켓 가장자리와 일치하는 세계 좌표 `0.65m`로 낮췄다.
- 고고도 운반 보상은 놓기 영역 밖에서만 적용한다.
- 닫힌 파지의 안정 유지를 그리퍼 상태와 무관한 `object_goal_release_readiness`로 교체했다.
- 안정된 놓기 영역에서는 열림 보상과 닫힘 벌점을 강화했다.
- 목표 밖 열림 벌점과 닫힘 유지 보상은 낮춰 운반 보상과의 불균형을 줄였다.
- 성공 종료에 `successful_release` 종료 보상을 추가했다.
- 정책 관측에 로봇 루트 좌표계 기준 물체 선속도를 추가했다.
- 장기 집기·놓기의 보상 기여 배분을 위해 PPO `gamma`를 `0.98 -> 0.995`로 높였다.

주의:

- 정책 관측이 42차원에서 45차원으로 바뀌므로 이전 체크포인트를 재개할 수 없다.
- 새 실행은 체크포인트 없이 처음부터 학습해야 한다.

`release_aligned_v15`를 5000회 반복까지 학습하고 `model_900.pt`, `model_2075.pt`를 GUI로 확인했다.

수정:

  - 물체 속도 관측 제거: 45차원 -> 42차원
  - PPO `gamma: 0.995 -> 0.98`
- `Isaac-PickPlace-OpenArm-TestUSD-Bi-FineTune-v0` 과업을 추가했다.
  - 학습 무작위화는 유지한다.

  - 정지하면 0, 목표에서 멀어지면 음수다.
  - 초기화·재파지 직후 거리 변화는 보상하지 않는다.

- v14까지 유지됐던 `carrying_object_high`를 목표 거리로 감쇠하지 않도록 원래 들어 올리기 진행 형태로 복원했다.
- 파지·들기 관련 기존 보상 가중치와 행동 공간은 바꾸지 않았다.

- v10은 수치와 실패 원인을 참고하지만 체크포인트는 사용하지 않는다.

## 5. 단계 상태 기반 목적함수 재설계

v16을 `lower_goal_v14/model_2175.pt`에서 재개해 `model_2900.pt`까지 학습했다. 그러나 `model_2675.pt` 기준 실제 물체 오차인 `object_position_error`가 약 `0.278m`로 v14의 약 `0.247m`보다 나빠졌고, 성공률은 0, 시간 초과는 약 99.86%였다. 기존 방식의 보상 계수 조정만으로는 개선되지 않는 것이 확인돼 v16 학습을 중단했다.

확정한 구조적 원인:

- 과거 v10~v15 실행은 모두 새로 시작했다. 코드 변경은 누적됐지만 학습된 정책 자체가 실행 사이에 누적되지는 않았다.
- 기존 밀집 보상 50개에는 파지·운반 상태를 매 단계 유지하면 받는 양의 보상이 많았다. 바스켓에 완전히 놓기보다 중간에 멈춰 시간 초과로 끝나는 행동이 안정적인 국소 최적점이 된 이유다.
- 보상과 종료 조건이 서로 다른 파지·놓기 조건을 사용했고, 성공 판정에는 놓기 체류와 실제 안착 상태가 필요하지 않았다.
- 기존 낙하 높이 `0.45m`는 물체가 시작 탁자 높이 약 `0.625m`로 떨어지는 실패를 검출하지 못했다.
- 정책은 보상 계산에 쓰인 파지 고정 상태, 놓기 준비 상태, 물체 속도, 에피소드 진행률을 보지 못해 같은 관측에서 서로 다른 행동을 요구받았다.
- `position_error`는 명령 대상인 손의 오차이며 물체의 실제 목표 오차가 아니다. 비교에 사용할 값은 `object_position_error`다.
- v16의 조건부 포텐셜은 조건이 켜지고 꺼질 때 연쇄 상쇄 조건이 깨져 장기 과업 목적함수를 안정적으로 나타내지 못했다.

v17 수정:

- `Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0`와 전용 실행 과업을 추가했다.
- 파지 확인, 들어 올리기 완료, 바스켓 XY 진입, 놓기 준비, 놓기, 성공·실패를 하나의 `TaskStateTracker`가 계산하도록 통합했다.
- 성공은 실제 놓기 이후 바스켓 내부에서 높이, 속도, 열림 상태가 10제어 주기 연속 안정될 때만 발생한다.
- 바스켓 밖 놓기, 파지 뒤 유지 상실, 놓은 뒤 바스켓 밖으로 이탈, 시작 높이보다 `3cm` 이상 낙하를 즉시 또는 짧은 체류 뒤 실패로 종료한다.
- 정책 관측에 물체 선속도 3개, 단계 상태 6개, 에피소드 진행률 1개를 추가해 총 52차원으로 만들었다.
- 그리퍼 행동에 `+-0.15` 히스테리시스를 넣어 탐색 잡음이 0 근처에서 열림·닫힘을 반복하지 않게 했다.

- 단계 사건 보상은 `dt`를 상쇄해 설정값 `10/15/40/20/5/200/-100`이 실제 에피소드 보너스가 되도록 했다.

## 6. v18 혼합 배치 정책과 보상·실패 조건 정렬

v17 `model_650.pt`까지 확인한 결과 파지·들기와 XY 운반은 유지됐지만 하강·놓기는 전혀
발생하지 않았다. 64개 환경의 결정론적 측정에서는 초기 목표 XY 거리 평균 `0.3136m`가 최소
`0.0900m`까지 줄었고, `93.75%`가 `0.12m` 안에 진입했다. 병목은 XY 이동이 아니라 바스켓
진입 뒤 약 `0.99m` 높이에서 멈추는 고고도 운반 국소 최적점이었다.

구조 수정:

- 학습된 행동자는 파지, 들어 올리기, 바스켓 XY 도달, 놓기 요청을 계속 담당한다.
- `basket_reached`는 들어 올리기 완료 후 XY `0.12m` 안에 들어왔을 때만 상태를 고정한다.
- 바스켓 진입 뒤에는 직교 좌표계 보조 제어 목표와 정책 목표를 `0.12~0.20m`에서 연속해서
  혼합한다. 보조 제어는 물체 XY를 목표 중심으로 보정하면서 에피소드별 놓기 높이로 내린다.
- 직교 좌표계 이동량은 XY `0.0010m`, Z `0.0015m`, 관절 목표 이동량은 `0.03rad`로 제한했다.
- 학습 놓기 높이는 `0.95/0.86/0.77/0.68m`, 확률은 `0.20/0.20/0.20/0.40`이다. 고정
  경계 `(0.68, 0.95)`로 정규화해 실행의 단일 `0.68m` 목표도 학습과 동일하게 관측된다.

놓기 상태 기계:

- 허가는 현재 XY, 높이 오차, 속도 조건이 5단계 연속 맞을 때 상태를 고정한다.
- 실제 놓기는 행동자 행동이 `+0.15` 이상일 때만 `release_commanded`로 상태를 고정한다. 기존
  임계값 `-0.75`처럼 허가 직후 사실상 자동으로 열리는 경로는 제거했다.
- 열림 전환은 10단계까지 유지 상실을 유예하며, 추가 3단계 안에도 물리적 열림이 끝나지 않으면
  실패한다.
- 바스켓 진입 뒤 `0.20m` 밖 이탈 6단계, 놓기 뒤 `0.16m` 밖 이탈 6단계, 일반 유지 상실 3단계를
  각각 독립적으로 실패 처리한다.
- 성공은 행동자가 요청한 놓기 뒤 XY `0.16m`, 안착 높이 `0.65+-0.045m`, 속도 `0.08m/s`
  이하가 10단계 유지될 때만 확정한다.

최종 Stage 보상 15개:

- 부호 있는 포텐셜: 접근 `5`, 들어 올리기 `150`, 운반 `150`. 정지하면 0이고 후퇴하면 음수다.
- 일회성 사건: 파지 `10`, 들어 올리기 `15`, 바스켓 `40`, 물리적 놓기 `25`, 성공 `200`,
  실패 `-100`, 미완료 시간 초과 `-50`.
- 벌점: 경과 시간 `-0.5/s`, 직접 그리퍼 행동 단계 `-4`, 행동자 제어 비율로 제한한 행동 변화율
  `-1e-4`, 테이블 여유 높이 `-2`, 관절 속도 `-1e-4`.
- 보조 제어가 만든 하강을 행동자에 귀속하던 배치 진행량, 놓기 준비 보너스, 높이·속도 벌점과
  행동자가 제어하지 않는 왼팔 벌점은 제거했다.
- 사건·포텐셜 함수는 `step_dt`를 상쇄하므로 사건 가중치는 실제 에피소드 보너스이고, 포텐셜
  누적은 `weight x physical delta`다. 16초 시간 초과의 경과 시간 벌점은 총 `-8`이다.
- Stage 교육 과정의 보상 가중치 변경도 꺼서 위 계수가 학습 중 바뀌지 않게 했다.

관측과 부트스트랩:

- 부트스트랩:
  `2026-07-10_16-26-00_model650_hybrid_v18_bootstrap/model_0.pt`

## 7. v19 도달 가능한 배치 목표와 하강 전 중심 정렬

v18 `model_1000` GUI에서 파지·들기는 안정적이었지만, 바스켓 중심에 못 미친 상태로 너무 높이
들었다가 하강했다. 로그에서도 바스켓 진입 사건은 약 96~98%였지만 놓기 준비, 놓기, 성공은
1000회 반복 동안 0이었다.

기구학 확인:

- 오른쪽 어깨 관절 원점은 로봇 루트 기준 `(0, -0.0935, 0.698)`이다.
- 기존 물체 목표 `(0.48, 0.20, z)`는 어깨 반대편으로 `0.2935m` 넘어간, 몸을 가로지르는 목표다.

  z가 `0.95/0.77/0.68m`일 때 각각 `40.5/85.5/123.4mm`였다. 낮출수록 정확한 중심
  도달이 불가능하다.
- 새 목표 중심 `(0.37, 0.07)`과 학습 범위 x `(0.36, 0.38)`, y `(0.06, 0.08)`는
  최종 세계 좌표 z `0.68m`의 가장 먼 모서리까지 IK 오차가 0이다.
- 바스켓 내부에서 가장 나쁜 큐브 가장자리 여유도 x `76mm`, y `38mm`로 유지된다.

정책·제어 수정:

- 바스켓 안의 도달 가능한 목표를 로봇 루트 기준 `(0.37, 0.07, 0.33)`으로 옮겼다.
- 운반 높이 범위는 세계 좌표 z `0.74~0.82m`, 중심 정렬 목표는 `0.78m`로 정했다.
  이 범위 밖의 높이 오차에는 행동자 운반 구간에서만 가중치 `-20`을 적용한다.
- 바스켓 진입 조건은 XY `0.10m`이며, 진입 뒤에는 전체 직교 좌표계 XY 보조 제어가 중심을 잡는다.
- XY 오차 `<=0.06m`, XY 속도 `<=0.05m/s`가 5단계 연속 유지돼 `place_centered`가
  고정되기 전에는 놓기 높이로 하강하지 않는다.
- 중심을 정렬하는 동안 물체 높이를 `0.78m`로 유지하고, 상태 고정 뒤에만 에피소드별 놓기 목표
  `0.78/0.73/0.68m`로 내린다.
- 기존처럼 이탈할수록 보조 제어 비율을 줄이지 않는다. 보조 제어 반경 `0.18m` 안에서는 전체
  제어 권한을 유지하고, XY 위치 이동량 `0.002m`와 물체 XY 속도 감쇠 `1.0`을 함께 사용한다.

## 8. v20 기존 운반 보존과 상승 없는 배치 보조 제어

v19 `model_900`까지 확인한 결과 파지·들기는 약 97~98%였지만 물체 XY는 평균 약 `0.133m`,
높이는 약 `0.98m`에서 정체됐다. `assist`, 중심 정렬, 놓기, 성공은 모두 0이었다. 실제 보조 제어는
설정한 바깥 반경보다 `basket_reached <=0.10m` 조건을 먼저 통과해야 해서 한 번도 실행되지 않았다.
v18 행동자의 입력도 이전 목표에서 새 목표로 바뀌면서 X 방향이 반전되고 Y가 축소됐으며, 두 Z
입력은 약 `+0.10m` 달라졌다. 이 때문에 비트 단위로 정확히 가중치를 복사해도 행동은 보존되지 않았다.

v20 수정:

- v18 행동자가 보는 가상 운반 경유점을 `(0.48, 0.20, 0.33)`으로 복원했다. 실제 과업, 보조 제어,
  놓기 목표는 도달 가능한 지점 `(0.37, 0.07, 0.33)`을 계속 사용한다.
- 실제 목표 XY `0.14m`에서 `assist_engaged` 상태를 고정한다. 엄격한 바스켓 상태는 `0.10m`,
  중심 정렬·놓기는 `0.04m`, 성공은 `0.05m`로 유지한다.
- 보조 제어는 `0.24m`까지 실제 목표 제어기를 유지한다. `0.20m` 밖으로 이탈해도 제어기가
  24단계 동안 복구할 수 있으며, 회복하지 못했을 때만 실패한다.
- 중심 정렬 전 목표는 `min(current object z, 0.78m)`이고 이후 놓기 목표도 현재 높이보다 높게
  만들지 않아 제어기가 위로 명령하지 않는다. 놓기 높이는 `0.73/0.68m = 0.40/0.60`이다.
- TCP 선형 Jacobian 대신 파지한 큐브 중심의
  `J_object = Jv - skew(p_object - p_tcp) @ Jw`를 사용한다.
- 행동자 구간 높이 보상은 `-abs(z-0.78)`의 부호 있는 포텐셜에 가중치 `150`을 적용한다. 높아지는
  동작은 즉시 음수, 내려오는 동작은 양수, 정지는 0이다. 범위 벌점은 보조 역할로 `-10`을 적용한다.
- 행동자가 만든 보조 제어 진입 사건만 `+40`으로 보상한다. 제어기가 만든 바스켓 진입에는 행동자
  보상을 주지 않는다. Stage 보상은 총 17개다.
- PPO는 3072개 환경, 48단계, 24개 미니배치를 유지하되 행동자 변화를 줄이려고 LR `5e-6`,

바스켓 간섭 수정:

- `/packing_table/container_h20`의 로컬 X를 `0.333333 -> 0.283333m`로 바꿨다.
- 부모 배율·회전을 적용한 세계 좌표 중심은 `(0.48, 0.20) -> (0.48, 0.17)`로 Y `-3cm` 이동한다.
- 실제 목표는 움직이지 않아 도달 가능성은 그대로이고, 무작위 목표에서 가장 나쁜 큐브 가장자리 Y 여유는
  약 `38mm -> 68mm`로 증가한다.

정책 이식:

- 원본: `2026-07-10_16-30-21_hybrid_place_v18/model_1000.pt`.
- 행동자와 행동 잡음은 그대로 복사하고 처음 66개 관측 열을 보존했다.

  `param_groups`와 LR `5e-6`는 유지했으며 반복 횟수는 0이다.

## 9. v21 양방향 수직 유지

v20 `model_250` 부근에서 파지·들기·보조 제어·바스켓 진입은 약 `98/97/97/96%`로 v19의 도달

v21 수정:

- 관측 69개, 행동 8개, 보상 17개와 모든 임계값은 그대로라 체크포인트 형상이 같다.

## 10. v22 신규 정책과 안정적인 TCP 보조 제어

v21은 약 160회 추가 갱신한 시점에 파지·들기·보조 제어가 약 `98/98/97%`였지만, 유지는 약
`80 -> 69%`, 바스켓 진입은 `96 -> 33%`, 중심 정렬은 `5.6 -> 0.1%`로 나빠졌다. 물체 Z는
`0.632~0.633m`에 머물렀고 놓기·성공은 0이었다.

원인:

- 이전 행동자 호환용 가상 경유점 `(0.48,0.20)`과 실제 목표 `(0.37,0.07)`이 정책과 제어기
  사이에서 서로 달랐다.
- `kp=0.10`, `kd=1.5`인 Z 식과 성분별 제한이 매 단계 포화되면서 상하 교번과 직교 좌표계
  방향 왜곡을 만들었다. 상승 상한 `0.75mm/step`도 실제 낙하 속도를 복원하기에 부족했다.
- 큐브가 TCP에 완전히 고정됐다고 가정한 물체점 Jacobian은 손목 회전을 평행 이동으로 사용해
  손가락 미끄러짐을 키울 수 있었다.
- Stage 희소 보상과 초기 실패 비용 `-100`은 새 행동자가 파지를 발견하기 전에 파지 시도를
  무동작 시간 초과보다 불리하게 만들 수 있었다.

v22 수정:

- 체크포인트 호환용 가상 목표를 제거했다. 정책은 실제 목표 XY와 세계 좌표 운반 Z `0.78m`를
  일관되게 본다. 파지 품질 3개와 이정표 고정 상태 2개를 관측해 `69 -> 74`차원이다.
- 접근의 부호 있는 포텐셜은 `5 -> 30`, 일회성 파지 준비는 `+5`, 파지 후보는 `+10`, 파지 획득은
  `10 -> 20`으로 바꿨다. 보상은 총 19개다.
- 실패 비용은 초기 `-50`으로 시작한다. 공통 단계 `4,800~14,400`은 PPO 반복
  `100~300`에 해당하며, 이 구간에서 `-100`까지 선형으로 강화해 순간적인 수익 변화를 없앴다.
- 포텐셜은 새 에피소드의 최고 진행에만 양수로 지급하고 후퇴에는 음수로 지급한다. 같은 구간을
  왕복해도 복귀 보상을 다시 받지 못하므로 gamma `0.98`에서 보상 순환이 생기지 않는다.
- 보조 제어 진입 때 물체·TCP 오프셋을 고정하고 그 오프셋으로 TCP 목표를 만든 뒤 TCP 선형
  `Jv`와 DLS 감쇠 `0.08`을 사용한다. 자세는 `gain=0.04`, 최대 `0.003rad/step`인 영공간
  항으로만 유지한다.
- XY는 `kp=0.12`, `kd=0.25`, 노름 최대 `0.002m/step`이고 Z는 `kp=0.12`, `kd=0.30`, 하강
  `0.003m/step`, 상승 `0.0025m/step`이다. 속도 EMA는 `0.75`다.
- XY/Z 명령은 항상 목표 방향이고 남은 오차보다 클 수 없다. DLS 관절 이동량도 관절별 제한 대신
  전체 벡터를 같은 비율로 줄이며, 마지막에 예측 TCP 방향을 다시 검사한다.
- 보조 제어 목표는 현재 관절값으로 매번 버리지 않고 누적하되 현재 관절보다 최대 `0.05rad`만
  앞선다. 예측 TCP 선행량도 남은 XY/Z 오차보다 클 수 없다. 유지 상태가 흔들린 뒤에는 마지막
  목표를, 놓기 뒤에는 현재 관절 위치를 12단계 유지해 목표 점프와 안착 중 재접촉을 막는다.
- 중심 정렬 고정 상태에 `z=0.78m +/- 0.03m` 조건을 추가했다. 낮은 상태에서는 하강으로
  전환하지 않고 운반 높이를 먼저 복원한다.
- PPO는 v10/v14 신규 학습 설정을 따라 잡음 `0.30`, LR `5e-6`, gamma `0.98`, 2에포크를 사용한다.

완전한 신규 학습 명령:

```bash
python scripts/rsl_rl/train.py --task=Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --num_envs=3072 --device=cuda --max_iterations=2000 --headless --run_name=fresh_stable_pick_place_v22
```

`--resume`, `--load_run`, `--checkpoint`, 부트스트랩은 사용하지 않는다. `model_25`에서 파지
사건, `model_100`에서 파지·들기 상승, `model_250`에서 유지·운반·보조 제어, `model_500`에서
바스켓 진입·중심 정렬, `model_750`에서 놓기, `model_1000`에서 성공이 0보다 큰지 판단한다.

## 11. v23 실제 물체 되먹임

v22 신규 실행 `2026-07-10_21-32-18`은 1304번째 반복에서 파지·들기·보조 제어가 약
`99/97/97%`, 유지가 `91%`까지 학습됐다. 그러나 최근 바스켓 진입은 약 `19%`, 중심 정렬·놓기·
성공은 0이었고 물체 Z `0.6356m`, 목표 XY 거리 `0.1197m`에서 정체됐다. 보조 제어 활성 비율이
92% 이상인데 요청한 Z 이동량과 목표 선행량이 전 구간 0인 것이 결정적 증거였다.

원인은 보조 제어 진입 때 저장한 물체·TCP 오프셋을 고정 목표로 사용했다는 데 있다. TCP가 그 목표에
도달한 뒤 큐브가 손가락 안에서 미끄러져도 제어기 입력에서는 미끄러짐이 상쇄돼 큐브의 실제
`0.635m` 높이를 보지 못했다.

v23 수정:

- 고정 오프셋을 제어식에서 완전히 제거했다. `target_object - actual_object`의 실제 큐브 XY/Z
  오차와 물체 루트 속도를 매 단계 TCP 선형 `Jv` 평행 이동 명령으로 되먹임한다.
- 물체 속도는 `+/-0.25m/s`로 제한한 뒤 EMA `0.80`을 적용한다.
- XY는 `kp=.12`, `kd=.25`, 노름 상한 `2.5mm`이고 Z는 `kp=.12`, `kd=.30`, 상승 `2.5mm`,
  하강 `3mm`다. 잡음이 있는 접촉을 고려한 무감응 구간은 `3mm`다.
- 예측 TCP 이동량은 목표 방향이어야 할 뿐 아니라 적용 뒤 XY/Z 잔여 오차를 실제로 줄여야 한다.
  지속 직교 좌표계 선행량도 XY·상승 `5mm`, 하강 `6mm`로 제한한다.
- 진입 오프셋은 제어에 사용하지 않고 미끄러짐 진단에만 보존한다. 미끄러짐 `50mm`가 6단계
  이어지면 지속 목표를 현재 관절값으로 초기화하고 1단계 멈춘 뒤 기준 오프셋을 다시 잡는다.
- 보조 제어 주기 수, 요청·증분·적용 Z, 최대 미끄러짐, 감시 장치 작동 횟수, 자세 오차, 목표
  선행량을 에피소드 단위로 누적해 제어기가 실제로 작동하는지 직접 확인한다.
- 운반 경로는 이전 요청에 맞춰 들어 올리기 조건 `0.73m`, 목표 `0.75m`, 범위 `0.73~0.79m`,
  중심 정렬 `0.75 +/- 0.025m`로 3cm 낮췄다. 놓기 `0.73/0.68m`, 안착 `0.65m`는 유지한다.
- 실제 효과가 확인된 신규 파지 보상 조정, 보상 19개, 관측 74개, 실패 비용 증가, PPO 설정은

판단 기준은 모델 250의 들어 올리기·보조 제어, 모델 500의 물체 Z `>0.70m`와 0보다 큰 중심

## 12. v24 실제 구동력과 유지 복구 수정

v23 모델 500 부근에서 신규 정책의 파지·들기·보조 제어는 약 `95/92/92%`까지 정상적으로
증가했지만, 종료 시 물체 Z는 약 `0.632m`, 중심 정렬·놓기·성공은 계속 0이었다. 보조 제어는
에피소드당 약 209단계 동안 상승 명령을 냈지만, 이는 실제 이동이 아니라 Jacobian이 예측한
같은 목표 선행량을 반복해 더한 값이었다.

정확한 원인:

- 지속 관절 목표를 매 단계 현재 관절 기준으로 다시 제한했고 직교 좌표계 상승 선행량도
  `5mm`로 제한했다. 실제 최대 관절 선행량은 약 `0.0208rad`여서 강성 `400` 기준 정지 토크가
  약 `8.3Nm`에 불과했다.
- `OPENARM_BI_HIGH_PD_CFG`는 로봇 링크 중력을 끄도록 되어 있지만, 원본 장면 USD를 참조한 뒤
  로봇 `spawn=None`을 쓰므로 생성 강체 속성인 `disable_gravity=True`가 적용되지 않았다.
- `current_hold`가 접촉 상태 외에 물체 Z `> start + 5mm`, 즉 `>0.630m`까지 요구했다. 큐브가
  이 높이에 닿으면 보조 제어가 바로 꺼지고 3단계 뒤 실패해 회복할 수 없었다.

v24 수정:

- 원본 USD 참조 직후 `openarm_bimanual` 아래 모든 강체에
  `physxRigidBody:disableGravity=True`를 명시적으로 기록한다. 큐브 중력은 계속 켜 둔다.
- 보조 제어 진입 때 행동자의 기존 절대 관절 목표를 제한해서 인계한다.
- 한 제어 주기의 XY/Z 속도 상한은 `2.5/2.5~3mm`로 유지하되 지속 선행량만 관절
  `0.05 -> 0.12rad`, XY `5 -> 12mm`, 상승 `5 -> 25mm`, 하강 `6 -> 12mm`로 늘린다.
  관측한 Jacobian 비율에서 상승 `25mm`는 어깨가 설정된 힘 제한까지 사용할 수 있는
  약 `0.10rad`의 관절 오차를 제공한다. 실제 구동기 힘 제한이 최종 안전 한계다.
- v18에서 유지 보존을 확인한 전체 6D 공간 DLS를 복원한다. 평행 이동 명령 3축과 각속도 0을
  함께 풀고 지속 목표의 각도 선행량도 `0.03rad`로 제한한다. 토크 선행량을 키웠을 때 위치 전용
  3D 영공간 때문에 손목 자세가 무너지는 현상을 막기 위한 조치다.
- `current_hold`는 높이가 아니라 기존 학습으로 검증한 손가락 근접도와 그리퍼 닫힘만 나타낸다.
  유지가 끊긴 12단계 유예 동안 물체 서보를 중지하고 `q_target=current_q`로 고정한다. 다시
  유지가 잡히면 새 보조 제어로 복귀한다.
- 미끄러짐 감시 조건은 `50mm/6step -> 15mm/3step`으로 강화한다. 인계·고정 중에도 보조 제어가
  실제 팔 목표를 소유한다는 사실을 별도 상태로 기록해 행동자 전용 보상과 벌점이 잘못 적용되지
  않게 한다.
- 에피소드 지표에 실제 물체·TCP Z 변화량, 직전 Z 명령 방향으로의 실제 물체·TCP 진행량,
  추정 힘 제한 비율, TCP 자세 오차를 추가해 명령 예측과 실제 동작을 분리한다.
- 5120개 환경 초기화에 쓰는 PhysX 집합 쌍 용량을 `32768 -> 65536`으로 늘렸다.
- v23에서 정상 학습을 확인한 관측 74개, 보상 19개, PPO와 모든 배치 높이·거리 조건은
  변경하지 않았다.

완전한 신규 학습 명령:

```bash
python scripts/rsl_rl/train.py --task Isaac-PickPlace-OpenArm-TestUSD-Bi-Stage-v0 --headless --num_envs 5120 --device cuda --max_iterations 2000 --run_name fresh_gravity_compensated_place_v24
```

모델 250부터 명령 방향과 일치하는 물체·TCP Z 진행량이 양수인지 확인하고, 모델 500에서 물체 Z
`>0.70m`와 0보다 큰 중심 정렬을 요구한다. 모델 500에도 중심 정렬·놓기가 0인 상태에서 명령
방향과 일치하는 Z 진행량이 0 이하이거나 물체 Z가 `0.68m` 아래면 추가 학습 없이 제어기를 다시
점검한다.

## 13. v24 5120개 환경의 PhysX 접촉 패치 버퍼

첫 v24 실행에서 PhysX가 강체 접촉 패치 버퍼 최소 `199728`을 요구했다. 기본값
`5 * 2**15 = 163840`은 5120개 환경에 부족하므로 IsaacLab의 대규모 환경 설정에서 사용하는
`10 * 2**15 = 327680`으로 늘렸다. 이 변경은 물리 접촉 누락만 방지하며 정책, 보상, 관측,
PPO에는 영향을 주지 않는다. 오류가 발생한 실행은 접촉 결과를 신뢰할 수 없으므로
이어 학습하지 않고 같은 v24 명령으로 처음부터 다시 실행한다.
